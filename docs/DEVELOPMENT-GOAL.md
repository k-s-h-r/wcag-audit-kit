# VISIONに向けて開発を続ける

[VISION](VISION.md)を目指す長期開発には、Codexの `/goal` を使う。Goalはチャットに目的と完了条件を保持し、実行できる間は、結果に応じて次の作業を選び続ける。権限や承認の規則はGoalの起動時も適用される。 [Codexの長期作業](https://learn.chatgpt.com/docs/long-running-work)

Claude Codeの `/loop` は固定間隔や状況に応じた繰り返しに使う。Codexのスケジュール機能も時刻やイベントを起点とする。このリポジトリでは実装と検証の結果を起点に次の作業を選ぶので、継続には `/goal` を使う。 [Claude Codeの繰り返し](https://code.claude.com/docs/en/scheduled-tasks) · [Codexのスケジュール](https://learn.chatgpt.com/docs/automations)

## 最初のゴールを始める

このリポジトリを開いたCodexのチャットで `/goal` を選び、次の文を入力する。CLIでは対話セッションで `/goal` と同じ文を使う。進捗欄から一時停止・再開・編集ができる。 [デスクトップの操作](https://learn.chatgpt.com/docs/app/slash-commands#set-or-manage-a-goal-with-goal)

```text
docs/VISION.mdのWCAG検証とアクセシビリティ点検を、docs/DEVELOPMENT-GOAL.mdの初回実証の完了条件まで進めてください。wcag-devの手順で次の作業を選び、実装・試験・根拠の保存・PR作成を繰り返してください。AGENTS.mdのマージ規則に従い、独立して進められる作業を続けてください。
```

## 初回実証の完了条件

各試験の前に、対象サイト・手続き・適合レベル・評価用の対照を固定する。実証した範囲は報告に明記する。詳しい開始条件と試験は各タスクに置く。

| 実現すること | 完了に必要な証拠 |
| --- | --- |
| URLから問題のある操作を見つける | [T024](tasks/T024-keyboard-function-result.md)で、数量変更の問題例と正常例・代替経路の対照を通常の入口から区別する。[T020の基準値](../validation/development/T020/README.md)と同じ採点条件で再測定し、既存の検出を維持した上で新たに検出できた行と誤検出の有無を記録する |
| WCAG適合の結論までたどれる | [T021](tasks/T021-scope-conformance-report.md)で、既知の適合・不適合・未確認を使い、各ページの未対応箇所一覧、検査票、最終回答の結論と根拠を照合する |
| 一連の手続きをURLから試せる | [T022](tasks/T022-url-to-process-audit.md)で、検査側に経路や正解を伏せ、正常例と問題例を使って手続きを実証する。機械とAIの操作や判断、発話を評価する場合の実スクリーンリーダーの証拠を、二つの成果物までつなげる |
| 普段の改善に使う点検結果を返せる | [T023](tasks/T023-accessibility-review-pilot.md)で、観察したつまずきと改善案を一経路で示す。元の操作から改善案までたどれ、WCAG検査票と併用できることを確かめる |

完了時に、これらを一緒に使える版のコミットと各条件の根拠を示す。ほかの手続き、対象範囲、支援技術に広げる場合は、残った実証条件を次のゴールにも引き継ぐ。個々のPRの作成は長期ゴールの途中の区切りとする。

## PRを作った後の動き方

1. [開発計画](ROADMAP.md)と[タスク一覧](tasks/README.md)を読み、関連PRの採用・レビュー結果とローカルの変更を照合する。未完了の作業を再開するか、前提が揃う作業を1単位選ぶ。
2. [wcag-dev](../.agents/skills/wcag-dev/SKILL.md)に沿い、別worktree・別runで実装と検証を行う。担当タスクに実装版、根拠、未確認、PR、次の作業または再開条件を残す。残る差から追加の作業が必要なら、既存タスクの範囲と重複を確認して整理する。
3. PR作成後は、完了条件に残る作業を見直す。前提のPRがレビュー待ちなら、T021のような独立した作業へ進む。依存作業を先に試す必要があれば、依存先と起点を明示した別ブランチで検証する。未合流の実装とmainで確認した結果を区別する。[マージと記録の規則](../AGENTS.md)
4. 権限・承認・試験環境などが不足し、進められる作業が尽きたら、必要な判断と再開条件を伝える。完了条件を満たしたときは、タスク、PR、原始証拠への参照で各条件を照合してからGoalを完了にする。

通常の「進めて」では、従来どおり1作業単位をPR作成まで進める。
