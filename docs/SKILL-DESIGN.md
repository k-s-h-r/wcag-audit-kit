# 4スキルの責務と呼び出し方

更新日：2026-11-21。公開スキルの責務と呼び出し方を記す。[VISION](VISION.md) · [開発計画](ROADMAP.md) · [設計の背景](adr/0019-skill-boundaries-and-explicit-invocation.md)

公開するスキルは現在の4つ。ユーザーが依頼する作業に応じて役割を分ける。機械・AI・実スクリーンリーダーは各ページで使う検証手段で、CLIの `--mode` で選ぶ。VISIONのアクセシビリティ点検は `wcag-audit-kit` の目的別手順として扱う。[点検の手順](../skills/wcag-audit-kit/references/accessibility-review.md)

## 利用者が選ぶ4つの作業

| スキル | 入力と責務 | 出力・境界 |
| --- | --- | --- |
| `wcag-audit-kit` | 試験対象の選定、ページ担当、ページ間比較、一連の手続き、記録更新を進行する。点検では、指定されたURL又は保存済みの証拠から操作のつまずきを調べる | 試験計画、担当と残作業、出所を確認できる報告。点検結果には利用への影響、改善案、再測定の方法と元の判定への参照を添える |
| `wcag-pages` | 基準URL・範囲・既存一覧から、候補URLと選定に必要な資料を集める | URL台帳、取得元、未訪問・失敗・除外理由。WCAG判定を行わず、試験対象の最終選定は全体進行へ渡す |
| `wcag-page` | 指定URL・状態・環境・run・担当範囲を検査する。必要な対象固有の操作手順も確認する | 観察事実、判定、証拠、未探索・未確認、他ページで必要な確認。単独でページ報告まで出せる |
| `wcag-report` | 保存済みrunの判定と証拠を確認し、集計・出力する | 達成基準ごとのチェックシート、不適合箇所の一覧、残る確認をHTML・JSON・Excelに出す |

1ページだけの利用、URLの一覧化だけ、再検査せずExcelを出し直す利用には、それぞれ独立した意味がある。全体進行には、他の3つに含めない試験範囲・担当・ページ間の責務がある。このため、現段階では統合や追加を行わない。

ページ検証に含まれるページ報告は、その検査の成果物である。`wcag-report`は報告だけの依頼や全体集計を担当する。作業用Excelの判定取り込みは明示された記録更新として分け、受領しただけでは実行しない。

機械検査の指摘、保存済みの達成基準の判定、検査した範囲をそれぞれ引き継ぐ。範囲の適合を答えるためには、一連の手続き等の適合要件と基準ごとの根拠がそろうか確認する。[検査票の仕様](../skills/wcag-audit-kit/references/checksheet.md) · [報告の後続作業](tasks/T021-scope-conformance-report.md)

## 開始は明示呼び出し、開始後は必要な手順だけ読む

4スキルのすべてを明示呼び出し専用にする。通常の開発やアクセシビリティに関する相談から、AIが独自に監査を始めない。スキル選択後は、依頼された範囲の作業を順に進める。

| 環境 | 設定 | 利用者からの呼び出し |
| --- | --- | --- |
| Cursor・Claude Code | SKILL.mdの`disable-model-invocation: true` | `/wcag-page`等、環境の明示呼び出し機能を使う |
| Codex | 各スキルの`agents/openai.yaml`で`policy.allow_implicit_invocation: false` | `$wcag-page`等、環境の明示呼び出し機能を使う |

設定の根拠は[Cursor](https://cursor.com/docs/skills)、[Claude Code](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill)、[Codex](https://learn.chatgpt.com/docs/build-skills)の公式資料にある。これは呼び出しの制御であり、機械検査モードの設定や外部操作の許可ではない。別のAI環境に配置するときは、その環境の設定対応を確認する。

全体監査を明示起動した場合、全体進行が必要な子スキルのSKILL.mdをファイルとして読み、内部手順として適用する。子スキルをホストのSkillツール等で自動起動することに依存しない。ユーザーに各段階で同じ監査を呼び出し直させず、最初の対象範囲・モード・予算を引き継ぐ。単独ページの依頼にURL巡回を加えるなど、内部手順の適用を理由に範囲を広げない。

この構成では4つを隣接したフォルダーとして配置する。単独で使うpage・pages・reportは、そのフォルダーだけで動作できる構成を維持する。フォルダーを分けたことだけを理由に、別エージェントを4つ起動しない。

## 今決めるのは受け渡す情報と、その責任者

次の表は必要な情報の契約である。新しいJSON形式や自動処理がすべて実装済みであることを示すものではない。既存の設定・台帳・操作調査票を使い、構造化が不足する項目は実測で必要性を確かめて追加する。

| 情報 | 管理する担当 | 保持する内容 |
| --- | --- | --- |
| URL台帳 | pages | 候補URL、取得元、訪問状態、失敗、未訪問、除外の根拠 |
| 試験計画 | audit-kit | 対象範囲、選定対象、全件又は抽出の理由、状態・権限・手続き、環境、モード、予算 |
| 対象固有の操作手順 | page。全体監査ではaudit-kitが共有範囲を管理 | 起動・到達・操作・復帰・証拠・後片付け、確認した対象の版と環境、未確認の経路 |
| ページ担当への依頼 | audit-kit又は単独ページの依頼 | run、URL、状態、環境、タスクID、モード、予算、必要な手順と証拠 |
| 検証結果 | page。ページ間の確認はaudit-kit | 観察事実、判定、根拠、対象・状態・環境、出所と版、未確認、残る操作・必要な手段 |
| 報告の入力 | report | 保存済みrunと出力範囲。異なる版・runを暗黙に合算しない |

機械からAIへ進むときも、この担当関係を保つ。未確認を解決した場合は新しい証拠と判定を記録し、過去の記録を上書きしない。モードを変えるときの別runと、将来の証拠再利用の条件はロードマップに従う。

## pstackから取り込む、実行確認と保守の循環

参照した版は`cursor/plugins`の`e1cc03121a0e71129a4fb730d7c5528a0a3e43c8`。[手順の作成](https://github.com/cursor/plugins/blob/e1cc03121a0e71129a4fb730d7c5528a0a3e43c8/pstack/skills/create-verification-skill/SKILL.md)と[手順の保守](https://github.com/cursor/plugins/blob/e1cc03121a0e71129a4fb730d7c5528a0a3e43c8/pstack/skills/maintain-verification-skill/SKILL.md)から、次の考え方を取り込む。

- 対象固有の起動・準備確認・操作・証拠保存・後片付けを具体化する。
- 機能ごとに、前提、到達経路、操作、観測できる終状態を対応させる。
- 小さな1経路を実際に動かし、後片付け後も証拠を確認できることを確かめる。
- 手順の古さ、ツールや環境の不足、対象の機能の問題を分けて、更新する場所を判断する。

既存の[方法一覧](../skills/wcag-audit-kit/references/methods.md)と[対象固有の手順テンプレート](../skills/wcag-audit-kit/assets/project-methods-template.md)にこの循環を組み込み、pageと全体進行から参照する。新しい公開のsetup・create・maintainスキルは、独立して繰り返し使う必要が実測で分かるまで追加しない。

pstackの[Claude Code対応](https://github.com/cursor/plugins/blob/e1cc03121a0e71129a4fb730d7c5528a0a3e43c8/pstack/docs/harness/claude-code.md)にも、明示起動した処理から必要なスキルのファイルを読む構成がある。呼び出し制御と内部手順の再利用を分ける参考とする。

WCAG向けには、公開URLだけの対象も扱う。名前やroleのない部品を見落とさないよう、AIが有効なモードでの画面の調査を残す。手順の実行成功とWCAG適合を区別し、製品修正や権限拡大、常時の複数モデル実行は取り込まない。原始証拠は保守の過程でも保持する。

## 配置と動作確認

共通リソースは既存どおりaudit-kitを編集元にして同期する。各フォルダーへ同梱する容量は増えるが、単独配置できる利点を維持する。全資料をAIへ一度に読む構成にはしない。各スキルの呼び出し設定は共通同期から分け、ベンチマークの実装スナップショットには含める。

隔離したCodexと専用MCPの組み合わせで、明示呼び出し、通常の相談での非起動、指定ページの検査、保存済みの報告、子手順を使う指定一覧の検査を確認した。通常シェルの構成や、モデルの最終回答と帳票の一致は確認が残る。各ホストの対応実績は環境と版を添えて記録する。[T004の検証記録](tasks/T004-codex-invocation.md)
