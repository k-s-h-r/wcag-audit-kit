# T001：最初の2観点の測定計画を固定する

状態：測定範囲を固定済み。参照先は[計画 #15](https://github.com/k-s-h-r/wcag-audit-kit/pull/15)。

T002とT003が同じ条件で評価できるよう、最小限の測定計画を作る。新しい検査器や汎用ジョブ基盤は作らず、既存の収集・採点結果を使う。

## 作業と成果物

採点側の資料として、対象を`2.4.2-01`と`1.1.1-01`のimage-alt対応範囲に定める。ページ・状態・対象・観点ごとの行、母数、除外する観点と理由を収集前に固定する。必要な取得期待は別に列挙し、未接続を成功扱いにしない。検査側へ正解・期待する判定を渡さない。

使用する実装・スキル・問題集の版、machineモード、表示環境、探索予算、再実行条件、取得できる費用情報を記録する。タイトルと画像を別runで収集しても比較条件が分かるようにする。未出力も母数へ残し、基準全体の適合と限定した観点の成績を分ける集計例を用意する。

成果物は`validation/development/T001/`内の計画、集計の説明、検査側へ渡す情報と採点側に残す情報の一覧。隔離方法が未整備なら、その不足も明記する。新しいJSON形式やフィルターの実装は、既存出力で不足することが確認できた場合に別タスクへ切り出す。

## 完了条件と確認

- T002・T003の担当が、対象行、実行条件、集計方法、保存先を迷わず確認できる。
- 生の出力が存在しない行も未確認として数える例がある。
- 選択範囲の成績と、全体の未完了・取得未接続・省略を併記する。
- 計画の版とハッシュを新しい実測から参照でき、検査側に正解を渡さない手順を確認する。

## 担当範囲と引き継ぎ

主な変更先はT001の記録とこのファイル。既存の`benchmarks/README.md`・`WORKER.md`・`core.py`・`runner.py`は読み取りで参照する。検出ロジック、期待結果、既存runは変更しない。

完了時に記載する情報：計画のパス・ハッシュ、採用した起点、検査側の隔離方法、残る制約、T002・T003が使う実行と集計の手順。
