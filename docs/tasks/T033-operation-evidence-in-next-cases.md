# T033 ダイアログの離脱証拠を検査票からたどる

状態は両画面幅の実測と独立レビューを完了し、ドラフトPRで提出。[T030](T030-dialog-keyboard-trap.md)の2.1.2の離脱観察を使い、[VISION](../VISION.md)にある、検査票の根拠が足りないときに画面へ戻って確かめる流れを、1ページの通常CLIで試した。[PR #102](https://github.com/k-s-h-r/wcag-audit-kit/pull/102)

## 作業と成果物

初期表示の検査票を読み、操作探索へ進む。Escape直前に観察したダイアログの状態と保存キャプチャーが一致したとき、そのページ・状態・画面幅の2.1.2の検査票に操作経路と離脱の記録を表示する。[ADR 0112](../adr/0112-bind-keyboard-exit-evidence-to-opened-cases.md)

## 完了条件

- 通常の `page-audit --initial-only` の結果を `page-next` で読み、記録された案内から簡易探索を再開し、両画面幅の該当検査票へたどり着ける。
- 離脱できる対照と、試したキーで留まる対照で、保存した操作・状態の証拠、機械結果、未判定の検査票を追える。
- 状態・幅・ページが一致しない証拠は関連付けを保留し、旧runに保存された機械結果を従来どおり読める。

正常例と問題例の双方で、簡易探索後の既定5件に両幅の検査票が出た。両例とも検査票の判定は未実施のまま。動的に表示が変わる対照と、画面幅・入力・URLが一致しない証拠は別エージェントが確認した。[実測と独立レビュー](../../validation/development/T033/README.md)

## 担当範囲

`codex/t033-operation-evidence-in-next-cases` の別worktreeで作業する。簡易探索における2.1.2のダイアログの離脱記録と `page-next` が担当範囲。ほかの操作や支援技術の確認は個別の証拠を使う。[試験手順と証拠](../../validation/development/T033/README.md)
