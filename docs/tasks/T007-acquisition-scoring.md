# T007：取得結果の照合を1種類だけ接続する

状態：未着手。前提タスク：T002・T003。測定結果から対象を選ぶ。

未接続の取得期待のうち、最初の機械検査の実測で必要になった1種類を、実証拠と照合できるようにする。全17観点の一括実装は行わない。

## 作業と成果物

T003等の記録から、列挙した対象や操作経路など、同じ状態・対象を確認できる機械的な取得を一つ選ぶ。期待結果、取得する事実、必要な生の証拠、照合不能な場合の状態を先に定義する。適した対象がなければ、理由を記録して後続タスクへ再分解する。

既存の取得契約を使い、証拠の欠落・改変、対象や状態の不一致、部分取得を成功にしない照合を追加する。取得できたこととWCAGの判定は別の結果として保持する。観点の取り込み可否が変わる場合はWORKERと報告にも同じ条件を反映する。

新しい実装とrunで結果を記録し、T002・T003の過去runを新しい採点方法で書き換えない。将来の比較には実装版・採点版の差を明記する。

## 完了条件と確認

- 選んだ種類に、取得一致・不足・証拠不一致の意味のある試験がある。
- ほかの未接続の取得期待は未確認のまま残る。
- 取得一致を達成基準の適合へ変換しない。
- 新しいrunの証拠、結果、厳格採点の挙動と残る制約を記録する。

## 担当範囲と引き継ぎ

共有箇所の`benchmarks/core.py`、必要に応じた`case_contracts.py`・WORKER・採点試験を担当する。runner、CLI、帳票コードへの変更が必要ならT008や調整担当と順序を決める。T009が扱う収集器と役割を分ける。共通の仕様を無断で広げない。

完了時に記載する情報：選んだ取得種類と理由、証拠契約、変更した仕様、新しいrun、未接続の残り、G1に必要な確認。
