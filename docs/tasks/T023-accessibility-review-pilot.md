# T023 つまずく場面と改善案を返す点検を試す

状態は点検レポートとローカル試作の検証を完了し、[PR #89](https://github.com/k-s-h-r/wcag-audit-kit/pull/89)で提出。前提は[T022](T022-url-to-process-audit.md)で実際にたどった一経路の操作・観察記録。

[VISION](../VISION.md#アクセシビリティ点検モード)にある、開発や運営で使える点検を小さく試す。達成基準の判定を示すWCAG検査票と併用し、操作の負担を減らす案をチームが検討できるようにする。

## 作業と成果物

一つの手続きを選び、例えばスクリーンリーダーで空きを聞いて回るような場面から、何をするとどんな手間がかかるかを証拠で示す。実際に観察した挙動、影響を受けうる利用状況、改善案を明記する。負担を減らせるという見立ては、改善前後の操作回数や案内の分かり方など、場面に合う方法で確かめる。

成果物は、開発・運営のチームが読む点検結果の試作一つと、その根拠・未確認事項。記録は `validation/development/T023/` の新しいrunに保存する。

## 完了条件と確認

- 報告から、どんな人が何をしようとするとつまずくか、元の操作と改善案を追える。観察した事実と、提案や未確認の効果を区別できる。
- 同じ経路のWCAG検査票と併用でき、改善案を加えても元の判定と根拠は保持される。
- 読み手が次に試す変更を説明できるか確かめ、繰り返し使う形にするために何が足りないかを記録する。

## 担当範囲と引き継ぎ

点検結果の試作と評価を担当する。検討の結果から、独立した依頼の入口や出力の形に必要な変更を判断する。別worktree・runを使い、WCAG検証の保存済み記録を参照する。
