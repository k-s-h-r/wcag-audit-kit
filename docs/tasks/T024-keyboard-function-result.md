# T024 キー入力と機能の結果を照合する

状態：実装・独立レビュー・前後の計測を完了。採用は[PR #87](https://github.com/k-s-h-r/wcag-audit-kit/pull/87)で確認する。前提：[T020のURL起点の実測](T020-url-only-machine-score.md)。関連：[T018](T018-widget-operation-sequences.md)・[T022](T022-url-to-process-audit.md)。

数量変更の問題例でクリック後は数量が増え、Enter後は増えなかった。現行の報告ではEnterの送出を記録できたところまでだった。ブラウザーに残った操作前後の証拠を使い、機能まで使えるかを確認する最初の対照とする。

## 作業と成果物

通常の `wcag-page` にURLと共通設定を渡し、数量変更の正常例、クリックだけで変更できる問題例、別のキーボード操作で同じ数量変更ができる例を比べる。機能の結果を示す状態を根拠に、入力到達、入力送出、実行結果を報告から追えるようにする。[問題集の対照](../../benchmarks/cases/2.1.1/README.md)

## 完了条件と確認

- クリックとキーの前後状態を同じ起点から比較できる。対象をクリックしたときの変化と、キーを送ったときの変化を対応付けられる。
- 通常の操作で機能が使える例と問題例を区別できる。代替操作で同じ結果になる対照で誤検出がなく、同じ結果か確認できない経路は未確認として残る。
- T020の採点で変更前後を別runとして比較する。観点の結果と達成基準全体の判定は、それぞれ根拠を示す。

## 担当範囲と引き継ぎ

主にキー入力後の結果をどう記録・照合するかを扱う。T018・T019と同じ探索・報告コードに触る場合は合流順を決める。検証記録は `validation/development/T024/` の新しいrunに保存する。共通の方法で再確認できた経路と、判断が残った経路をT022へ渡す。

## 実装と検証の状況

`codex/t024-keyboard-function-result` で、同じ初期状態からクリックとキーを試し、実入力と数値の前後を帳票へ記録する処理を追加した。レビューで挙がった祖先のキー割り当て、フォーカス後に現れる代替ボタン、ポインターを押した時点で変わるカウンターの3例を別runで確認した。前2例は両幅で未確認、最後の1例は機能の問題として指摘しなかった。代替経路の対照では、両幅でポインター専用部品のクリックと別ボタンへの実キーが同じ値になった。T020の採点は、このポインター専用部品の証拠がある場合に代替経路を採用する。[ADR 0096](../adr/0096-compare-keyboard-function-results.md)

Pythonの単体試験318件と配布スキルの同期を確認した。Debian上で旧版 `67aa42e` と実装版 `8fe594a` を比較した。旧版は初回の71ページと別runで取り直した5ページ、実装版は初回の76ページを採点した。問題39行の検出は8行から9行、対照48行の期待結果との一致は14行から16行。既存の検出と対照一致は同じ行で維持し、誤検出は0行だった。 [全87行の採点と操作の証拠](../../validation/development/T024/README.md)

今回の比較で確認したのは、初期表示から実行する数値表示の変更。変更後も問題30行、対照32行の判定に必要な確認が残る。実入力・初期値・操作後の値を結び付けた記録をT022へ渡し、手続き途中の別の機能や複数ステップの比較は各タスクで確認する。
