# T038 実Escapeで子のダイアログが閉じたことを帳票に残す

前提は[T036](T036-observe-nested-dialog-exit.md)の通常探索と層ごとの実測。PR #109の `098ec3d` から別worktree `codex/t038-record-nested-child-dismissal` で作業し、実測と独立レビューを経てドラフトPRで提出した。通常CLIのステップ上限だけを広げると、公式045・046とも両幅で実Escapeが届き、後者は子だけが閉じた。[PR #112](https://github.com/k-s-h-r/wcag-audit-kit/pull/112) · [再現記録](../../validation/development/T038/README.md)

## 作業と成果物

通常探索の実Escapeに、同じ主文書の親と子の開閉、および操作後のフォーカス先と層を記録する。既存の帳票の操作調査から入力と観察の原本を参照できるようにする。[ADR 0122](../adr/0122-record-escape-in-a-nested-dialog.md)

## 完了条件と確認

- 公式の2例で同じ探索経路から信頼されたEscapeを確認し、子が閉じた場合と表示が続いた場合を両幅で区別する。
- 親も閉じる、対象を置き換える、別のダイアログが現れる、親子関係を取れない場合は、子の開閉を確定した観察を出さない。
- HTMLとExcelの既存表で、閉じた層とフォーカス先から証拠へ移れる。JSONの観察と原始ログの添字が一致する。
- 通常24ステップの順序や2.1.2・2.4.3の判定に、この観察を結び付けない。一層の039・040を再測定し、機械検査の結果を照合する。

公式045・046の通常探索、8対照の両幅、単層の回帰と旧版の帳票再生成を確認した。別のレビュアーが通常探索と境界対照を再測定し、帳票と原本の参照を照合した。[検証記録](../../validation/development/T038/README.md)

## 担当範囲と引き継ぎ

ダイアログの入力前後の観察、通常探索の証拠管理と、既存の操作調査への表示を担当した。通常24ステップでの経路発見と、複数の入力先を循環する場合の判断は残件とする。[検証原本](../../validation/development/T038/proof.zip)
