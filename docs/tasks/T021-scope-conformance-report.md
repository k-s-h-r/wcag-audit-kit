# T021 対象範囲の適合・不適合・未確認を検査票で示す

状態：着手可。前提は[T008の帳票](T008-machine-report.md)と[T004の呼び出し・最終回答の記録](T004-codex-invocation.md)。関連は[T022](T022-url-to-process-audit.md)。

[VISION](../VISION.md)の二つの成果物を、対象範囲の結論から使えるようにする。現行の報告は達成基準ごとの判定、未確認、`audit_complete` を持つ。検査が完了しても不適合はあり得るため、利用者に伝える結論を保存済みの判定・範囲・証拠から出せるか検証する。

## 作業と成果物

保存済みのローカル試験結果を使い、単独ページと小さな複数ページの報告で結論を照合する。必要な変更は既存の[検査票と不適合箇所一覧](../../skills/wcag-audit-kit/references/checksheet.md)へ入れる。WCAGの版とレベル、判定した範囲、結論、残る確認を表示し、該当する達成基準、URL・状態、証拠をたどれるようにする。

| 試験に使う記録 | 確認したい結論 |
| --- | --- |
| 必要な適合要件・対象・状態を確認し、目標レベルの適用基準をすべて満たした | 確認した範囲は適合 |
| 範囲内で根拠付きの不適合を確定した | 不適合。ほかに未確認があれば併記 |
| 不適合の確定がなく、未探索・未判定・適合要件の未確認が残る | 未確認。追加で確かめる箇所を示す |

実データの保存先は `validation/development/T021/` の新しいrunとする。回帰試験で作った記録は試験データとして扱う。

## 完了条件と確認

- HTML・JSON・Excelで、同じ保存済みrunと範囲から同じ結論を読み取れる。1ページの報告と複数ページの報告は、それぞれの範囲・手続き・適用基準に沿う。
- 根拠付きで確定した不適合は、ページ別一覧から再現手順と証拠をたどれる。axeの候補、未探索、人への確認待ちは、それぞれ元の状態を保持する。
- 既存の `audit_complete` と終了コードの意味を保つ。報告だけの依頼で再訪問や判定更新を行わずに同じ結論を再出力できる。
- T004で使ったような隔離環境で、帳票と最終回答の結論・パスを照合する。ホストの実行結果は帳票の回帰試験と別に記録し、実行できなかった場合は条件を引き継ぐ。

## 担当範囲と引き継ぎ

集計、チェックシート、ページ別と全体の報告、最終回答の引き継ぎを担当する。T020の収集・採点とは独立したworktree・runで始められる。共通CLIや `page_workflow.py` の変更が要る場合は、探索担当と合流順を調整する。

完了時は、使った実装版、試験ケースと結果、帳票から根拠へたどる例、未確認のホストや範囲を残し、T022へ渡す。
