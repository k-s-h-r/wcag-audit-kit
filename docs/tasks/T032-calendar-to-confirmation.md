# T032 メニューから見学日の選択、人数修正、確認までを一つの手続きで測る

状態は、統合版 `5bb4a80` から分岐し、両例の確認画面への到達と選んだ4.1.3の判定を検証済み。前提は[T022の手続き](T022-url-to-process-audit.md)、[T026の実Orca](T026-process-error-speech.md)、[T029の空き状況](T029-audit-availability-without-color.md)。[VISIONの利用場面](../VISION.md#人が使うように最初から最後まで試したい)

## 作業と成果物

同じ見た目のローカル対照を用意する。閉じたメニューを開き、見学日の空き状況を確認し、日付を選ぶ。1名で確認したときの案内を確かめ、人数を直して日付と人数の確認画面まで進む。実予約と外部送信は試験範囲外。

採点側はページ、キー操作、採点条件を固定してハッシュを残す。別の検査担当には起点URLと目的を渡し、画面と公開アクセシビリティ情報を使って操作してもらう。同じ対照で実Orcaを起動し、エラー表示・フォーカス・発話の時刻を照合する。[ADR 0111](../adr/0111-observe-a-complete-calendar-and-error-recovery-journey.md)

## 完了条件

- 起点から確認画面までの到達、実キー入力、表示とフォーカスを各例で照合できる。
- 別の検査担当による観察と、実スクリーンリーダーの発話の観察範囲を区別する。発話から対象の判定を得るには同じ環境で正常対照の発話を取得する。
- 通常のCLIの機械検査で確認できた範囲を示す。実Orcaで確かめた入力エラーの判定を検査票へ記録し、残る観点と、不適合から証拠までの参照を確かめる。
