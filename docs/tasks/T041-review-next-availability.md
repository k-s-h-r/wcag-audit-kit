# T041 最初の空きを探す負担と「次の空き」の効果を点検する

[VISION](../VISION.md#アクセシビリティ点検モード)の例を、ローカルの予約カレンダーで確かめる。前提は[T027](T027-accessibility-review-workflow.md)の点検手順と[T026](T026-process-error-speech.md)で使った実Orcaの採取方法。T023・T027で調べた人数変更と、T029で調べた色の手がかりとは対象操作が異なる。

## 担当範囲と完了条件

- 同じ開始日、空き状況、到達日を固定し、片方にだけ「次の空き」を加える。最初の空きが分かったところで止める。
- 同じ環境で日別移動と「次の空き」を操作し、キー入力、通過した日、実Orcaの発話を比較する。
- URLと利用目的だけを受け取った別担当が得た画面・操作の観察を照合する。
- 実際に生じた負担、改善案、同じ条件で得た効果と未確認を点検結果にまとめる。通常CLIの初期検査票と証拠を参照できるようにする。

公開PR #111の `405134e` を起点に、別worktreeの `codex/t041-review-next-availability` を使った。成果物は `validation/development/T041/` に保存する。[ADR 0125](../adr/0125-measure-next-availability-in-a-calendar-review.md)

## 実行結果

両例で12月19日に到達。日別移動は6キーと日付・空き状況の発話5回、「次の空き」は3キーと発話1回だった。別担当はEnter操作で6キーと3キーを再現した。WCAG 2.2 AAの初期検査の結論は両例とも未確認。予約の送信は試験の範囲外とした。[点検結果](../../validation/development/T041/review.md) · [再現と原本](../../validation/development/T041/README.md)

別環境へ展開する際は、同じ出発日と同じ到達条件で他のスクリーンリーダー・実利用者による比較を行い、空きがない場合と月をまたぐ場合も追加する。
