# T008：機械検査の報告と残作業を照合する

状態：1ページの問題一覧、フォーカス画像、4モードの共通欄をHTML・Excelで照合済み。共通部品の測定をページ別に参照するHTMLも確認済み。

機械検査で確認できたことと、AI・実SRへ残ることが、JSON・HTML・Excelで一致して伝わるか確かめる。

## 作業と成果物

T002・T003の確定した記録を読み取り、既存の帳票を比較する。機械ルールの結果、達成基準全体の判定、未探索、未確認、モードによる省略、取得照合の未接続、具体的な箇所と証拠を追う。報告だけでページを再訪問したり、判定を更新したりしない。

証拠や判定が出力間で対応しない場合は、再現例と期待する表示を記録する。修正は最小限の報告処理に限定し、元runの判定を変更しない。出力を作り直す場合は新しい保存先と参照元を記録し、過去の結果を失わないようにする。

T007で取得の表示仕様が変わる場合は合流後に再確認する。成果物は比較結果、必要な報告修正、再実行手順とする。

## 完了条件と確認

- JSON・HTML・Excelの対象、判定と未確認の件数、証拠の対応が一致する。
- 機械ルールの通過を達成基準全体の通過として表示しない。
- 報告だけの操作で再検査・判定更新が起きない。
- 変更した場合は関連する帳票試験と、ブラウザー表示・Excel読戻しで結果を確認する。

## 担当範囲と引き継ぎ

ページの報告処理は`page_workflow.py`、共通帳票は`checksheet.py`等を必要な範囲で担当する。ベンチマーク帳票側へ変更が必要なら先に調整し、T007が扱う採点ロジックは変えない。実測で不要なレイアウト変更は加えない。

完了時に記載する情報：比較したrun、出力と証拠、見つかった不一致と修正、確認内容、G1に残る問題。

## 確認結果

13ページ・24経路を検査し、うち3ページを抽出して検査票461行と機械検査203行を比較した。自動検出の問題が集約された4行に問題一覧へのリンクを追加した。HTMLはChromiumで幅320pxと1280pxの表示を、Excelはシート名とリンク先をファイルの読戻しで確認した。試験した各ページでAAの未実施55件と対象水準外の31件を維持した。今後の対象は採点帳票とモード別の残作業の照合。[ADR 0026](../adr/0026-verify-widget-state-and-input-scope.md)

## フォーカス画像の帳票

2.4.7の画像と入力ログを専用欄に表示し、取得済み・比較不可・省略とその理由をJSON・HTML・Excelで照合した。Chromiumで幅320pxと1280pxのHTMLを確認し、画像・操作証拠へのリンクとExcelの相対リンクを検証した。達成基準の判定は未確認のまま維持した。[ADR 0030](../adr/0030-collect-and-measure-visual-evidence.md)

## モードごとの共通欄

機械のみ、AI併用、SR併用、AI＋SRの各設定をChromiumで実行した。131観点の対応、準備、実施記録をJSON・HTML・Excelで読み戻した。画像は順に0・2・0・2枚。AIの内容判断と実SRの発話はこの比較では実行していない。次は、発話や内容判断を実施できる環境で、選んだ検査票と実施記録との対応を確認する。[ADR 0033](../adr/0033-record-status-acquisition-and-mode-evidence.md)

## 共通部品の測定のページ別参照

`shared-contrast --page-exact <URL> --out <新しいHTML>` で、指定ページを起点に既存のaxe測定を読めるようにした。実バッチで、8.6:1の同じ測定のページ、1.35:1の異なる測定のページ、収集失敗・未着手を区別した。元の証拠を開く相対リンクとハッシュ、証拠改変時の未確認、幅320pxでの表示を確認した。元のページ別帳票・検査票とソースの記録は保持した。[ADR 0051](../adr/0051-export-page-shared-contrast-reference.md)
