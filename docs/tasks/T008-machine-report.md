# T008：機械検査の報告と残作業を照合する

状態：未着手。前提タスク：T002・T003。T007・T009と担当箇所を分けて進める。

機械検査で確認できたことと、AI・実SRへ残ることが、JSON・HTML・Excelで一致して伝わるか確かめる。

## 作業と成果物

T002・T003の確定した記録を読み取り、既存の帳票を比較する。機械ルールの結果、達成基準全体の判定、未探索、未確認、モードによる省略、取得照合の未接続、具体的な箇所と証拠を追う。報告だけでページを再訪問したり、判定を更新したりしない。

証拠や判定が出力間で対応しない場合は、再現例と期待する表示を記録する。修正は最小限の報告処理に限定し、元runの判定を変更しない。出力を作り直す場合は新しい保存先と参照元を記録し、過去の結果を失わないようにする。

T007で取得の表示仕様が変わる場合は合流後に再確認する。成果物は`validation/development/T008/`の比較記録、必要なら小さな報告修正と、新しい表示・読戻しの証拠。

## 完了条件と確認

- JSON・HTML・Excelの対象、判定と未確認の件数、証拠の対応が一致する。
- 機械ルールの通過を達成基準全体の通過として表示しない。
- 報告だけの操作で再検査・判定更新が起きない。
- 変更した場合は関連する帳票試験と、ブラウザー表示・Excel読戻しで結果を確認する。

## 担当範囲と引き継ぎ

ページの報告処理は`page_workflow.py`、共通帳票は`checksheet.py`等を必要な範囲で担当する。ベンチマーク帳票側へ変更が必要なら先に調整し、T007が扱う採点ロジックは変えない。実測で不要なレイアウト変更は加えない。

完了時に記載する情報：比較したrun、出力と証拠、見つかった不一致と修正、確認内容、G1に残る問題。
