# 並行して進める開発タスク

更新日：2026-11-18。起点は`6f3384c`（PR #11のマージ後）。

[開発計画](../ROADMAP.md)を実行するための作業一覧。タスクごとに依存関係、成果物、担当するファイル、完了条件を定める。現在の状態と実測の参照先は各タスクのファイルで管理し、別のセッションへそのまま渡せるようにする。タスク分解の判断は[ADR 0020](../adr/0020-parallel-development-tasks.md)に残す。

## まず4担当で着手する

| 担当の例 | 最初のタスク | 次に進めるタスク |
| --- | --- | --- |
| A：測定・採点 | T001 共通測定計画 | T002 タイトルの基準値 → T007 取得結果の照合 |
| B：画像・ページ検査 | T005 対象固有の手順 | T001完了後にT003 画像の基準値 → T009 実測した機械検査の不備を修正 |
| C：呼び出し・報告 | T004 Codexでの呼び出し | T002・T003完了後にT008 報告の整合確認 |
| D：URL・全体進行 | T006 URL収集の基準値 | G1達成後にT010 指定URL一覧の検査 |

担当の例は固定の人員や同時起動数を要求しない。最初の4タスクは別の新規成果物で進められる。T001以外の先行作業は準備と既存機能の評価に限定し、機械検査の実力を測る前に広範囲の実装を始めない。

T001は新しい汎用基盤を作るタスクではない。既存CLIで最初の2観点を測る条件と集計方法を小さく固定し、T002・T003を始められるようにする。機械検査の基準値は、ホスト上のスキル選択動作と分けて測るため、T004の完了を待たず収集できる。

## 合流時に確認する条件

| 条件 | 調整担当が確認すること |
| --- | --- |
| G1：選択した1ページの機械検査を次へ使える | T001〜T003の測定範囲が追跡できる。必要なT007・T009の修正後、対象の期待結果が一致し、誤検出・未確認が残らない。T008で残るAI・実SR確認も正しく報告できる。確認した実装・問題集・環境と新しいrunをロードマップから参照できる |
| G2：指定URL一覧で使える | T010のページ別結果と集計が一致し、中断した未完了分を再開できる。T006の候補一覧と、実際に検査した一覧を区別できる。T004の確認範囲で、依頼からスキルを実行できる |

測定タスクが完了しても、成績が悪ければG1は未達のままにする。G1に必要なのは選択範囲の正確さであり、全86基準やすべての取得観点の実装完了ではない。T011とT012の準備・実測は独立した環境なら並行できるが、優先順位は機械検査、AI、実SRの順とする。

## 競合を避ける作業単位

- タスクごとに`codex/t001-...`等のブランチと別worktreeを使う。同じ作業ディレクトリーでブランチを切り替えながら複数担当を動かさない。
- 新しい記録は`validation/development/T001/`等、担当IDの下へ保存する。各試行はさらに別runにし、既存の記録を上書きしない。実データの保存方法は、証拠の大きさ・機密性と既存の規約に従う。
- ブラウザー、プロファイル、認証、試験データ、待受ポート、出力先を担当ごとに分ける。実スクリーンリーダーやネイティブGUIを使う同じデスクトップは、一人が操作する。
- ベンチマークで採点側と検査側が分かれるタスクは、公開ページ・必要な手順・生の証拠だけを検査側へ渡す。正解を読んだ開発セッションは検査側へ流用しない。
- 最初の基準値タスクは実装と問題集を変更しない。修正はT007〜T009等へ分け、元の成績を保持する。
- 共通リソースは`skills/wcag-audit-kit/`だけを編集し、同期結果を同じPRへ含める。ほかの3スキルのコピーを別担当が直接編集しない。
- `benchmarks/core.py`・`runner.py`・`run.py`とCLI入口の`audit.py`は共有箇所とする。同時編集を避け、変更が必要なら先に担当範囲を調整する。共通の集計仕様はT001へ戻してから使う。

各PRは担当のタスクファイルへ状態、検証記録、未確認、次の作業を記載する。ロードマップは担当ファイルを参照し、段階や次の作業が変わる合流時に調整担当が更新する。索引を全員で編集する必要はない。

並行作業を開始するときは、依頼する側がタスクごとの担当セッションと、共通部分を調整する担当を決める。担当が重ならないことを確認してから着手する。

各PRのADR番号は着手時に調整担当が割り当てる。同じ番号を複数の未マージPRで使ってしまった場合は、レビュー中の新規ADRだけを改番し、索引とリンクを直す。マージ済みADRの改番・書き換えは行わない。mainへのマージは利用者の指示に従う。

## 新しいセッションへ渡す依頼

> AGENTS.md、docs/ROADMAP.md、docs/tasks/README.mdと、担当するdocs/tasks/Txxxのファイルを読んでください。前提タスクの完了根拠を確認し、このタスクの範囲だけ進めてください。別worktreeと作業ブランチを使い、証拠と未確認事項を記録して、新しいADRを添えたPRを作成してください。

実行担当・採点担当・操作環境が必要なタスクでは、その担当範囲も依頼に添える。前提が揃わない場合は不足を記録し、準備できる範囲を進める。測定前に期待結果を渡さない。
