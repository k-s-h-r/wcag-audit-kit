# T027 アクセシビリティ点検を依頼して使う

状態は手順を実装し、応答を確認中。前提は[T023](T023-accessibility-review-pilot.md)で試した見学予約の点検結果と、参照したT022の検査票・観察証拠。

T023では、操作上のつまずき、変更する箇所、効果の測り方を一つの点検結果にまとめた。[VISION](../VISION.md#アクセシビリティ点検モード)の日常的な依頼で同じ流れを使えるようにする。

## 作業と成果物

`wcag-audit-kit`を明示して点検を頼むと、保存済みの証拠を読む手順か、指定URLから実際に操作する手順を選ぶ。結果には操作と証拠、利用への影響、改善案、効果の確かめ方、未確認、元の検査票への参照をそろえる。改善を試した証拠がある場合は、変更前後の結果と条件も示す。 [点検の手順](../../skills/wcag-audit-kit/references/accessibility-review.md) · [ADR 0104](../adr/0104-accessibility-review-workflow.md)

## 完了条件と確認

- 保存済みの操作記録を渡す依頼で、記録を変更せずに操作、影響、改善案、効果の確かめ方、未確認、元のWCAG判定を示せる。
- URLを渡す依頼で、指定した範囲の操作と証拠を新しいrunに保存し、観察した結果から点検結果を作れる。依頼の範囲内で止めた操作と、判定や再測定が残る箇所が分かる。
- 4スキルの配置と同期、CLIの検証手段、既存の報告・判定が保たれる。同期確認、Python単体テスト、変更した資料の相対リンクを確認する。

## 担当範囲と引き継ぎ

起点はT023の `ca89597`。公開された[PR #89](https://github.com/k-s-h-r/wcag-audit-kit/pull/89)と同じツリーを使った。別worktreeの `codex/t027-accessibility-review-workflow` で、`wcag-audit-kit` の手順、共通資料と配布用コピー、利用案内を更新する。試験の記録は `validation/development/T027/` に置く。応答を読む担当には、操作観察に使うローカルサイトと保存済みの観察を分けて渡す。

## 実行結果

T022の問題例の起点URLから、既存のブラウザー操作でキーでは増員できないことと、クリック後に確認画面まで進めることを再現した。フォーカス、画面とアクセシビリティツリーを新しい場所に保存し、参照した元の証拠と判定のハッシュを照合した。明示呼び出しからの応答は、保存済みの証拠とURLを渡す二つの依頼で別に確認する。 [実行記録と試し方](../../validation/development/T027/README.md)

`python3 scripts/sync_skills.py --check` と `python3 -m unittest discover -s tests -p 'test_*.py'` を実行し、配布用資料の同期と324件の単体テストが通過した。CLIコードと過去のrunの差分はない。
