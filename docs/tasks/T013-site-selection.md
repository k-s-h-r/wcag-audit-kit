# T013：URL候補からサイトの試験対象を選ぶ

状態：完了。ローカルの有限サイトで、認証や操作で見つけた対象をページ別の機械検査に引き継ぎ、未検査の対象を区別できることを確認した。

全体進行が選定理由を説明できる、小さな試験計画を作る。候補URLの発見と、検証するページ・状態・手続きの選定を区別する。

## 作業と成果物

T006のURL台帳と、T010で扱った小規模サイトを使う。全件又は抽出の方針、ページ種別、主要機能、共通部品、権限、操作後の状態、一連の手続きの開始と終了を記録する。抽出する場合は代表ページと無作為抽出の方法、選定・除外理由を残す。

選定対象をページ担当へ渡せること、未訪問・未発見・試験対象外の理由を区別できることを確認する。新しい汎用形式を先に作らず、既存設定と資料で不足する最小の情報を定める。状態が同じURLで変わる場合や、手続きの一部を外してしまう例も確認する。

成果物は`validation/development/T013/`の試験計画、台帳との対応、担当への入力例、不足する情報と必要なら小さな全体進行の改善。

## 完了条件と確認

- 範囲・環境・レベル・選定理由が明記され、各対象を追跡できる。
- 一連の手続きに必要なページと状態が欠けないか確認できる。
- 未検査の範囲へ適合の主張を広げない。
- T014が受け取れる対象一覧と完了確認の条件がある。

## 担当範囲と引き継ぎ

試験計画と全体進行の責務を担当する。URLクローラー、個別の検出器、帳票全体の再設計には広げない。構造化を追加する場合は、既存設定と保存済みrunへの影響をADRで説明する。

完了時に記載する情報：台帳と計画、選定根拠、対象と状態、手続き、未検査範囲、T014への引き渡し方法。

## ローカルサイトの再現試験

`python3 tests/site_selection_browser.py --out <新しい保存先>`で匿名7候補、認証後8候補、操作後だけ現れるリンクを確認した。対象・状態・選定根拠を記録し、設定用のURL一覧に渡した。共通フッターは3ページで同じHTMLとアクセシビリティツリーだったが、CSSによるリンクのコントラストは2ページで通過、1ページで問題だった。ナビゲーションの現在位置もページごとに異なった。共有結果を使う際は、ルールと表示条件ごとに再利用の根拠を示す必要がある。[ADR 0036](../adr/0036-pass-the-limited-machine-gate.md)

Chromium 156で、選定した9 URLを順序どおりに`pages`の設定指定と`page-batch`へ渡した。認証が必要な履歴、操作後に見つけた完了ページ、HTTP 404のページを先頭に置き、実行上限を3ページにした。先頭2ページは個別のHTML・JSON・Excelとハッシュで照合できる証拠を出力した。完了ページのクエリとフラグメントも保たれた。404の1ページは失敗として記録し、残り6ページは未実行で、ブラウザーのアクセスも発生しなかった。

T014へは`selection-packet.json`で選定根拠、権限による表示差、手続きと対象外の情報を渡す。`selected-urls.json`の各URLを`batch/page-batch.json`の状態と照合し、ページ別の帳票と証拠を追跡できる。バッチ中は一つの認証状態を使う。同じURLで認証前後の状態を比較する操作や、手続き全体をたどる操作はブラウザーで別に実施した。再現試験の認証状態は終了時に破棄する。適合は判定していない。

## 共通部品の同じ初期表示の測定を参照

`shared-contrast` で各ページのaxe証拠を照合し、同じ環境と対象の同じ測定を一つにまとめた。実フィクスチャでは同じ8.6の2ページをまとめ、同じフッターHTMLでも1.35だったページは別に出た。404・未着手・証拠不一致も追跡できる。共通部品の他の観点や、操作後の状態はページごとに確認する。[ADR 0047](../adr/0047-reference-shared-contrast-observations.md)
