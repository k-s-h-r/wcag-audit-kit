# T026 予約手続きの入力エラーを実Orcaで調べる

状態　ローカルで実測と帳票の照合を完了。両例で実キーだけで確認画面に到達し、エラー発生時の発話の違いを4.1.3の検査票に反映した。

前提は[T012の実Orca対照](T012-screen-reader.md)、[T021の帳票](T021-scope-conformance-report.md)、[T022の手続き](T022-url-to-process-audit.md)。`codex/t026-process-error-speech` をT023の `ca89597` から分岐した。

## 作業と成果物

同じ入力エラーを表示する予約手続き2例で、起点から1名の入力、エラー、2名への修正、確認まで進む。フォーカスが確認ボタンに残るエラー通知の表示、役割、発話を照合し、WCAG 2.2 AAの4.1.3の検査票に記録する。不適合箇所一覧から再現手順と証拠をたどれることを確かめる。

T022の記録を保持し、今回の対照ページと採点条件は実測より先に固定する。実Orcaは作業専用のX11、D-Bus、設定とプロファイルで起動する。正常対照の発話や実キーの到達条件を確認できない試行は判断保留にする。

## 完了条件

- 2例の開始、入力エラー、修正、確認に実キー操作で到達し、画面、フォーカス、発話を元の記録から追える。
- 同じ環境の正常例と問題例で、エラー時に発話された内容と、入力欄に戻った際の説明を区別できる。
- 発話の判定が対象状態の検査票にあり、確定した不適合の一覧から再現手順と証拠をたどれる。未確認の観点や全体の適合の結論も確かめる。

## 担当範囲と引き継ぎ

実測スクリプト、対照ページ、帳票の照合は `validation/development/T026/` に置く。共通CLIの変更が必要なら先に担当を調整する。支援技術や入力エラーの形式を広げる場合は、その組み合わせの正常な発話を確認してから検査する。[ADR 0103](../adr/0103-bind-native-error-speech-to-process-reports.md) · [実測と再現手順](../../validation/development/T026/README.md)
