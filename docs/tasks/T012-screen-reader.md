# T012：限定した環境で実スクリーンリーダーを確認する

状態：専用環境の整備・実操作調査完了。選択問題集の通知判定能力は未達。開始条件：限定G1提案コード、T005。独立した実行環境があればT011と並行できる。

実SRを使う観点のうち、状態通知等の小さな対象から始める。使用するOS・ブラウザー・支援技術を一組に限定する。

## 作業と成果物

既存の`references/screen-reader.md`とアダプター、`benchmarks/native_status.py`等の実証を読み、使用できる組み合わせを決める。準備状態を確認し、正常な対照で名前や通知を実際に取得できることを確かめる。モック、アクセシビリティツリー、仮想読み上げは実SRと分ける。

通知あり／なしの実操作と発話を新しいscreen-readerモードのrun等へ記録する。正常例が発話しない環境では、問題例の無発話を失敗の根拠にしない。環境不足・操作手順の問題・対象の問題を分ける。採点側の正解を検査担当へ渡さない。

成果物は`validation/development/T012/`の環境、準備と対照の記録、操作・発話・判定・採点、再実行方法。必要な修正は選んだアダプターに限定する。

## 完了条件と確認

- 一組の環境で実SRを動かした証拠があり、正常な対照を確認できる。
- 通知の見た目と実発話を区別し、必要な対象・状態と対応させる。
- 実行不能な場合は方法調査の結果を残し、能力達成を未完了とする。
- 使用条件、成績、残る未確認、T014へ適用できる観点が明記されている。

## 担当範囲と引き継ぎ

専用の実SR環境と対象アダプターを担当する。AIの意味判断やURL収集の処理は変更しない。同じデスクトップをほかのGUI担当が同時操作しない。

完了時に記載する情報：OS・ブラウザー・支援技術の版、正常対照の証拠、選んだ観点と成績、実行不能条件、再実行手順。
