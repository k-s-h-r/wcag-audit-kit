# T034 Tabのフォーカスに伴う文書移動の要求と遮断を記録する

状態は実装・実測・独立レビューを完了し、ドラフトPRで提出。問題集の073とc01では、通常のURL入口から両画面幅でブラウザーが送ったTab、フォーカス、別文書の移動通知と、通信の遮断をたどれた。独立レビューで見つかった同じURLへの競合する要求や、子フレームを経る例は発生元の照合を保留する。[PR #104](https://github.com/k-s-h-r/wcag-audit-kit/pull/104) · [検証結果と証拠](../../validation/development/T034/README.md)

[T020](T020-url-only-machine-score.md)の073は、通常のURL入口から移動先への通信を遮断した。3.2.1-02に使うフォーカスと移動の根拠は確認できなかった。[従来の測定](../../validation/development/T020/README.md)

## 作業と成果物

`8520421` から `codex/t034-focus-navigation-evidence` の別worktreeで作業する。通常の補助Tab観察、入力記録、通信制限の記録と配布用の同期を担当する。別文書への移動が要求され、制限で遮断された場合に、Tabで移ったフォーカスと移動要求を同じ観察からたどれるようにする。[ADR 0113](../adr/0113-record-blocked-navigation-on-tab-focus.md)

## 完了条件と確認

- URLと通常の探索設定を渡し、既存の問題例の両画面幅で、最初のTab、フォーカス先、メインフレームの別文書への要求、通信の遮断を同じ記録で確認する。
- 正常例、Enter、同じ文書内の移動、タイマー、iframe、書き込み通信を区別する。取り消したフォーカス時の要求を、その後に同じURLを要求したキーアップと結び付けない。
- 通信の制限を保持し、移動先への受信がないことを照合する。達成基準3.2.1の判定と、確認していない移動先の表示は未確認に残す。
- 過去の帳票を読めることを確かめる。探索実装が異なる場合は、新しいrunを作る既存の扱いを保つ。

## 引き継ぎ

[T034の検証記録](../../validation/development/T034/README.md)に再実行手順と結果を保存する。対象は、Tabでフォーカスが移ったときの別文書への要求のうち、Chromiumのイベントとガードの記録を照合できる範囲。フォーカス後のタイマーによる文脈の変化、iframe内の操作、表示やフォーカスだけが変わる場合は別の操作で確認する。
