# T005：対象固有の手順を1経路で実行確認する

状態：ローカルの1経路を実キーで再実行し、準備・操作・証拠・片付けを確認済み。

pstackから取り込んだ手順を、小さなローカルアプリで実際に試す。対象製品やWCAGの検出ロジックを修正するタスクにはしない。

## 作業と成果物

既存の`tests/fixtures/audit_site_server.py`等から、起動・到達・操作・結果の観察・復帰を必要とする短い1経路を選ぶ。`project-methods-template.md`を必要な範囲で具体化し、ソースを読める場合と、画面から確認した事実を区別する。

起動と準備確認、対象状態への到達、操作、証拠保存、後片付けまで実行する。後片付け後も証拠を読めることを確認する。手順の不一致、ツールや環境の不足、対象の機能の問題を分け、原因不明なら未確認とする。実行で確認していない経路は、そのまま残す。

成果物は`validation/development/T005/`の対象固有の手順、確認した版・環境、実行記録、生の証拠、再実行と復帰方法。形式は既存テンプレートを使い、新しい手順エンジンは作らない。

## 完了条件と確認

- 小さな1経路を開始から後片付けまで再現できる。
- 機能の観測できる結果と、WCAGの判定条件が混ざっていない。
- 手順の作成済みと実行確認済みを区別し、証拠が後片付け後も残る。
- 次の担当が使える操作方法と、未確認・必要な環境が明記されている。

## 担当範囲と引き継ぎ

変更先はT005の記録とこのファイル。既存fixtureは変更しない。共通テンプレートを直す必要が判明した場合は、実例を添えて別の修正へ切り出す。機密値は記録しない。

完了時に記載する情報：対象、確認した経路と環境、手順と証拠の場所、残る問題、T011・T012が再利用できる操作。

## 現在の実装での再実行

`python3 tests/project_procedure_browser.py --out <新しい保存先>`で、ログイン前、ログイン、入力と確認、入力を残した編集への復帰、保存、ログアウトの6段階をChromiumで実行した。TabとEnterの実入力44件、確認画面や保存後のフォーカス、ローカルの3つの操作要求と結果を照合した。終了時に専用サーバーを止め、テストセッションが残っていないことと、画像・入力の証拠を読み戻せることを確認した。実スクリーンリーダーの発話や達成基準の適否は追加検査へ渡す。
