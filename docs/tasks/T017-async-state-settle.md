# T017：短い非同期更新を待って状態を取得する

状態：限定範囲の取得修正完了（PRでレビュー待ち、G1未達）。前提タスク：T002・T003の基準値。使用する起点コードはT009のフォーム関連付け修正の提案ブランチ。親はT009だが、親の完了を開始条件にせず循環を作らない。

## 根拠と成果物

T009のimage-001で#loadの4操作は実行されたが、300ms後に追加される画像が全経路のstate.jsonにない。100ms固定待機だけでは状態を取り逃がす。T009の選択範囲の取得不足を、この独立原因へ分割する。

操作後の短い非同期更新を、観測できる範囲で上限付きに待つ。待ちの根拠・上限・未完了を証拠へ残し、無限待機や任意のサイトの全非同期完了は主張しない。ケースID・正解を待機条件へ埋め込まない。元の正解は不変とする。

完了条件は、修正前に遅延画像を取り逃がす再現、異なる短い遅延でも状態・axeを取得できること、上限を超えた待ちを未確認に残すこと、新規runでの再測定である。名前付き状態への採点接続は、取得後の証拠を見て別に扱う。

## 担当と共有箇所

page_explorer.js・page_explorer.pyと待機の回帰試験を担当する。共通同期で4スキルを更新し、採点器や問題集はこのタスクで変えない。別worktree・ブランチ・runを使い、validation/development/T017へ記録する。G1の合流ではT009からこの子タスクの完了根拠を確認する。

## 実行結果と引き継ぎ

担当：wcag-dev、codex/t017-observe-delayed-state、worktree /workspace/wcag-dev-t017。[650msの未取得の再現、300/650msの取得、上限とタイマー契約](../../validation/development/T017/README.md)を確認した。208試験と新規の画像runでも、操作後のimage-altの生データがあることを確認した。ただし成績は5/7一致のままで、名前付き状態の対応不足を[T018](T018-named-state-evidence.md)へ渡す。全非同期・全将来状態の完了は主張しない。

PR #22のレビューで、操作前のidle時間を使って観察が即時終了する不備を修正した。[新しい観察窓の起点の確認](../../validation/development/T017/review-001/README.md)はHTTP応答後のDOM更新の旧実装での見落とし、修正後の取得、209試験を含む。
