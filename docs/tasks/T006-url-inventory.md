# T006：URL収集と一覧化の基準値を記録する

状態：基準値の記録完了（PRでレビュー待ち）。前提タスク：なし。T001・T004・T005と並行できる。

既存のconfiguredとdiscoverが何を一覧化できるかを測る。機械検査やAI判断は実施せず、候補URLと実際の試験対象を決める前の資料を評価する。

## 作業と成果物

小さな既知のローカルサイトを用意し、URL一覧の指定と初期リンクの収集を比べる。相対URL、重複、クエリー、ハッシュ、範囲外、HTTP失敗、上限による未訪問を含む対象を選ぶ。既存fixtureで不足する入力だけ、新しい専用fixtureとして追加する。保存済みの問題集は変更しない。

期待するURL集合と範囲を実行前に固定し、取得元、訪問状態、失敗、未訪問が出力に残るか確認する。操作後や認証後だけで見つかるURLは、初期リンク収集の限界として記録する。全サイトを発見したことへ読み替えない。

成果物は`validation/development/T006/`の入力条件、pages出力、期待集合との比較、未発見・誤った統合・範囲の問題、再実行手順。新しいサイトマップ収集や動的巡回の実装は、実測後の別作業とする。

## 完了条件と確認

- configuredが指定一覧を使い、discoverが候補と取得元を返すことを実測する。
- 発見漏れ・余分な候補・訪問失敗・上限による未訪問を区別できる。
- クエリーや状態を誤って一律にまとめていないか、例から確認できる。
- T010とT013へ渡せる入力一覧と、追加実装が必要な点がある。

## 担当範囲と引き継ぎ

主な変更先はT006の記録と新規の専用fixture。`page_catalog.py`やCLIの修正はこの基準値へ混ぜず、必要なら具体的な不備として切り出す。ほかの担当のサイト・ブラウザー・出力先を共有しない。

完了時に記載する情報：入力と期待集合、取得結果、未発見範囲、指定URL一覧へ使える出力、後続の小さな修正候補。
