操作する前に、PC幅とスマホ相当幅で機械検査する

設定、撮影範囲、実際のコマンド

「おまかせ」の項目には、それぞれAA・機械のみ・初期表示だけを使います。既存runの再開や親の監査から担当を引き継ぐときは、確定済みの条件を使います。設定なしの単独検査は1280×900と320×900の等倍で行います。

標準の撮影範囲
設定保存する画面
off撮影なし
initial操作・スクロール前のページ全体を表示幅ごとに1枚
states初期表示に加え、到達した状態の画面やスクロールの画像
all状態ごとの画像に加え、自動探索で追加した操作の前後にその時点の表示範囲

初期検査はDOMから見える状態と要素一覧、Chromiumのアクセシビリティツリー、axeの実行結果を保存します。Tabの実入力と診断用スクロールは探索を始めた後に行います。コマンドは配置した wcag-page のフォルダーから実行します。

python3 scripts/audit.py page-audit --url <URL> --out <新しいrun> \
  --level AA --mode machine --screenshots initial --initial-only

python3 scripts/audit.py page-audit --url <URL> --out <同じrun> \
  --resume --quick-explore

初期画面だけという依頼なら1つ目で終了します。詳細な自動探索を指定されたときは2つ目の --quick-explore を --explore に替えます。撮影とAIの画像判断は独立した設定です。

候補を見つけ、初期画面から操作を再生して次の候補を増やす

どの要素に、どの入力を試すか
手がかり試す操作・記録
ボタンや開閉部品ネイティブ要素、ARIAの役割・展開情報、登録イベントなどから抽出。クリックやTabでの到達、Enterなどを試します。簡易探索は開閉部品を優先し、チェックボックスなどにはSpaceを選びます。
ポインター操作カーソルや登録イベントも候補の手がかりです。同じカーソルを継承するだけの子は、親の操作部品にまとめます。簡易探索のホバーはポップアップ属性や対応イベントがある候補に絞ります。
横並びタブ左右キーで移ったフォーカスも状態の識別に使います。表示がまだ切り替わっていない手動選択のタブでも、移動先からEnter・Spaceを試せます。
入力欄と遅延表示対象に応じて試験文字列の入力・クリア、画面下や横へのスクロールを候補にします。初期画像が全ページでも、実スクロールで初めて表示される要素があります。

キー候補は実Tabで対象に到達してから送ります。例えばEnterで開く経路では、実キーが狙った要素に届いた記録と、展開前後の状態を照合します。

簡易探索は操作した部品、変化した部品、新たに使える部品を優先します。画面上の位置だけが変わった候補の組み合わせは減らします。iframe、canvas、閉じたShadow DOMの内部は追加検査へ残ります。

簡易探索では表示環境ごとの通常の保留経路を最大12件に絞ります。絞り込み、待ち行列の残り、実行エラーは記録します。上限の調整は --max-steps、--max-states、--max-depth で行います。

ページ移動を伴うリンクは単独検査の巡回には使いません。フォーム送信や永続変更のおそれがある操作は自動候補から外します。通信制限や別ウィンドウで経路が中断した場合は、停止理由を記録します。

既知のGoogle Analyticsや同一オリジンのCloudflare RUMへの計測送信だけが遮断された場合は、対象に届いた実キーを照合します。同じ文書・要素で状態変化まで確かめられたときに、その操作の結果を記録します。機能の通信や観測できない効果が残れば保留です。

Tab後のフォーカスが aria-controls で指された一意の領域内に入ると、Escapeを後続候補に加えます。再生時に同じ領域内にいることを確かめ、フォーカスを動かさずに送ります。

ダイアログは閉じた直後と、次のTabを別に観測する

コンボボックスは、候補が見えるかと展開属性を照合する

実キーの後、aria-controls で結び付いた候補一覧が新たに見え、フォーカスが入力欄に残った場合に、4.1.2の展開の観点を検査します。aria-expanded="true" なら通過、false または未指定なら不一致です。透明な候補は表示として扱いません。

操作前後を比較し、条件のそろう2つのaxeルールで結果を再利用する

結果を再利用する場面

同じIDを持つ表示中の要素について、直前の経路の保存値・今回の操作前・操作後が一致した場合。対象は aria-valid-attr と正の tabindex の2ルールです。

全文書で検査する場面

ほかのaxeルールは全文書を検査します。2ルールも、比較元が無いときやiframe・Shadow DOMがあるときは全文書で検査します。DOM更新の記録が上限に達した場合も同様です。

開閉した領域と、離れたラベルの例

アコーディオンを開いて現れたボタンは再検査します。非表示の参照元が変わってボタン名が失われる場合は、参照されるラベルの変化も記録し、名前のルールは全文書で確認します。祖先が aria-hidden または inert の要素も毎回検査する側に残します。

同じ環境で検査済みの画面状態に戻る場合は、その状態の結果を参照します。新たな状態での2ルールの再利用とは別に、どの入力で到達したかを操作ログに残します。

帳票では、機械ルールの結果と達成基準全体の判定を別々に読む

新規の単独ページrunで開くファイル

修正箇所・見つかった問題reports/report.html の「自動検出した問題」。環境・状態・対象から証拠を開きます。
基準別の検査票と残りreports/report.xlsx、または data/report.json の cases・counts・exploration.remaining。
キーが届いたことと、何が変わったかwork/evidence/ 以下の input-events.json、transition.json。コンボボックスとメニューの前後の観察もここに残ります。
検査した画面や結果の出所同じ証拠フォルダーに状態と要素一覧、アクセシビリティツリー、画像が入ります。機械ルールは axe.json、再利用の参照元は operation-impact.json で追えます。

axeの違反・通過・要確認・対象なしはルールごとに集計し、達成基準は検査票に記録した判定から集計します。探索の履歴と保留経路は work/exploration.json にあります。

audit_complete: false は検証に未確認が残ることを示します。帳票が開けたら、残る検査票、未探索の経路、各モードで省いた観点を合わせて読みます。
