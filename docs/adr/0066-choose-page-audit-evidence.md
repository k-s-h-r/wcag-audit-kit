# 0066 ページ検査の撮影範囲を独立して選ぶ

日付：2026-11-20 / 状態：Proposed

## 背景

[ADR 0033](0033-record-status-acquisition-and-mode-evidence.md)で定めた検証モードでは、機械のみとスクリーンリーダー併用で標準の画面撮影を無効にしていた。機械検査を選んだ場合でも、修正担当者が画面の状態や操作を画像で確かめたい。新しい1ページ検査では、何を検査するかと、どこまで画像を保存するかを依頼時に選べるようにする。

## 決定

- `wcag-page` への直接の新規依頼では、目標レベル、検査モード、標準の撮影範囲のうち、指定されていない項目を一度に聞く。利用者が任せた項目にはAA・機械のみ・初期表示だけを使う。既存runの再開と報告、設定を引き継いだ子の作業は保存済みの設定を使う。
- 検査モードはAI・実スクリーンリーダーを使うかを決める。どのモードでも標準の撮影を `off`・`initial`・`states`・`all` から選べる。`initial` は操作前に表示されている領域を環境ごとに1枚保存する。`all` では自動探索で経路に追加した操作の前後を撮る。撮影範囲外・上限・撮影エラーは証拠が得られた扱いにしない。
- [ADR 0065](0065-publish-readable-audit-results.md)の閲覧用HTMLから、保存した画像を環境・表示状態・操作が分かるリンクで開けるようにする。標準画像の設定と保存枚数を報告する。明示したフォーカス枠や文字色の画素測定に必要な切り出しは、従来どおり個別の測定証拠に記録する。

## 代替案と影響

機械検査で画像を既定でオンにすると、既存のCLIや自動処理でも画像の保存量が増える。CLIのモード別既定は維持し、対話側で選択を受け付ける。CLIに質問を組み込む案では自動処理が入力待ちになるため、CLIは引き続き引数と設定ファイルを使う。撮影範囲や適合レベルを変更して再検査する場合は新しいrunに保存する。

画像があっても達成基準の判定は実施した検査から記録する。AI併用でも画像を必要とする観点は、必要な証拠が揃うまで未確認にする。既存の判定や画像はそのまま参照できる。以前の実装で中断した自動探索を再開する場合は、保存時と同じ実装を使う。

## 検証方法

4モードと4種類の撮影設定を単体試験で組み合わせる。ローカルページをChromiumで機械検査し、初期表示2枚の実寸、状態と操作前後の撮影、HTMLの画像リンク、設定済み状態の収集、再開時に設定変更を拒否して元の記録を保持することを確かめる。対話側は実ホストで未指定・一部指定・全指定・おまかせの依頼を試し、質問する項目と開始のタイミングを確かめる。
