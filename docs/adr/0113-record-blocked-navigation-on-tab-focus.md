# 0113 Tabでフォーカスした際の文書移動要求と遮断を記録する

状態は提案。

## 背景

URLだけを渡す通常の検査では、対象外への文書移動を遮断する。問題集の073では、最初のTabの後に遮断したURLとフォーカス取得のエラーが残った。どの要素にフォーカスし、文書移動がいつ始まったかは、その停止記録から追えなかった。[T020の測定](../../validation/development/T020/README.md)

## 決定

補助のTab観察中、ブラウザーが送ったTabとフォーカスを既存の入力ログに記録する。同じ文書・同じメインフレームで、フォーカスイベントの配信中にブラウザーが別文書への移動を通知し、同じTabの観察中に通信制限が同じ移動先の文書要求を遮断したとき、その対応を調べる。Tabを離した時点の文書とURLが変わらず、対応する移動通知の配信が終了し、その通知が取り消しや中断を受けていないことを確かめる。停止記録から四つのイベントと遮断をたどれる。配信中には、Chromiumでイベントの配信が続いている間に実行されたマイクロタスクも含まれる。

移動先を比較する際にハッシュを除く。文書内のハッシュ移動や、Tabを離した後・タイマー等による移動通知も補助観察中は入力ログに残す。同じTabに複数の移動要求があれば、どの要求が通信の遮断に対応するかは保留する。子フレームがある場合も、子フレームからの移動をトップのブラウザー通知だけで区別できないため、発生元の照合は保留する。

## 代替案と影響

Tab直後に同じ移動先の通信が遮断されたという時刻だけの照合では、先の要求を取り消し、キーアップで同じURLへ移動する例を区別できない。独立レビューでは、子フレームが起こした同じURLへの移動がトップの文書の通知に出ない例も確認した。制限を解除して移動先の画面を取得する案では、既存の探索範囲を越える。今回の記録には要求と遮断までを残し、移動先の表示と達成基準の判定は追加の確認に委ねる。

新しい項目は既存の停止記録への追加とし、保存済みの記録をそのまま読める。探索の実装が変わった場合は、従来どおり新しいrunを作る。

## 検証

通常のURL入口から既存の対照を両画面幅で試す。Enterで移動する例、タイマー、文書内のハッシュ、iframe、バックグラウンド通信、取り消しまたは文書内に切り替えた後にキーアップや別フレームから同じ移動先を要求する例を照合する。移動先への通信がサーバーに届かないことは受信記録で確認する。[T034の試験と証拠](../../validation/development/T034/README.md)
