# 0026 キーボード操作後の部品の状態を証拠付きで照合する

日付：2026-11-19 / 状態：Accepted

## 背景

コンボボックスでは、DOMのフォーカスが入力欄に留まる間も矢印キーで示す候補が変わる。タブやスイッチも、見える内容とDOM属性が別々に変化する場合がある。フォーカス・表示だけの条件では、キーを押して候補を選べたか、表示と属性の変化が対応するかを確認できなかった。[ADR 0024](0024-check-keyboard-path-outcomes.md)

## 決定

指定経路に矢印キー、ARIA属性の値、テキスト入力欄の現在値の照合を加える。属性の不在を期待する場合も、対象要素の存在を確認する。条件と異なる場合は、指定したキー、対象、期待値と実測値をJSON・HTML・Excelへ出す。4.1.2には属性条件を含む経路を使い、スクリーンリーダーでの通知は追加確認に残す。

通常探索のキーボード欄は、全手順が実キーの経路から作る。クリックやホバーから始めた経路は原始記録から確認できる。達成基準全体は検査票の判定として扱う。

同一オリジンの直接の子iframeを一つ宣言できるようにする。宣言した文書へのGETのみを経路内で許可し、実際に入力を受け取った文書と、操作後の条件を評価する文書を別々に照合する。書き込み、未宣言文書や別オリジンへの移動、所有文書を照合できない場合は保留する。

フォーカスだけでページが移動して補助的なTab観察が止まった場合は、停止理由と途中までの記録を残して帳票を出す。検査票に自動検出の問題がある場合は、HTML・Excelの問題一覧に移動できるリンクを付ける。

## 代替案と影響

すべてのコンボボックスやタブで同じキー操作・属性値を期待すると、操作方法が異なる正常な部品を誤って指摘する。既知の仕様を経路の条件として渡し、その条件の結果を報告する方法を維持する。既存の操作経路、判定、原始証拠は引き続き参照できる。新しく検査する際は新しいrunを使う。

## 検証方法

`python3 tests/widget_keyboard_browser.py --out <新しい出力先>`で候補移動、選択、EscapeとTabでの離脱、タブ、スイッチ、Shadow DOMの開閉状態をChromiumで検査する。差が出た経路は、同じ判定・対象・証拠をJSON・HTML・Excelで読めることを確かめる。既存のメニュー・ダイアログの経路も別runで再確認する。

`python3 tests/frame_keyboard_routes_browser.py --out <新しい出力先>`で、iframeから戻れない例、親へ戻って後続要素へ進める例、照合できない文書や書き込みの保留を確認する。`python3 tests/dynamic_focus_navigation_browser.py --out <新しい出力先>`では、フォーカスによる移動を止めても初期状態・途中のキー入力・停止理由から帳票を読めることを確認する。
