# 0009 確認観点ごとに分担と実行準備を説明する

日付：2026-11-16 / 状態：Proposed

## 背景

[ADR 0008](0008-all-criteria-verification-table.md)では、全86達成基準の分担を1基準1行の表にした。「自動」「追加」の表記は、プログラムが実行する処理と実行前の準備を混在させており、利用者が検査方法を読み取れなかった。属性の取得・操作・内容判断も同じ行に詰め込まれていた。

## 決定

全86基準を1つの表に載せる方針は維持し、検査方法や判断が異なる確認観点は行を分ける。各行には基準名・レベルを繰り返し記載し、別の行や凡例に戻らなくても対象が分かるようにする。基準名から個別の検査手順へのリンクも維持する。

列は、達成基準・レベル・確認すること・プログラムが行う処理と現在の限界・実行方法と必要な準備・任意のAI補助・人の確認や準備が必要な場合に分ける。「自動」「追加」「共通」などの省略に頼らず、標準コマンドで実行する処理、操作手順や道具を設定して行う検査、信頼できる方法が不足する部分を文で説明する。略語は意味が伝わる言葉へ置き換えるか、説明を添える。

画像の代替文の取得と意味の比較、字幕の表示と音声との内容比較、フォーカスの移動記録と開閉後の離脱確認などを分ける。人への引き継ぎ条件もその行の確認内容に合わせ、再生や取得だけの行で内容判断の専門家を一律に要求しない。設定・道具の準備は、利用可能な環境ではスキルを使うAIが進めることを説明する。

ADR 0007・0008の、機械検査を先に進め、必要な内容判断にAIを任意で使う方針は維持する。証拠取得と基準全体の適合を区別し、原典の選択可能な達成方法を表の行数によって必須化しない。

## 代替案

- 凡例の言い換えだけでは、同じ行に混在した処理・準備・判断を読み手が分ける必要が残る。
- 基準ごとに表を分けると、全基準の分担を1つの表で確認したいという利用者の希望を満たせない。
- 行を分けて基準名を省略すると、その行だけを読むときに対象が分かりにくい。

## 影響

表は長くなるが、確認観点から処理・準備・残る判断を確認できる。これは説明の改訂であり、コマンド・検査定義・適合条件・保存済み判定・原始証拠は変更しない。検査手順と方法の準備状況を詳細の原本とする。

## 検証方法

全86基準の順序・名称・レベル・手順リンクをカタログと照合する。同一基準の行は連続させ、確認観点の重複、空欄、省略語だけのセルがないことを確認する。標準処理・個別の準備・未実証の制約を既存の手順と照合し、観察と内容判断、人への引き継ぎ条件が対応するか確認する。表の列数・相対リンク・差分の空白を確認し、読みやすさと条件の保持を見直す。文書のみの変更のため、実行ロジックの試験と実ブラウザー検査は再実行しない。
