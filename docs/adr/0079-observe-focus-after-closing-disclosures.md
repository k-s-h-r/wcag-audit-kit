# 0079 展開した領域をEscapeで閉じた後のフォーカスを記録する

- 日付 2026-11-20
- 状態 Proposed

## 背景

[ADR 0078](0078-continue-keyboard-paths-after-duplicate-states.md)では、Enterで開いた後にTabでどこへ移ったかを記録した。メニューから離れられるかを確認するには、次の入力で閉じるかと、そのときのフォーカス先も観察する必要がある。

## 決定

キーで開いた部品からTabで移動し、フォーカスが `aria-controls` で指された一意の領域の中に入った場合、その後のEscapeを探索候補に加える。同じ経路を再生して領域が開いていることと、その中のフォーカスをもう一度確かめる。フォーカスを動かさず、実キーを送る。

同じ文書・領域での入力前後の表示、`aria-expanded`、実際のフォーカスを `transition.json` に記録する。閉じて開閉ボタンへ戻った場合は、その観点を確認済みとする。開いたままの場合や別の場所へ移った場合は、観察した内容を帳票に出し、適切な閉じ方やフォーカスの判断を保留する。

## 代替案と影響

開閉ボタンへ先にフォーカスを移してからEscapeを送ると、開いた領域の中にいる利用者が使える操作は確認できない。実Tabの後のフォーカスをそのまま使う。操作経路は従来の深さとステップ数の上限に従う。Enterを2回、Tab、Escapeと続く例は深さ4を使う。操作の途中で領域を特定できなくなった場合は未確認として残す。

## 検証方法

`python3 tests/keyboard_close_browser.py --out <新しい出力先>` を実行する。2.1.2の3階層メニューと、その一部を変えた対照を、ChromiumのPC幅・スマホ相当幅で調べる。閉じて開閉ボタンへ戻る場合、開いたままの場合、閉じた後に別の場所へ移る場合の操作記録と帳票を照合する。
