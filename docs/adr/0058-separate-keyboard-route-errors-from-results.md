# 0058 キーボード経路の実行エラーと確認結果を分ける

日付：2026-11-19 / 状態：Proposed

## 背景

自動探索のキーボード経路では、対象が複数一致してキーを送れないときも機械帳票に失敗を出していた。経路の途中で停止した場合も、最後の対象に失敗を付けていた。セレクターの生成を改善した後も、ライトDOMと公開Shadow DOMを含むページで複数一致を再現できた。[ADR 0057](0057-match-exploration-targets-to-dom-parents.md)

## 決定

実際にTabで探索して対象へ届かなかったときは、停止した手順番号を探索台帳と`transition.json`に保存する。最後の手順がその理由で止まった経路は「問題あり（機械）」とする。先行手順で止まった経路や、ブラウザーの操作・収集エラー、通信制限のある経路は「機械判定不能」とし、観察した原因を表示する。明示した操作経路の入力後に期待条件と違った場合は、その条件の結果を使う。

## 代替案と影響

すべての実行エラーを失敗とすると、実入力前の停止もサイトの問題として表示される。停止理由と手順を保存すれば、対象が見つからないケースと、実Tabで到達できないケースを追える。旧runの帳票を再出力するときは、従来のTab到達失敗メッセージと、初期表示および完了済み操作の待機記録から停止手順を確認できる場合に失敗を表示する。保存済みrunの証拠は読み取りに使い、新しい探索実装での収集は新しいrunで行う。

## 検証方法

`python3 tests/exploration_targets_browser.py --out <新しい出力先>`を実行する。セレクターが複数一致してキーが届かなかった例、実Tabで届かなかった例、Enterを送った後に期待する表示が確認できなかった例を比較する。HTML・JSON・Excelに対応する結果が出ることを確認する。`test_keyboard_report_scope.py`では経路途中の停止、旧runの再出力、通信・ブラウザーの制限、ポインターを含む経路の扱いを照合する。
