# 0004 人向けの達成基準チェックシート

日付：2026-11-15 / 状態：Proposed

## 背景

[0002](0002-tasks-and-excel.md)のExcelは、証拠付きの判定と担当情報を交換するため、ページ・状態・環境・基準ごとの検査票や対象を別シートにしている。[0003](0003-modular-skills-and-inspection-profiles.md)の報告スキルでも、その形式だけでは人が達成基準ごとの適否と修正箇所を探しにくい。日本でよく見るチェックシートの構成に合わせつつ、AI用の詳細と取り込み契約を保持する必要がある。

## 決定

JSON台帳を正本とし、共通の表示モデルからHTMLとExcelの人向けチェックシートを生成する。通常は現行86達成基準にそれぞれ集計行を作り、記録した対象の期待結果が異なれば確認観点の内訳を追加する。基準番号、名称、レベル、確認観点、適用、適合、不適合箇所、注記、残る確認、証拠を並べる。

確認観点は既存のtargets[].expectedを完全一致でまとめる。観点専用の新しい判定形式や、期待結果の推測による分類は追加しない。内訳の通過は記録した対象に限る。未記録の観点や検査手順の各操作を自動で適合にしない。

不適合を優先して表示し、未確認が併存する場合は残る確認を示す。未実施・判断保留・未網羅・収集や票の不足を基準全体の適合にしない。非適用と目標レベル外は分ける。公開チェックシートに見られる適用・適合の列を参考にするが、非適用を通過と混同させないため独立した表記を使う。サイト全体の範囲確認と検証完了は別に表示する。

人向けの「不適合箇所」には、不適合の全対象をURL・状態・環境・位置・観察・期待結果・再現手順・証拠と共に出す。チェックシートの長い一覧は件数付きの要約とし、全件への参照を示す。

Excelの先頭2シートをチェックシートと不適合箇所とし、report・workの両モードで閲覧用にする。既存のシート名・列・交換形式は変えず、人向け2シートの編集は取り込まない。HTMLでは同じチェックシートを主な表にし、個別検査票も詳細として保持する。report.jsonの判定形式は変えない。

Excelの人向け集計は既存の選択条件に従い、他ページの不適合を混ぜない。タスク・担当・未完了票の選択は、その票だけの集計であることを明示する。既存の概要・達成基準シートのrun全体の集計も保持する。

## 代替案

- 機械用の検査票をそのまま人向けにすると、1.1.1等の基準全体と複数の観点の関係が分かりにくい。
- 人向けシートから集計判定を直接取り込むと、対象・証拠・条件等が不足したまま適合を設定できてしまう。
- 新しい観点IDを必須にすると過去の判定の移行が必要になる。既存の期待結果を使い、意味が似た文言の統一は将来の明示的な設計課題に残す。
- 全箇所を1セルへ詰めるとExcelの制限と読みづらさが増す。全件の箇所一覧と、件数を明示する要約を組み合わせる。

## 影響

保存済み判定・定義・原始証拠は変更しない。古いrunも再出力できる。表示モデルは読取専用であり、既存の記録検査や更新競合の処理を変えない。workを編集・取り込みした後は、新しいファイルへ再出力して人向け表示を更新する。

期待結果の表記が異なれば別の観点行になる。内訳は確認済み対象の記録であり、すべての必要観点を自動で列挙する機能ではない。JIS準拠の公表用帳票としての認証・保証も追加しない。[参照形式と読み方](../../references/checksheet.md)に適用範囲を示す。

## 検証方法

複数の観点が適合・不適合に分かれる1.1.1、部分的な不適合と未確認の併存、非適用と未実施、欠けた収集・票、ページ・タスクの選択範囲、全不適合箇所の保持、HTMLのエスケープ、Excelの数式化防止と印刷設定を試験する。人向けシートの編集がwork取り込みで判定を変えないこと、既存の作業用Excelの往復と競合試験が通ることを確認する。保存済み2,200票を別ディレクトリーへコピーしてHTML・Excelを再生成し、元の判定件数・未確認と照合する。ブラウザーで表示を確認し、Excelはopenpyxlで生成・読取を検証する。Microsoft Excel/Excel Onlineの実操作は今回の検証に含めない。
