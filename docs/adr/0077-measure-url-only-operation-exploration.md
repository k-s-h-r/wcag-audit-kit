# 0077 URLだけで始める操作探索を問題集で測る

- 日付 2026-11-20
- 状態 Proposed

## 背景

問題集の一部では、評価したい入力や状態をあらかじめ指定して機械判定を測った。普段の `wcag-page` では、URLを受け取ったスキルが初期画面を検査し、そのまま簡易探索を始める。操作の見つけ方と差分再検査の改善に先立ち、どこまで到達して何を判定できるか測る。 [ADR 0069](0069-run-a-short-operation-sweep-automatically.md) · [ADR 0074](0074-score-bounded-browser-measurements.md)

## 決定

既存の8ページを公開用ディレクトリーから配信し、通常のCLIを別プロセスで実行する。初期画面を検査してから、簡易探索と通常探索を同じ上限でそれぞれ開始する。両方で既定の表示幅と機械モードを使う。操作手順、名前付きの状態、追加計測はCLIへ渡さない。収集に失敗した場合も、PC幅・スマホ相当幅それぞれの結果を収集失敗として残す。

照合は収集後に行う。問題例と正常例の両方について、必要な表示やキー入力の記録があるかを先に確かめる。実際に出力した機械判定を期待と比べる。ポインターで同じ表示にできた場合も、キーだけで到達したものとは区別する。3階層メニューとコンボボックスは、開いた状態を記録するところから測る。

## 代替案と影響

既存ベンチマークの指定手順付き実行は、既知の状態での検出能力の確認に使える。URLから操作を発見する工程も測るには、指定手順を渡さない実行が必要になる。今回の測定は決めた8ページと上限に対応する。上限を変えると見つかる経路が変わるため、結果を比べるときは両方の条件を揃える。

## 検証方法

`python3 benchmarks/url_only.py --out <新しい出力先>` を実行する。`result.json` で表示幅ごとの到達と判定を確認できる。コマンドログ、操作の証拠、ページ別の報告を同じ出力先に保存する。実測の結果と後続作業は [T017](../tasks/T017-url-only-exploration.md) を参照する。
