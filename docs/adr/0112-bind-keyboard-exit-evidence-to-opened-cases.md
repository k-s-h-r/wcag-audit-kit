# 0112 ダイアログの離脱証拠を開いた状態の検査票に表示する

状態はProposed。

## 背景

追加探索でダイアログの離脱を調べると、機械結果は操作経路番号で保存される。`page-next` が各検査票に表示する機械結果をキャプチャーIDで探すため、離脱を調べた開いた状態の検査票にその結果が出なかった。[T030の記録](../tasks/T030-dialog-keyboard-trap.md)

## 決定

簡易探索では、EnterまたはSpaceで開き、Escapeを送る直前に観察した状態の指紋を離脱証拠へ記録する。同じ文書・URL・ダイアログ・フォーカスで記録した指紋を、開くキーを単独で実行した後の観察と保存キャプチャーの両方に照合する。実入力と状態を示す証拠ファイルのハッシュを確認し、保存キャプチャーから一つのページ・表示状態・画面幅の検査票を特定する。

`page-next` は、選択中のモードで実施可能な未完了の検査票のうち、該当する2.1.2の検査票を優先して返す。根拠には操作経路番号と元の証拠のパスを含める。検査票の判定と適合の結論には従来どおり別の記録が必要になる。

## 代替案と影響

達成基準や操作対象だけで結び付けると、同じURLで開き直したダイアログの内容が変わった場合や、幅ごとに動作が異なる場合に誤った根拠を渡す。古いrunの操作結果は従来の集計と帳票から読める。操作直前の状態を記録していないrunで検査票への関連付けを確認するには、新しいrunで追加探索する。状態が複数候補に当たる場合や、保存した探索状態の指紋に追加の視覚構造情報が含まれる場合も、関連付けを保留する。

## 検証

初期表示だけを集めたrunで`page-next`を読み、案内された簡易探索を同じrunで開始する。離脱できる例と入力欄に留まる例で、それぞれPC幅とスマートフォン相当幅の検査票から元の操作証拠へ戻れるかを確認する。旧runと、再表示時に内容が変わる対照も照合する。[試験手順と証拠](../../validation/development/T033/README.md)
