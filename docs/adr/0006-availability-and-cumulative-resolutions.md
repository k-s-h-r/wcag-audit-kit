# 0006 操作可能性を含む状態識別と追加検査の累積

日付：2026-11-15 / 状態：Proposed

## 背景

[0005](0005-machine-first-page-workflow.md)の実装に対し、PR #5のレビューで2件の問題が見つかった。aria-disabledだけで操作可能になった部品は既存状態と同じと判断され、その先の探索が始まらない。また、同じ探索に対する追加検査を分割して保存すると、直前の解消項目だけが参照され、先の解消項目が未確認へ戻っていた。

## 決定

状態識別には内容・色等に加え、disabled、aria-disabled、readonly、inert、tabIndex、入力型、リンク先、ARIAの操作・状態・関係属性を含める。実際に操作候補となった部品の識別子・役割・入力型・名前・リンク先・イベント種別等も比較する。部品の座標やフォーカス位置だけでは別状態にせず、イベント種別は重複と登録順を正規化する。ページURLとタイトルの変化も保持する。ネイティブの操作可能性にはfieldset等の祖先から引き継いだdisabledも反映する。

追加検査は、同じgraph_digestの参照済み解消項目を検証して引き継ぎ、今回の項目と合成した新しいスナップショットへ保存する。同じ項目を再記録するときは新しい観察・証拠を採用し、他の項目を保持する。過去のスナップショットは変更せず、previous_reviewで参照元を残す。新規解消数と累計を別々に返す。

graph_digestが異なる場合は、以前の項目を引き継がない。既存証拠の検査と未実行キューによる完了の抑止は保持する。旧形式でresolutionsを省略した空の記録は、解消項目なしとして読み取る。

## 代替案

- aria-disabledだけを追加すると、イベント登録や他の操作属性だけが変わる分岐を引き続き見落とす。
- 操作候補全体をそのままハッシュ化すると、スクロール座標やイベントの登録順だけで別状態が増える。
- 追加検査のたびに利用者へ全解消項目の再送を求めると、分担・中断・再開時に項目を失いやすい。
- 過去のスナップショットを書き換えると、その時点の観察と証拠を追えなくなる。

## 影響

新しい状態識別は新しいrunで使う。過去の探索の指紋・判定・原始証拠を再計算しない。探索実装の版の照合により、更新前のrunを新しい実装で再開することは拒否する。過去の報告は当時の証拠から読み取れる。

追加検査の形式は単一の参照先を保持し、保存内容を累積スナップショットにする。古い有効な解消記録は引き続き読める。機械検査の結果とWCAG達成基準全体の判定の区別は変更しない。

## 検証方法

旧実装で状態衝突と解消項目の消失を再現する。実Chromiumでaria-disabledだけを解除し、新しく操作可能になったボタンの先の内容・axeの証拠まで取得する。候補の座標・イベント登録順だけが変わっても状態が増えないことを試験する。

解消項目をA、Bと分けて保存した場合の累積、Aだけの更新時のBの保持、旧スナップショットの不変、既存証拠の改変拒否、探索の版の変更時の失効、旧形式の空の記録との互換性を試験する。既存試験も実行し、保存済みの証拠は新しい確認記録と分けて保持する。
