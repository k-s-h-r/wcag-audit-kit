# 0119 初期表示で隣り合うネイティブボタンの寸法と間隔を測る

状態はProposed。

## 背景

URL起点の検査は2.5.8の対照を両画面幅で取得し、ボタンの矩形も保存していた。既存の指定検査は別の入口で矩形と当たり判定を取得できた。通常の帳票に、この結果を結び付ける処理がなかった。[T035](../tasks/T035-observe-adjacent-target-spacing.md)

## 決定

初期表示で、同じ親の下にあり、明示したCSS pxの寸法と実測が一致する二つのネイティブボタンを対象にする。ブラウザー内で矩形とその内側9点へのヒットを確認する。祖先に切り抜きがある場合、生成疑似要素や他の要素の被覆がある場合、追加の操作対象やシャドウDOMを検出した場合は、自動計測の範囲から除く。

指定検査で使っている矩形の取得と、中心の円が隣接対象または小型対象の円と重なるかの計算を共用する。帳票では対象・幅・初期表示にひも付けて、2.5.8の寸法・間隔の機械結果と元の証拠を表示する。採点は対象と幅が一致する帳票行を、初期表示の証拠とハッシュに照合する。他の例外の判断と達成基準全体の判定には、検査票の追加確認が必要になる。

## 代替案と影響

配布axe 4.11.0の `target-size` は既定で無効。明示して実行すると代表的な問題例と正常例は区別できた。今回の23.984375 CSS pxの中心間距離と、対象の一部を覆う試験では、採用する測定範囲を同じように区別できなかった。矩形だけで判断すると、クリッピングや擬似要素による当たり範囲の変化も拾えない。今回の自動計測は、限られた静的条件と観察できた点に基づく。

## 検証

既存対照と、中心間距離が24 CSS pxおよびその直前の対照を両幅で調べる。文中リンク、矩形の内側を覆う要素、親による切り抜き、疑似要素、追加の操作対象を使い、測定対象に含めるかを確認する。旧runは同じ採点器で読み直す。[再実行と結果](../../validation/development/T035/README.md)
