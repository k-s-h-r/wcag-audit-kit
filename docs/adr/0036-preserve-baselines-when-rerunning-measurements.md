# ADR 0036：基準値の再実行先を収集前に拒否する

日付：2026-11-18。状態：提案。対象：T002・T003のレビュー対応。

## 背景

旧measure.pyは保存された実行原文だが、記録先を固定しexist_ok=Trueで作る。新しいworktreeでrun出力がなくても、保存済み記録を上書きする危険がある。またADR 0024等の説明にstrict終了値の誤記があった。

## 決定

旧ソースは変更せず実行時の記録として保持する。再実行用の入口をmeasure-baseline-v2.pyへ置き、--recordsと--artifactsを必須にする。両方を収集・import・ディレクトリー作成前に検査し、どちらかが存在すれば拒否する。現在の再現手順はvalidation/development/README.mdを入口とし、旧固定先スクリプトの再実行を禁止する。

## 代替案と影響

保存済みの実行原文を直接変更すると旧チェックサムと再現性を失うため採用しない。新しい入口もT001の実装・問題集・環境を検証するので、変更後の実装を基準値へ混ぜない。

ADR 0024とT002の旧説明の「strict 2」は誤記。保存された2つのreceiptとruns.jsonは0で正しい。タイトルの選択3行は完了だが全体はincomplete。原始証拠や旧ADRは書き換えず、新しい文書から訂正する。

## 検証

既存T002/T003記録先＋未使用run先、未使用記録先＋既存run先の4組を実行し、終了2、収集未開始、出力未作成と旧記録のハッシュ不変を確認した。初回の試験ドライバー自身の一時ディレクトリー指定失敗も記録し、測定の失敗とは区別する。
