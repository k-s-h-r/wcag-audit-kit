# 0070 計測通信とキーボード操作の結果を別に扱う

日付：2026-11-20 / 状態：Proposed

## 背景

1ページの簡易探索で、初期読み込み時のGoogle AnalyticsとCloudflareの計測通信を遮断した。目次を開けた場合も、自動判定は遮断記録のあるEnter入力をすべて保留にした。[ADR 0058](0058-separate-keyboard-route-errors-from-results.md)の入力結果の扱いを、操作を照合できる範囲で補う。

## 決定

- 通信の遮断処理を継続し、記録に計測通信かどうかを付ける。既知のGoogle Analyticsの送信先と同一オリジンのCloudflare RUMに対する、ページ移動を伴わないPOSTだけを計測と識別する。
- 遮断が計測通信だけの場合でも、対象に届いた実キーボードイベントと、同じ文書・要素における操作前後の状態変化を照合できた場合に限り、自動探索の実入力を通過として記録する。機能の送信やページ移動に関わる通信、状態変化が確かめられない操作、ブラウザーの分岐は保留にする。
- 記録する状態は開閉、展開、押下、チェック、選択を対象にする。操作の記録から2.1.1全体の判定は確定しない。旧runは当時の記録のまま扱う。

## 代替案と影響

遮断したPOSTを一律に無関係とみなすと、保存や送信を試した場合にも見かけの表示だけで通過させるため、送信先・用途を絞る。反対に遮断だけで結果を保留にすると、初期表示から発生する計測通信の影響が全操作へ及ぶ。送信先を限定し、実入力と状態変化の両方を必要とする。ログでは計測通信が送信されずに遮断されたことも確認できる。

## 検証方法

ローカルのChromiumで、画面読み込みとEnter時に計測を送る例、Enterを受けても状態が変わらない例、機能の送信も要求する例を比較する。実キーとDOMの照合、帳票の操作結果、POSTが一件もサーバーに届かないことを確認する。未分類の送信先、旧runの判定、合成イベントや対象外のキー入力は単体試験で確認する。
