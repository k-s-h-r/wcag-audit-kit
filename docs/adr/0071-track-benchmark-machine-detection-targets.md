# 0071 問題集の機械検出対象を観点ごとに採点する

日付：2026-11-20 / 状態：Proposed

## 背景

問題集には、同じ基準でも機械で確定できる観点、内容判断が要る観点、実スクリーンリーダーが要る観点がある。全問題の未検出数にはモードで保留した観点も含まれる。機械モードの改善を進めるには、検出すべき間違いと対照例を選び、同じ条件で回帰を測れる必要がある。

## 決定

- 既存の `evidence_kind` と `modes.machine` から検査手段を表示する。機械検出対象は `program` と `evaluate` がそろう81行とする。判定を保留する機械観点、意味・見た目の判断、複数ページの比較、実スクリーンリーダーも `inventory --expectations` と採点帳票で確認できる。
- `collect --machine-targets` は該当するケースを機械モードで収集する。検査担当へ渡す公開タスクの記録形式は維持する。通常の採点に加え、自動収集から確定した結果で、問題・正常・対象外の対照例と正解にない追加の指摘を `--strict-machine-targets` で確認する。
- 3.1.1のページ言語指定の有無は本番のaxe結果を採点に接続する。1.4.3の指定済み静的文字には、機械モードでも `--text-paint` の証拠を使用できるようにする。[ADR 0035](0035-grade-opt-in-text-paint-evidence.md)で定めた画像の上限と証拠の検証を引き継ぐ。1.4.6は同じaxe証拠のうち、影なしの文字・背景を測れた場合に限り、通常7:1、拡大文字4.5:1と比較する。

## 代替案と影響

検出可否を別の列として各ケースに手入力すると、証拠の種類やモードの条件との不一致が生じる。既存のフラグから算出することで、問題集の版を変えずに集計と回帰試験を追加できる。機械判定の未確認・不一致は、その検査手順または既存の測定結果を採点に結びつける次の作業の候補になる。機械モードで保留中の観点は、条件を確かめたうえで対象に加えられる。

## 検証方法

[問題集READMEのコマンド](../../benchmarks/README.md#間違いごとに必要な検査手段を確認する)で、現在の機械検出対象を収集して採点する。Chromiumでページ言語と文字コントラストの問題・正常例が一致することを確認する。単体試験ではフラグによるケース選択、未確認や正解にない追加指摘の扱い、取り込んだ判定と機械採点の独立、測定証拠の条件を確認する。
