# 0069 初期結果に続けて主要な操作を自動で探索する

日付：2026-11-20 / 状態：Proposed

## 背景

[ADR 0068](0068-defer-single-page-operation-exploration.md)では、初期画面を先に報告してから操作探索を別の依頼で開始した。利用者は1回の依頼で両方の結果を受け取りたい。実測した探索では、状態が変わるたびに無関係な操作も組み合わせ、未実行の経路が21,047件まで増えた。

## 決定

- 直接の `wcag-page` は初期画面の結果を途中で共有し、同じrunで `--resume --quick-explore` を続けて実行する。利用者が初期画面だけを明示した場合は、初期結果で終了する。初期証拠を保持し、最終結果は同じ帳票に反映する。
- 簡易探索はPC幅とスマホ相当幅の両方を優先する。開閉が分かる部品と、その操作で新しく現れた部品を先に試す。閉じた入れ子の内容のように実際に描画されていない要素は、表示されるまで候補から外す。
- 操作前後で変化した部品、新しく現れた部品、操作した部品を中心に次の経路を作る。単に位置がずれた部品同士の組み合わせは省く。追加する入力の種類も根拠のある候補に絞る。
- 既定は累計24ステップ・16状態・深さ3。環境ごとの通常の保留経路は12件まで。上限や絞り込みによる省略は未確認として、件数と理由をJSONに、概要を帳票に記録する。

## 代替案と影響

全経路を先に作って実行件数だけを制限すると、同じ部品の組み合わせが大量に残り、展開して初めて現れる部品に時間を割きにくい。簡易探索は経路を作る段階から絞るため、別の部品の操作結果に依存する挙動や、候補外の入力は個別の確認が必要になる。詳細な自動探索を依頼された場合は初期収集後に `--resume --explore` で開始できる。

## 検証方法

ローカルのChromiumで、先に40個のボタンが並ぶページから、その後ろにある入れ子の目次を両幅で探索する。閉じた目次内の部品を最初から試さず、開いた後に現れる部品と指摘を同じ帳票に追加できることを確認する。候補の上限と省略数を読み戻し、通常の探索、既存の入れ子の操作、画像と対象の回帰試験も実行する。
