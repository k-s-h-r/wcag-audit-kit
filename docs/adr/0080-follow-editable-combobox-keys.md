# 0080 入力欄のコンボボックスで候補の展開・選択・取消を追う

- 日付 2026-11-20
- 状態 Proposed

## 背景

[T017](../tasks/T017-url-only-exploration.md)では、コンボボックスが入力欄として実装されている場合に、入力・クリックは試したものの、候補を開くArrowDownを送っていなかった。候補が実際に表示されても、展開状態を支援技術に伝えない問題例がある。

## 決定

`role="combobox"` の入力欄を新しく発見したら、実Tabで到達してArrowDownを送る。単一の `aria-controls` で指されたリストボックスが表示範囲に現れたら、`aria-expanded` と表示が一致するかを検査する。候補が表示されるまでの経路と、実キーが入力欄へ届いた証拠を保存する。 [WAI-ARIA APGのコンボボックス](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)

同じ欄にフォーカスを保ち、同じ候補一覧を再現できた場合に、ArrowDownで次へ進む、Enterで選ぶ、Escapeで閉じる経路を試す。次へ進んだ候補でもEnterを試す。入力前後の表示、`aria-activedescendant` の参照先、フォーカス、入力値が変わったかを記録する。選択や取消の適否は、この観察をもとに部品の目的に応じて確認する。

## 代替案と影響

すべてのテキスト入力欄へ矢印キー・Enter・Escapeを送ると、既知の候補と関係ない操作が増える。コンボボックスの役割と一意に照合できる候補一覧を根拠に、キーを追加する。候補を確認できない場合や、別の要素へフォーカスが移る場合は、経路の後半を推定で通過にしない。

## 検証方法

`python3 tests/keyboard_combobox_browser.py --out <新しい出力先>` を実行する。4.1.2の正常例と、候補は見えるが展開状態が更新されない問題例をChromiumの両幅で比較する。操作の記録には入力欄へ届いた実キーを残し、選択後の値の変化と、取消後に値が保たれたことを確認する。 `benchmarks/url_only.py` では、到達した経路に対応する帳票の判定を照合する。
