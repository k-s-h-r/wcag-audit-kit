# 0040 実スクリーンリーダー検査で既存のOrcaを維持する

日付：2026-11-19 / 状態：Accepted

## 背景

ネイティブ検査は専用のXvfbとD-Busを用意する。同じアカウントで試行を並行させると、Orcaの強制置換が他方のプロセスを止めようとした。強制置換はXvfbやD-Busの違いを区別せず、利用中のOrcaに影響し得る。

## 決定

ネイティブOrca起動時の `--replace` を外す。起動直後の終了は収集できなかった結果として返し、起動ログを残す。実行時の掃除は従来どおり、この試行が起動したプロセスを対象とする。

## 代替案と影響

強制置換を続ける方法も、専用画面だけで隔離する方法も、同じOSアカウントの既存Orcaを維持できない。変更後は同じアカウントで別のOrcaが起動中なら、試行を中断する。実Orcaの複数試行は専用アカウントを使うか、そのアカウントで順に実行する。

## 検証方法

`python3 -m unittest discover -s tests -p 'test_native_orca*.py'` で起動引数と失敗時の記録を確認する。実Orcaの別プロセスを模した試行では、起動拒否が `orca.stdout` に残り、先行プロセスは動作を維持した。専用環境で保存通知のp03・p04を順に実行し、p04で通知の発話を確認した。最初に空の通知だけを持つ元のp01・p02は発話を確定できず、採点は保留した。
