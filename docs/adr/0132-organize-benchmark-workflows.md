# 0132 ベンチマークの実装を用途ごとに配置する

状態はProposed。

## 背景

`benchmarks/` の直下に実行コマンド、採点と帳票、個別計測が並んでいる。READMEでも8ページの探索比較が76ページのURL起点の採点より先に出てくるため、いま使うコマンドが分かりにくい。実装ファイルのパスと内容は保存済みrunの再開判定に使われ、採点器のハッシュは過去の採点JSONとの比較に使われる。

## 決定

READMEの冒頭に、URLだけで始める一括採点と、操作条件を指定した回帰試験のコマンドを載せる。8ページの探索比較はT017の再現手順からたどれるようにする。実装は `suite/`、`url_runs/`、`measurements/` に置く。コマンドのパス、保存済みの検証スクリプトが使う参照先、問題集の公開ページと正解の配置を保つ。

再開時は配置と内容を含む実装ハッシュを照合する。配置変更前の `af58822` と `1a7d387` については、変更後の実装が登録済みのハッシュと一致した場合に限り再開できる。旧版と同じ採点器のハッシュは、移動直後の採点器と依存ファイルのハッシュがそろった場合に使う。照合の対応表は新規runの実装スナップショットに保存する。実行環境、対象、設定、証拠の検証にも従来の条件を適用する。

## 代替案と影響

READMEだけを直す案では、採点、帳票、計測のコードを探す手間が残る。ファイルのパスをハッシュの対象から一律に外す案では、意図していない配置や実装の変更も再開時に区別しにくくなる。今回の移動を照合できる版を記録することで、保存済みのrunと採点JSONをそのまま利用できる。

## 検証方法

移動前のコードで完了と中断のrunを作成し、移動後に既存コマンドで未完了分を収集する。完了済みと中断時の証拠のハッシュを照合し、操作条件付きの `result.json` とURL起点の `score.json` をそれぞれ旧版の結果と比較する。実装を変更した対照では旧版のrunを拒否し、採点器のハッシュが切り替わることを試験する。
