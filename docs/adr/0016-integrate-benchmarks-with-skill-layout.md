# 0016 最新mainのテスト基盤をスキル配置へ対応させる

日付：2026-11-17 / 状態：Proposed

## 背景

PR #9のスキル単独配置の変更後、mainにPR #7のテスト入力・採点基盤が入った。Gitの競合はADR一覧だけだが、新しい採点基盤は移動前のルートscripts・references・vendor・SKILL.mdを参照している。そのままではCLIの起動と実装スナップショットの作成ができない。ADRの0011も両ブランチで使われていた。

## 決定

mainをPR #9のブランチへマージし、両方の変更を保持する。mainへPR #9をマージする作業は今回の対象に含めない。

採点基盤の実行コード・資料・axe・実SRアダプターの参照先を、編集元のskills/wcag-audit-kitへそろえる。実装のスナップショットには、共通リソース一覧を使って編集元のコード・資料・テンプレート・vendor・依存定義を含め、4つのSKILL.mdと開発用コードも保存する。配置先3スキルの共通部分は既存の同期確認で一致を検査する。

テスト問題集と入力の期待結果、保存済みのrun・証拠・検査定義は変更しない。実行中の旧runは当時のスナップショットを保持し、新しい配置での収集は別runに記録する。実装の識別値が変わるため、旧runを新しい実装で再開しない。

mainで確定済みのADR 0011〜0014は保持する。PR #9で提案中だった配置方式のADRは、本文の判断を変えず[0015](0015-ready-to-use-skill-directories.md)へ改番する。この統合作業を0016として別に記録する。

## 代替案

ADR一覧の競合だけ解消すると、コードの移動をGitが競合として扱わなかった参照先が壊れたままになる。ルートへ旧コードを戻す方法は編集元が増え、単独配置の方式と整合しない。採点基盤を各スキルへ複製する方法は、利用時に不要な開発用入力と正解まで配布するため採用しない。

## 影響

コピーして利用する4スキルの構成を維持したまま、リポジトリから採点基盤を実行できる。スナップショットのパスは配置変更に追従する。通常のWCAG判定・探索アルゴリズムや、取得期待を未確認として扱う仕様は変えない。保存済みの証拠は当時の配置のまま維持する。

## 検証方法

新規プロセスからのCLI起動と、編集元の全リソースをスナップショットへ含めることを回帰試験にする。全Python試験、JavaScript試験、4スキルの同期、資料リンク、テスト入力の索引を確認する。新しいrunで採点基盤を実ブラウザー収集し、実装の保存・未確認時の終了状態・HTMLとExcelの出力を確認する。スキル単独コピーの試験を行い、mainとPR #9それぞれの保存済み証拠のハッシュを照合する。

実施結果は[最新mainとの統合確認](../../validation/skill-layout-main-integration/README.md)へ保存した。
