# 0124 開いた子ダイアログのEscapeを既定の探索に収める

状態はProposed。

## 背景

通常の24手では、親と子をクリックで開いた後のEscapeが待ち行列に残り、64手では45・46手目に実行された。開いた子を観察した時点で先に調べると、既定の手数ですぐ後に続く別の操作が上限から押し出される。過去にも、一層のダイアログで閉じるボタンと次のTabが探索上限から外れた。[T040](../tasks/T040-prioritize-nested-escape.md) · [従来の調整](0115-limit-modal-exit-priority-to-input-dialogs.md)

## 決定

同じ主文書で親をクリックで開き、その内側に非表示の子ダイアログを一つ確認できた場合を扱う。親の中でフォーカス済みの空のテキスト入力欄について、既知のポインター処理を確認する。入力欄・祖先・文書のクリック系処理と、主文書でポインターが移動するときに発火する処理を検出した場合は、元の順序を使う。

条件を満たすときは、その入力欄への既存クリック候補を各幅で1件ずつ後へ回す。同じ経路から実際に子が開き、親子と子内のフォーカスが確認できた時点で、待ち行列に入った同じ経路のEscapeを前へ移す。後回しにした候補が待ち行列に残る場合に、各幅で一度だけ適用する。結果の証拠は、再生時のT038の実入力と開閉の観察から得る。

## 代替案と影響

原本による比較では、親の背景をクリックするとフォーカスが本文に移った。同じ入力欄をクリックしたときは、観測した表示・フォーカス・操作部品が一致した。後者を後へ回すことで、子をEnterで開く候補と、親の閉じる操作の後にTabを送る候補を既定の手順内に残す。研究用の64手と同じ調査量が必要な場合は、個別に上限を指定する。
