# 0126 移動先の表示が残ったフォーカス操作を追試する

## 背景

T009は、対象を指定した問題集の試験でフォーカス直後の文書移動を区別した。T034では、普通のURLから始める探索で、フォーカス時の移動要求と制限による遮断が同じ原始記録に残るようにした。T042は、帳票の作成中に残った移動先の表示を確認し、元の検査票に証拠を結ぶ流れを確かめる。[T009](../tasks/T009-machine-gap.md) · [T034のPR #104](https://github.com/k-s-h-r/wcag-audit-kit/pull/104) · [VISION](../VISION.md#機械とaiに任せたいこと)

## 決定

通常の `page-audit` と `page-next` から、移動先の表示を確認できなかった観察を探す。`pending` と `case` で、同じ始点URL、初期状態、画面幅の検査票を取得する。フォーカス先と移動要求を読み、専用のChromiumで最初のTabを1回だけ試す。許容範囲は、ループバックの同じポートの始点と、事前に固定した移動先への主文書のGET。画面・文書・フォーカス・実入力・HTTP受信をそろえる。

検査票へ `attach` と `record` で根拠を登録する。移動先の表示を確認できた観察は、元の `graph_digest` と同じ行を指定して `resolve-exploration` で解消する。追加証拠の取得、達成基準の判定、探索残件の解消をそれぞれの既存コマンドで行える。

## 代替案

専用の問題集測定は、指定した対象の回帰確認に向いている。今回は先に帳票と実際の残件を確かめ、それが指す観察を追試した。通常探索の範囲には既存のガードを適用した。

## 影響

この手順は固定した2ページの初期状態と2画面幅を対象とする。既存の検査票と探索の版が一致する場合に追加記録を使う。任意のページや到達先の追加には、対象と許容範囲の確認が必要になる。基準の残りの対象とほかの操作は、検査票と探索の残件で扱う。

## 検証方法

073で主文書GETの受信と別文書への移動が生じたこと、074で同じ文書と入力欄のフォーカスが保たれたことを原本から照合する。帳票の結論、元の検査票ID、残件、添付、保存された探索のハッシュを追試前後で比べる。[実行と原本](../../validation/development/T042/README.md)
