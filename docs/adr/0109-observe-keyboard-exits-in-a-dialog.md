# 0109 ダイアログからの離脱をキー入力とフォーカスで照合する

状態：Proposed

## 背景

通常の探索は、開いたダイアログと閉じた後のフォーカスを記録していた。統合版の正常例と問題例ではキーボードで開いた証拠があり、離脱の2.1.2の判定は両方とも未確認だった。[T030](../tasks/T030-dialog-keyboard-trap.md)

## 決定

クリックでダイアログを発見したときは、通常の候補にある同じ対象へのEnterを優先する。キーで実際に開いた経路も、同じ表示を先に記録していてもEscapeまで追う。離脱は、同じ文書でダイアログが閉じ、実際のフォーカスが外へ移ることで確かめる。

追加のキーを調べるのは、入力欄にフォーカスがあり、補助操作を照合できる単純な表示に限る。試した向きとキーで同じ入力欄に留まったあと、閉じるボタンのマウス操作で離脱したとき、その観察を機械の指摘候補に出す。フォーカス先や表示が変わった場合は追加調査を残す。

## 代替案と影響

Escapeだけの試験で分かるのは、その入力で離脱できたかどうか。順方向と逆方向の移動、ほかの標準キーとポインターを照合すると、入力欄に留まる経路を説明できる。案内がある例はほかの離脱手段の確認を残す。追加操作が始まる前の状態を帳票のキャプチャーに使う。

## 検証

通常のCLIで、既存の正常例と問題例をPC幅とスマートフォン相当幅で比較する。別のキーや操作順で離脱できる例は、別担当が誤検出を確かめる。採点では帳票に出た結果を実入力の記録と照合する。[再実行と証拠](../../validation/development/T030/README.md)
