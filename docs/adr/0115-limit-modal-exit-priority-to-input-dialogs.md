# 0115 入力欄のあるダイアログに離脱経路の優先を絞る

状態：Proposed

## 背景

[ADR 0109](0109-observe-keyboard-exits-in-a-dialog.md)で、キーボードによるダイアログの開閉を探索の早い段階で試すようにした。76ページの再測定では2.1.2の対照2例を区別できた。その一方、閉じるボタンに最初からフォーカスがある2ページでは、新しいEscape経路が先に試され、閉じるボタンをEnterで押した直後のフォーカスを調べる従来の経路が探索上限に達した。[変更前の再測定](../../validation/development/T030/run-002/score.json)

## 決定

探索順を変えるのは、フォーカスがテキスト入力欄にあり、観察した操作部品がその入力欄と閉じるボタンの二つである場合に限る。探索順を決めた時点の形と別に、Escapeの実入力と離脱の判断に必要な状態は、キー操作を再生したときに確認する。

## 影響と検証

探索上限を増やす方法では、必要な経路を調べるまでの時間と問題集の採点条件が変わる。既存の24ステップで離脱の証拠と閉じるボタンの証拠を確認する。

通常の探索上限で、入力欄の2例とボタンにフォーカスする2例の操作証拠を照合する。固定した76ページ・87行を再測定し、判定と問題集の採点行に対応しなかった指摘を比較する。[再実行と比較](../../validation/development/T030/README.md)
