# 0122 入れ子のダイアログの開閉を実Escapeの観察に残す

状態は提案。

## 背景

T036の通常24ステップでは、子を開いた後のEscapeは実行を待っていた。[ADR 0120](0120-observe-nested-dialog-exits-by-layer.md)に基づき、通常CLIのステップ上限だけを64に広げると、両対照の両画面幅で実Escapeが届いた。045では親子が表示されたまま、046では子が閉じて親にフォーカスが移った。既存の一層の観察では、いずれも閉じる前のモーダルを一つに特定できない結果になった。[測定](../../validation/development/T038/README.md)

## 決定

通常探索が既に実行するEscapeを対象にする。入力直前に、同じ主文書に表示されている一意の親と子をDOMの包含関係で特定し、子の中のフォーカス先に実入力が届いたことを入力ログと照合する。入力後も同じ親が表示され、同じ子が閉じてフォーカスが外へ移った場合に、閉じた子を記録する。子が表示されたままの場合は、表示が続いた観察を記録する。入力後のフォーカス先と属する層は個別の項目にする。

親も閉じる、子を別要素に置き換える、別のダイアログが現れる、文書が変わる、または操作が中断する場合は対象となる開閉の観察を保留する。古い記録に追加の観察がなければ、従来の帳票を生成する。

## 代替案と影響

既存の一層の離脱条件を緩めて適否を出すと、親子の開閉と復帰先の適切さが一つの判定に混ざる。追加の原本と、既存の帳票の操作調査に分けて観察を出す。通常24ステップの探索順、2.1.2と2.4.3の判断、既存の一層の機械検査は、それぞれの根拠を使う。

## 検証

公式の045・046を通常CLIで両幅測り、Escapeのブラウザー入力、前後の開閉、フォーカス先、JSON・HTML・Excelの証拠リンクを照合する。親子同時の閉鎖、同じIDでの子の置き換え、別のダイアログが現れる場合と、親子関係のないダイアログを対照にする。T030の039・040は通常24ステップで比較する。[再実行と証拠](../../validation/development/T038/README.md)
