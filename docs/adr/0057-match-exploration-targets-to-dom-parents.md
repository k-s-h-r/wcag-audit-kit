# 0057 探索対象をDOMの親子関係で特定する

日付：2026-11-19 / 状態：Accepted

## 背景

T014の4ページで、本文へ移動するリンクの自動生成セレクターがナビゲーションやフッターのリンクにも一致した。EnterとSpaceの試行は対象にキーを送る前に止まり、帳票では失敗になった。また、スキップ先の `main[tabindex="-1"]` にも直接Tabで到達する操作が作られ、失敗として記録された。

## 決定

自動生成するセレクターは、同じDOMツリー内の直接の親子を `>` で結ぶ。開いたShadow DOMのホストと内部のツリーの間は、Playwrightが探索できる子孫の関係を使う。負の `tabIndex` を持つ要素は、ネイティブ操作要素、対応するARIAロール、イベント、ポインターのいずれかの手掛かりがある場合に操作候補にする。スキップ先の本文は、そのDOMとフォーカス先の記録で追える。

## 代替案と影響

複数一致したセレクターから最初の1件を選ぶ方法では、観察した要素と操作する要素を対応付けられない。今回の変更は、探索時に観察した親子関係を使う。否定的な観察も、実行した操作とともに残す。以前の探索結果から作り直す場合は、新しいrunで収集する。

## 検証方法

`python3 tests/exploration_targets_browser.py --out <新しい出力先>` でChromiumを使う。DOM階層の異なるリンクを置いてスキップリンクへ実キーを送り、フォーカスが本文へ移ることを確認する。公開Shadow DOMでも、内側の階層が異なる二つのボタンを区別して実キーで操作する。負の `tabIndex` だけの要素、独立した操作の手掛かりがある要素、通常のTab停止位置、実際にTabで届かない操作候補の帳票を照合する。
