# 0098 起点URLから予約手続きの検査を試す

状態：Proposed

## 背景

T020では単独ページの機械検査を測った。操作の結果によって次の画面への進み方が変わる手続きで、何を見つけて帳票に記録できるかを確かめる。

## 決定

ローカルの予約確認に正常例と問題例を用意する。両方の公開サイトを同じ条件で検査し、採点側が期待する操作結果を保管する。機械結果を先に保存し、別のCodex文脈で画面と操作結果、アクセシブルな名前を確認する。

手続きの到達、個別の観点、対象範囲の結論を記録する。機械と追加検査で同じ6項目を照合し、問題の再現手順と証拠を既存の検査票・不適合箇所一覧に出す。

## 代替案

事前に操作を指定する検査は、同じ経路の回帰を測る場合に使う。今回は検査担当が公開画面から操作を見つける範囲を測るため、採点側で期待を管理する。発話の適否を評価する試験は、正常対照で動作を確認した実スクリーンリーダーを使う。この手続きでは画面の表示と公開されたアクセシブルな名前を比較する。

## 影響と検証

予約確認までの限定した試験で、機械から追加検査への引き継ぎを確かめる。確定した不適合と残る確認を両方の成果物で追えるようにし、操作記録をT023へ渡す。[試験条件と結果](../../validation/development/T022/README.md)
