# 0030 短い非同期更新を上限と残作業付きで観察する

日付：2026-11-18 / 状態：Proposed

## 背景

T009の実測では操作できても300ms後の画像が状態・axeへ入らなかった。固定100ms待機では取得段階の見落としが残る。

## 決定

DOM変化と関数形式のタイマーの実行・取消を観察する。150msの静かな期間と1500msの上限を使い、窓の外の予定、文字列コールバック、継続中の処理は未確認として記録する。ケースIDや正解を待機条件に使わない。intervalやネットワーク等の完了は保証しない。

## 代替案

300msだけ待つ対処は既知fixtureの時間に依存する。無限待機や、静かなDOMを全将来状態の完了とする方法も採用しない。

## 影響

短い遅延画像の状態・axeを取得できる。待機の理由と限界が証拠へ残る。呼び出しの引数・this・取消を保持する。採点への状態対応はT018へ分け、未確認の2行を通過にしない。

## 検証方法

旧実装の650ms画像の未取得を再現し、300ms・650msで取得、3000msと再帰タイマーで上限を確認した。ネイティブの引数・this・取消、文字列タイマーの未観測を実ブラウザーで確認した。208単体試験と元入力の新規runを保存した。[T017](../../validation/development/T017/README.md)を参照。
