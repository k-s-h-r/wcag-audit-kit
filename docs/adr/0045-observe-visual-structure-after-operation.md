# 0045 操作後の表示から見出しとリストの候補を記録する

日付：2026-11-19 / 状態：Accepted

## 背景

見出し・リスト候補の収集は初期表示に限っていた。アコーディオンを開いて現れた段落は、状態と要素が収集されても候補が記録されなかった。

## 決定

領域の指定とともに `visual_structure_states: explored` を選ぶと、初期表示と既存の探索が新たに保存する通常の操作状態を観察する。既定の `initial` は初期表示を観察する。表示の更新が収まらなかった場合などは、観察できなかった理由を証拠に記録する。

候補の証拠は観察時のページ、環境、状態、操作に結び付ける。JSON・HTML・Excelと後続の検査票から同じ証拠を参照できる。候補を確認した後の判定は、従来の検査票に記録する。

## 代替案と影響

毎回の操作直後に調べると、同じ状態の繰り返しや予算外の観察が増える。既存の状態の重複判定と探索上限を使い、保存した状態だけを対象にする。新しい状態に分かれない描画の変化、子階層、表示範囲外は別の観察が必要になる。有効化すると、保存した状態ごとに上限5秒の観察が加わる。

## 検証方法

`python3 tests/visual_structure_probe_browser.py --out <新しい保存先>` を実行する。Chromiumで実クリック後の見出し候補と中黒リスト候補が各1件出た。ARIAで見出しが伝わる対照は候補から外れた。指定なし、既定の初期表示、探索上限1状態も比較し、画像を省略した機械モードで1.3.1の未実施を保持した。
