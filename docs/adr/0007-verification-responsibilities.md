# 0007 検証をプログラム・AI・人で分担する目安をREADMEに置く

日付：2026-11-16 / 状態：Proposed

## 背景

検証方法はreferences/methods.md、方法の制約はmethod-capabilities.json、基準別の実証記録はVERIFICATION-COVERAGE.md、人への引き継ぎ条件はhuman-review.mdに分かれている。利用者がプログラムで実行できる部分、AIの補助が使える判断、人が必要になる条件を把握できる一覧がREADMEになかった。

## 決定

READMEに、確認観点と関連する達成基準の例を付けた分担表を置く。プログラムの表ではpage-auditの自動実行と追加ツール・シナリオを区別する。AIの表では内容判断の補助を示し、AIの利用を必須にしない。人の表では現在の実装・実証環境で不足する条件と、必要な担当・専門環境を示す。

分類単位は達成基準の中の確認観点とする。同じ基準でも、機械的な有無や数値、意味の比較、専門判断を分担できる。表中の番号は例とし、基準全体の自動検証や、全86基準の担当が確定した一覧とは表明しない。

機械の検査・計測を先に進め、必要な部分にAIの補助を使い、代替方法を試しても確定できない項目を人へ引き継ぐ。実行できることと、当該サイトで条件・対象を満たして判定できたことを区別する。準備状況・実証記録・引き継ぎ条件の原本へリンクする。

## 代替案

- 既存資料へのリンクだけでは、複数の資料を読んで分担を組み立てる必要がある。
- 各達成基準を3分類のどれか1つへ固定すると、機械で調べられる部分と内容判断が必要な部分を混同する。
- 道具やAI一般の可能性だけで分類すると、現行キットで未実装・未実証の検査まで利用可能と読めてしまう。

## 影響

READMEを利用者向けの要約とし、方法の仕様・準備状況・実証記録の原本は維持する。検証方法を変更する際は、READMEの自動実行・追加検証・環境条件の表記も見直す。検査定義・実行ロジック・判定・証拠は変更しない。

## 検証方法

既存の方法一覧・準備状況・実証記録・引き継ぎ規約と記述を照合する。表中の基準番号が現行カタログに存在すること、文書内の相対リンクとMarkdownの表の列数を確認する。文書だけの変更のため、実ブラウザー試験や検証ロジックの試験は再実行しない。
