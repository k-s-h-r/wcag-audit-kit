# 0114 URLからアコーディオンを調べる際にEnterとSpaceを比較する

状態はProposed。

## 背景

T018は、Enterで開いてからTabで本文へ進み、Shift+Tabで戻ってEnterで閉じる経路を確認した。以前の対照で使ったクリック専用の `div` とネイティブの `button` は、対象の見た目と部品の種類が異なっていた。統合版の実測では、通常のボタンを押すキーとして簡易探索がEnterを選び、Spaceは試していない。[T018の開閉経路](../tasks/T018-widget-operation-sequences.md) · [ADR 0100](0100-follow-accordion-keyboard-return.md)

## 決定

同じネイティブボタン、本文、スタイルで、キーに対する既定動作だけを変えたアコーディオンを固定対照にする。URLと共通設定で `page-audit` を実行し、簡易探索後に残るSpaceの観察を、別runで `--resume --explore` から行う。実際のキー入力、本文の表示、`aria-expanded`、Chromiumのアクセシビリティツリーの展開状態を照合する。目で見た表示だけから、操作手段による差を判断しない。

## 代替案と影響

簡易探索で既定の候補を増やす場合は、ほかのページで同じ探索予算を使ったときに観察を失う可能性がある。今回は既存の通常探索で追加観察する。得られた結果は試した操作に限定する。ほかのキーボード経路や支援技術で読み上げた結果は個別に検証し、機械結果から2.1.1全体の判定を確定しない。

## 検証

2ページを両画面幅で実行し、初期表示が同じこと、マウスとキーの記録を区別できること、保存した表示と展開状態をたどれることを確認する。観察していない経路は未確認として記録する。収集と採点の手順を分け、同じURL起点の実行を独立に再現する。[条件と再実行](../../validation/development/T018/url-operation/README.md)
