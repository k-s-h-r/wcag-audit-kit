# 0123 ダイアログ離脱の採点で証拠のハッシュを照合する

状態はProposed。

## 背景

T030のURL起点の採点は、離脱記録、実入力、遷移の内容を照合していた。公開済み040の入力記録の複製に空白を加えると、JSONとしては同じ内容を読めるが、SHA-256は採取時の記録と異なる。この状態でも、変更前の採点はPC幅の候補を採用した。[T039](../tasks/T039-verify-dialog-score-proof.md)

## 決定

2.1.2-02の離脱候補を採点するときは、`dialog-focus.json`、`input-events.json`、`transition.json` のパスとSHA-256を探索台帳の `proof` と照合する。3件の照合が済んだ候補に、従来の対象、経路、実入力、操作後の状態の検査を適用する。

帳票に上がった離脱候補の遷移は、JSONを読み込む前に照合する。照合できない候補は該当する画面幅の離脱結果から外し、別の正常な経路から得た到達証拠と、別の画面幅で確認できた結果を使う。帳票に残る採点未対応の指摘は、採点で採用した判定と区別する。

## 代替案と影響

JSONとして読み取った値の比較は、内容が変わった場合に検出できる。元のバイト列まで照合するには、台帳がファイルごとに保存しているSHA-256を使う。対象は既存の離脱採点が参照する3ファイル。収集済みの台帳で、3ファイルに記録された値が一致するものは従来の結果を維持する。

## 検証

公開済みの039と040を再採点する。040の別コピーで3ファイルを個別に変えた対照、2画面幅の入力記録を変えた対照、台帳から入力記録の登録を外した対照を用意する。遷移ファイルが途中で切れた対照と欠けた対照も含め、変更前後の採点を画面幅ごとに比較する。[試験結果](../../validation/development/T039/README.md)
