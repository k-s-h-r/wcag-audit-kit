# 0030 キー入力前後の画像と、指定した外枠の画素を記録する

日付：2026-11-19 / 状態：Accepted

## 背景

2.4.7の指定経路には実キー入力とフォーカス位置が残るが、フォーカス表示の有無を画像から復元できなかった。1.4.11では、CSSの枠色だけからは重なりの影響や隣接色を確定できなかった。

## 決定

2.4.7の指定経路の最終操作を挟んで、2枚のビューポート画像を取得する。主文書の同じ対象、実キー入力、文書、フォーカス、表示領域、倍率、スクロール位置、対象の矩形を照合する。対象が画面外にある、表示位置が変わる、または入力後の状態を確認できない場合は、取得できた証拠と理由を残す。キャレットを含む元の表示で撮影する。画像予算が2枚に満たない場合はペアの取得を省略する。

1.4.11は、視覚的な識別に必要な外枠と確認済みの対象を指定し、初期表示を1枚撮影する。色が均一で不透明な単色の直線枠に限り、四辺の中央付近とすぐ外側の画素を照合し、丸める前の比と3:1を比較する。複雑な描画、前面の重なり、画素の不一致、撮影中の対象の変化は保留する。境界の必要性、各操作状態、例外は引き続き別に確認する。

画像は`ai`／`full`で`screenshots=all`を使用し、既存の画像上限を適用する。外枠の画素読取りには任意依存のPillowを使う。2.4.7の取得状態はJSON・HTML・Excelの専用欄へ出し、機械検査や達成基準の通過件数には加えない。1.4.11は指定した外枠の測定結果を機械検査欄に出す。

## 代替案と影響

CSS値や画像差分だけでフォーカスの見え方を判定すると、スクロール・レイアウトの変化や、キャレットなどの一時的な表示を誤って扱う。比較条件と画像を保存し、フォーカス表示の有無は残る確認とする。外枠もCSS色だけでは採点せず、実際の画素を確認できる範囲に絞る。以前のrunの報告を読み直すことはできる。実装が異なるrunの探索は新しい保存先で開始する。

## 検証方法

```sh
python3 tests/focus_image_paths_browser.py --out <新しい出力先>
python3 tests/border_contrast_paths_browser.py --out <別の新しい出力先>
```

Chromiumで既存の2.4.7の6ページを検査し、5ページで比較可能な前後画像を取得し、画面外へフォーカスする1ページは比較不可とした。キャレットのみの表示、レイアウトの変化、撮影設定と上限、中断からの再開、3形式の帳票を追加確認した。1.4.11の既存2例では約1.358:1と7.455:1を測定し、前面の重なりと画像なしの条件では確定しなかった。
