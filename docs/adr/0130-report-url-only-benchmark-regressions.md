# 0130 URL起点のベンチマークで行ごとの改善と回帰を表示する

状態はProposed。

## 背景

操作条件付きのベンチマークには採点レポートと比較がある。URL起点の試験は収集と採点を別々に起動し、固定76ページ・87行の実測をJSONで保存していた。修正の前後を確かめるとき、正解の総数だけでは、別の行で起きた改善と回帰を見分けにくい。[固定条件と基準値](../../validation/development/T020/README.md) · [T044](../tasks/T044-compare-url-only-benchmark-results.md)

## 決定

既存のURL起点の入口に `--report` を追加する。収集後に同じ採点器を実行し、正解数、判定済み件数、問題検出、対照一致と未確認の内訳を出す。HTMLの各行から、今回の画面幅別の証拠をたどれる。

`--baseline` に前回のJSONを指定すると、同じページ・状態・対象・観点・期待結果の行を比べる。正解の喪失、新たな確定不一致・収集失敗、観察済みから未到達への変化は回帰とする。今回初めて期待と一致した行は改善とする。採点行に対応しない指摘は件数も比較し、一覧の正解数とは別の指標にする。

問題集・環境・実行引数・並列数・採点行と、記録がある探索上限・採点器の版を照合する。採点器の版を持たない過去の結果を使う場合は、一致を確認できないことを表示する。元のrunをもう一度採点する場合も、新しいJSONとHTMLに保存する。

## 代替案と影響

集計の差だけを出す案では、同じ総数で起きる行の回帰を見落とす。操作条件付きの比較と同じ表に合わせる案では、URL起点の採点が持つ未到達と観察後の判定なしを表しにくい。既存の採点JSONを入力に使い、結果と証拠の参照を保ったまま表示と比較を追加する。

## 検証

保存済みの成績で改善と回帰を照合し、同じ総数で行が入れ替わる対照と条件が異なる対照を用意する。Chromiumで固定76ページを一括収集し、HTMLとJSONを開いて全行・集計・前回との差を確認する。[再実行方法](../../benchmarks/README.md#一括で採点し前回と比較する)
