# 0015 配置できるスキルをskillsに揃える

日付：2026-11-17 / 状態：Proposed

## 背景

4つのスキルのうち全体進行だけがリポジトリのルートにあり、他の入口はskills配下にあった。実行コードと共通資料は全スキルの外にあり、単独配置にはinstall_skills.pyで組み立てる作業が必要だった。READMEの「スキルとして使う」がこの生成作業から始まるため、利用者がAIにスキルを呼び出させる操作と、開発者の配布準備を混同しやすかった。

この判断は[0003](0003-modular-skills-and-inspection-profiles.md)の、共通原本から導入時に配布用ディレクトリーを生成する方式を変更する。目的別の4入口と検証の取り決めは維持する。

## 決定

- 4つのSKILL.mdをskills/の同じ階層へ揃える。ルートのSKILL.mdは移動する。
- 各フォルダーに実行コード、資料、テンプレート、vendorと依存関係の一覧を含め、フォルダーをコピーするだけで配置できる状態をコミットする。通常の導入から生成コマンドを外す。
- 共通リソースの編集元はskills/wcag-audit-kit/。開発者がscripts/sync_skills.pyで他の3フォルダーへ同期する。固有のSKILL.mdは同期対象にしない。--checkで相違を検出する。
- 開発専用スクリプト、テスト、ADR、保存済みの実証記録はルート側へ置く。大きな実証記録はスキルへ複製せず、既存の固定コミット参照を保持する。
- 個別の3スキルはそれぞれ単独で配置できる。全体進行には4スキルを登録する。Python等の実行依存の初回導入と、AIによる通常の呼び出しをREADMEで分ける。
- 補助CLIの呼び出し元は配置したスキルのディレクトリーとする。ルートから直接CLIを使う開発者向けの例にはskills/wcag-audit-kit/までのパスを明示する。

## 代替案

- SKILL.mdだけ移動し、親ディレクトリーの共通コードを参照する案：単独配置できず、導入時の組み立てが残る。
- 兄弟フォルダーへのシンボリックリンクで共有する案：個別コピー先で参照が切れ、コピー方法やOSに依存する。
- 共通処理を別パッケージとして公開する案：独立配布とバージョン管理の仕組みが増えるため、今回は採用しない。

## 影響

チェックアウト時の共通ファイルは4フォルダーへ複製される。Gitは同一内容のblobを共有できるが、作業ディレクトリーの容量は増える。編集元を1つに決め、同期確認と独立コピーの実行試験で相違を防ぐ。利用者は生成用Pythonを実行しないが、補助処理の実行にはPythonと必要な依存物の導入が引き続き必要となる。

既存のルートscripts/audit.pyを直接呼ぶ操作は新しいパスへの変更が必要。READMEと開発用テストの参照を更新する。保存済みのrun、判定、検査定義スナップショット、原始証拠は変更しない。検証モード、WCAG判定、未確認の意味も変更しない。

## 検証方法

- 4スキルのフロントマターとローカル資料の参照を確認する。
- 同期確認が欠落・内容差分・余分なファイルを検出し、--checkが書き込まないことを試験する。
- 各フォルダーをリポジトリ外へ単独コピーし、別の作業場所からCLIの設定・URL選定・保存済み台帳の報告・Excel出力を実行する。
- Python全体試験、JavaScriptアダプター試験、ローカルHTMLを使うブラウザー統合試験を実行する。
- 既存の実証記録と前回監査runのファイル一覧・ハッシュが変更されていないことを照合する。
