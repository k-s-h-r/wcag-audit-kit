# ADR 0034：実SRの正常対照と互換性の制約を新規実行で確認する

日付：2026-11-18。状態：提案。対象：T012。起点：T007提案版081d18f。

## 背景

現在の環境にOrca・Xvfb・Speech Dispatcherはなかった。過去の実績を現在の動作確認へ流用せず、限定した一組を用意して実操作と発話を調べる。

## 決定

既存の31パッケージのmanifestを元にDebian配布物を取得しSHA-256を照合した上で、workspace内の専用rootへ展開する。OSへインストールせず、既存のアダプターの専用D-Bus・X11でOrca 48.1とChromium 156を動かす。

既存4.1.3対照2件を実行し、正常な通知が取れない場合に無発話を不適合へ変えない。Playwright入力とnative入力を別のrunで比較し、既存のlive-region比較ページで実際の画面・フォーカス・発話を確認する。採点の期待値や問題HTMLは変えない。

## 代替案と影響

Guidepupのカーネル対応条件は偽装せず、native Orcaの結果と区別する。AXツリーやモックを実発話へ代用しない。入力変更だけでは対象の通知取得を改善しなかったため、試したworker変更は製品へ採用しない。試行002の変更原文と版はrun.zipへ保持する。

この一組では明示したpolite、明示atomic、非atomic statusの通知を取得できたが、暗黙atomic statusと通知属性のない例は取得しなかった。特定組合せの観察であり、roleだけから成功や不適合を生成しない。音声出力はALSA nullで、ログはOrcaが合成器へ渡した発話であり音響録音ではない。

## 検証

配布物31件、実SR対照2件を2方式、比較ページの10操作を記録した。見える更新・入力後フォーカス・名前発話・通知発話を別々に残す。選択問題集の2件は両runともcant_tell、strict2で未完了。比較ページの5ボタン名と明示通知3件は取得できた。現在の限定的な互換性制約をT014へ渡し、全実SR能力を達成したとはしない。
