# 0034 URL抽出ではリダイレクト先を送信前に照合する

日付：2026-11-19 / 状態：Accepted

## 背景

`pages`の抽出モードでは、対象範囲外のURLを候補から除いていた。一方、対象内のページから除外先へリダイレクトすると、到達後の範囲確認までに除外先へGETが送られることをローカルサーバーで確認した。

## 決定

Chromiumで最上位の文書を読み込む際、送信前に毎回`scope.include`・`scope.exclude`とオリジンを照合する。HTTPの各リダイレクト先と、同じタブで発生する別文書への移動にも適用する。範囲内の移動はChromiumの通常の処理に任せ、Cookieや相対URLの解決を維持する。止めた移動は元のURLの訪問エラーに記録する。

この制御の対象はURL抽出中の最上位文書。画像・スクリプトなどのサブリソース、埋め込み文書などの通信や操作後に現れるリンクは、別の観察範囲として扱う。指定URLだけを使うモードは一覧の作成だけを行う。

## 代替案と影響

最終URLを調べる方法では、範囲外に送信したあとで気付く。HTTPの追従を別のクライアントでやり直す方法では、Cookieとブラウザーのナビゲーション状態を同じように扱う必要がある。抽出に使うブラウザーの送信前イベントを使い、既存のURL・取得元・訪問上限の記録を引き続き使う。

## 検証方法

`python3 tests/url_selection_browser.py --out <新しい保存先>`で、ローカルサーバーの受信記録と出力を照合する。指定モード、相対リダイレクト、別ポート・除外パスへのリダイレクト、HTTP失敗、訪問上限を比較する。

Chromiumで、除外パスへのHTTP移動、別ポートへの二段階移動、同じタブでのスクリプトによる移動の3例を試した。修正前は3宛先へのリクエストを受信した。修正後は0件で、一覧に3件の範囲外エラーが残った。許可された302・307と、リダイレクトループに続く候補では、Cookie・相対リンク・クエリーとフラグメントの扱いが維持された。
