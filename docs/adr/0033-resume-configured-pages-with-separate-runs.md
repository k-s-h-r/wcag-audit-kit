# ADR 0033：指定URLを1ページずつ実行し、同じ条件で再開する

日付：2026-11-18。状態：提案。対象：T010。起点：T007提案版081d18f。

## 背景

限定した1ページの機械検査が安定したため、指定一覧の取り違えと中断後の継続を評価する。T006のクエリー・ハッシュと似たパスを含む有限の所有サイトを使う。G1のコードは未マージであることを明記する。

## 決定

既存のpage-auditをURLごとのrunで順番に使う。完了済みページを再実行せず、中断したページだけ同じ設定・環境・実装で--resumeする。run・URL・結果・証拠の出所を読み取り集計に残す。404は訪問成功や適合へ変えない。

## 代替案と影響

新しい一括実行基盤や独自の再開形式は追加しない。start/recoverによる収集の再実行と、page-audit --resumeを混同しない。この評価は1状態・desktopの機械ルールに限定し、未知のサイトの全状態や全AAの完了は主張しない。T004のホスト呼び出し条件が未達のためG2は未達。

## 検証

事前に7URL、ルール上の問題2件、404、中断方法を固定した。2ページ目のHTTP読み込み中にSIGINTを送信し、同じ出力先へ再開。完了した1ページ目の全10証拠と、中断時の2証拠が不変。6ページの機械ルール、55件ずつの未実施判定、ページ別HTML・JSON・Excelを照合した。初回は試験ドライバーの補助関数の参照誤りで最終集計が止まったため、原文と全runを保存し、修正後に新規出力で再測定した。
