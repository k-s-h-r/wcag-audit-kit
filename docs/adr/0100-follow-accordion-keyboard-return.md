# 0100 本文の開閉ボタンへキーで戻って閉じる

状態：Proposed

## 背景

URLから本文の開閉を検査すると、開くキーや展開先のTabを記録できても、戻って閉じる経路が探索に残らない場合があった。キーを送っただけでは、領域が表示されたか、閉じたあとにフォーカスがどこへ移ったか分からない。

## 決定

本文を開閉するボタンと、単一の `aria-controls` が指す領域を対象とする。対象へTabでフォーカスを合わせ、Enter・Spaceの前後で表示と展開状態を観察する。Tabで別の要素に進んだ場合は、Shift+Tabで同じボタンへ戻れるかを試す。

閉じる操作は、同じ試行で領域とフォーカスを照合し、実際のShift+Tabが届いたことを確かめてから行う。領域の表示や戻り先を確認できない場合は保留とする。CSSでボックスがない領域や透明な領域にも、確定した開閉の判定を出さない。

## 代替案

初めに開いたボタンを後からTab検索してもう一度操作する方法では、本文に入った直後に逆順で戻れるか分からない。本文に入ったあとEscapeを調べる既存の手順は維持し、同じボタンに戻って閉じる経路も上限内で試す。

## 検証と影響

新しい経路には深さ4が必要。簡易探索の上限と両幅の配分を保ち、選んだ開閉経路を先に試す。本文内にフォーカス先がある例、テキストだけの公開Shadow DOM、クリックでだけ開く例を通常のURL入力で比較する。透明な領域と `display: contents` の対照、既存のメニュー経路も確認する。[実測と再実行](../../validation/development/T018/README.md)
