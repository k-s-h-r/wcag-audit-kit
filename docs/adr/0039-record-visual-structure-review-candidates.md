# 0039 見た目の見出し・リストを確認候補として記録する

日付：2026-11-19 / 状態：Accepted

## 背景

見出しや箇条書きに見える段落は、既存の機械ルールだけでは見つけにくい。同じ外観の導入文もあり、装飾をそのまま達成基準の不適合へ結び付けると誤判定になる。

## 決定

`visual_structure_scope` で指定した領域の初期表示を観察する。表示範囲内にある直下の段落から、本文と文字サイズ・太さ・位置が異なる見出し風の段落と、記号・位置がそろう連続した箇条書き風の段落を拾う。公開された見出し・リストの構造をChromiumのアクセシビリティツリーで照合し、認識済みのものを候補から除く。

観察結果を探索の証拠へ追加し、JSON・HTML・Excelから対象と証拠を追えるようにする。観察できなかった場合も理由を残す。判定は従来どおり、画面上の役割と伝えるべき関係を調べたうえで検査票に記録する。

## 代替案と影響

領域設定を必須にして、関連する表示に絞る。画素画像を消費せず、レイアウト・文言・アクセシビリティ情報から観察する。操作後、領域内の子階層、スクロール外、装飾が基準に合わない形は追加調査に残る。1.3.1の適用範囲と合否は既存の検査票が扱う。

## 検証方法

`python3 tests/visual_structure_probe_browser.py --out <新しい保存先>`。Chromiumで11の対照を比較し、通常の `page-audit` で候補あり、候補なし、領域が一意でなく未観察、設定なしの4ケースを確認する。ページ別JSON・HTML・Excelの証拠参照、1.3.1の検査票が未実施のまま保持されること、後続の作業票に証拠が渡ることを照合する。
