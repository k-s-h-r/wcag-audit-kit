# 0076 操作の影響範囲から再検査する要素を決める

- 日付 2026-11-20
- 状態 Proposed

## 背景

[ADR 0069](0069-run-a-short-operation-sweep-automatically.md)で、簡易探索は開閉できる部品や新しく使えるようになった部品を優先した。操作で新しい状態に到達すると、その都度、文書全体をすべてのaxeルールで検査していた。アコーディオンの開閉で、離れた場所にある同じ要素の属性を毎回確認する必要はない。

## 決定

初期画面では文書全体を検査する。簡易探索では、最後の操作の直前と直後を比べる。現れた要素、消えた要素、属性やテキストが変わった要素、DOMの更新箇所、ARIAなどで結び付く要素、フォーカスの移動を `operation-impact.json` に記録する。CSSで表示が切り替わる領域や、非表示の要素からボタン名を参照する場合も比較できる。同じ状態に戻った場合は、操作の記録からその状態の検査結果を参照する。

一つの要素の属性で判定できる `aria-valid-attr` と `tabindex` から始める。直前の経路の記録、今回の操作前、今回の操作後の3つで、同じIDを持つ表示中の要素の情報が一致した場合に結果を再利用する。操作対象やフォーカス先、変化した要素と参照関係にある要素は再検査する。ほかのaxeルールは文書全体を検査し、既存の実Tab観察やフォーカスの検査も行う。

同梱するaxe 4.11.0の公開APIで、2ルールのセレクターから再利用する要素を除く。iframeやShadow DOMがある場合、比較元が無い場合、DOM更新が続く場合などは全文書で再検査する。祖先が `aria-hidden` または `inert` である要素も毎回検査側に残す。従来の `axe.json` には再利用した結果も含める。再検査した対象、再利用した対象と参照元は `operation-impact.json` に残す。 [axeの設定API](https://github.com/dequelabs/axe-core/blob/v4.11.0/doc/API.md#api-name-axeconfigure)

## 代替案と影響

DOM更新の通知から対象を決める案では、CSSによって現れた子要素や、別の場所にあるラベルの変化を取りこぼす。すべてのルールを変更箇所に限定する案では、文書タイトル、フォーカス順、色のコントラストなどを判断する文脈が足りない。ルールごとの比較で再検査する対象を減らす。操作経路の再生には引き続きページの読み込みが必要で、今回の変更によるリクエスト数や総所要時間の減少は評価していない。

## 検証方法

`python3 tests/initial_page_audit_browser.py --out <新しい出力先>` を実行する。ローカルのChromiumで、CSSで開閉するアコーディオンを簡易探索と通常探索の両方で検査する。次の結果を照合する。

- 開閉ボタンと新しく表示されたボタンを再検査し、ARIA属性名の検査は変化のない10要素の結果を再利用する。正の `tabindex` の検査は9要素の結果を再利用し、開いて現れた1要素を検査する。
- 全ルールの指摘、追加確認、通過、対象外の記録と対象が通常探索と一致する。
- 開いた後のTabは中のボタンに移動する。閉じる操作では中の要素が消え、閉じた状態から開いたときの指摘を参照しない。
- 非表示の名前の参照元だけを変える操作で、それを参照するボタンが記録される。名前が無くなったボタンは全文書の検査で検出する。

レビュー後は、祖先に `aria-hidden` と `inert` を設定する各操作について、子要素の結果を再利用せず、全文書の検査と一致することを確認した。
