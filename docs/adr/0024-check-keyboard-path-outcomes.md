# 0024 指定したキーボード経路の到達条件を機械で照合する

日付：2026-11-19 / 状態：Proposed

## 背景

従来の単独ページ検査は、操作候補へキーを送れたことを機械結果に記録していた。3階層メニューでは、Enterを押しても開かない、開いてもフォーカスが先へ飛ぶ、開いた階層から離脱できないといった問題が残る。基準ごとの対照は既存の問題集に揃っている。[ADR 0013](0013-three-level-navigation-fixtures.md)

## 決定

`page-audit`の設定で、キー操作とフォーカス・表示の到達条件を経路ごとに指定できるようにする。経路は通常探索と同じキューで管理し、各経路を初期表示から別のブラウザーコンテキストで実行する。実際のキー入力、操作前後のフォーカス、表示、URLを記録する。最初に一致しなかった操作と要素をページ別の機械検査へ出し、HTML・JSON・Excelから同じ証拠を参照できるようにする。

リンク先まで確認する場合は、最後のキーで対象範囲内の同一オリジンにある指定URLへのGETを許可する。リダイレクトや通信制限、入力量の上限、更新の観察上限で到達条件を確定できない場合は判断保留とする。

## 代替案と影響

すべての開閉部品にEscapeで閉じることや特定の移動順を一律に要求すると、仕様に合う別の操作方式も誤って指摘する。既知の経路と条件を設定し、比較できた範囲を記録する方式を採る。代替手順の有無、構造として意味のある順序、達成基準全体の適否は追加の確認対象に残る。

## 検証方法

`python3 tests/keyboard_checks_browser.py --out <新しい出力先>`で既存の正常3ページと問題3ページを検査する。正常側の6経路は通過、問題側の6経路は設定した操作と位置で条件不一致。問題側はHTMLとExcelの対象・キー・観察・証拠が保存済みJSONと一致する。中断後の再開と指定外リダイレクトの保留も確認する。実行出力は作業用ディレクトリーへ保存し、PRに結果を要約する。
