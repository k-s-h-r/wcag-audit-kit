# 0002 検査タスクとExcelによる共同作業

日付：2026-11-15 / 状態：Accepted

## 背景

大きなサイトでは、一度のAI実行で検査を終えられない。人とAIがページや基準ごとに担当を分け、途中の結果を残して続ける必要がある。Excelで一覧を確認し、担当・メモ・判定を共同編集する要望もある。既存のJSON台帳には、証拠の検査と判定履歴を保持する仕組みがある。

## 決定

検査票を固定のcase_idで追跡し、ページ又は基準ごとに上限件数付きのタスクへ分割する。担当・作業状態・メモはplan.jsonに保持する。判定の参照と作業情報を1回の原子的な置換で更新し、同じホストからの書込みはOSのファイルロックで直列化する。プロセスが停止するとロックはOSが解放する。

Excelは閲覧用reportと、取り込み可能なworkを提供する。workの配布時にrun ID、設定・定義のハッシュ、各票の判定と作業情報の版を保存する。変更された票だけを取り込み、更新競合があれば全体を止める。変更されていない古い行は、新しい記録の上書きに使わない。

Excelの判定は既存のrecordと同じ検査へ通す。対象・観察・期待結果・操作・採用した手順・証拠・条件や例外の確認を求め、媒体と人への引き継ぎの検査も維持する。全行を確認してから新しい判定ファイルを作り、最後にplanを切り替える。切り替え前に停止した場合、参照されない新しい判定ファイルが残ることはあるが、公開中の判定参照は変わらない。

同一runの別コピーを複数端末から直接同期しない。調整担当が1つの正本を管理し、Excelを配布・回収する。OneDrive/SharePoint等の共同編集は利用者の既存環境で行い、このCLIは保存されたxlsxを取り込む。

取り込み済みの変更のダイジェストをplanと一緒に保存し、同じファイルの再取り込みで重複記録を作らない。未取り込み行の追加編集は受け付け、一度取り込んだ票を再編集するときは最新の配布版から作業する。

## 代替案

- Excelだけを正本にすると、証拠のハッシュ、型、深い対象の検査、競合の検出が難しい。
- 共有サーバーやDBは複数端末の即時同期に向くが、認証・運用・設置が必要になる。初期導入では、既存のrunとExcelの交換で進める。
- セル内へ判定JSON全体を記入する方法は、通常の対象・観察の編集が難しい。検査票・対象・観察方法を別シートにし、複雑な媒体比較と引き継ぎだけJSON欄を使う。

## 影響

openpyxl 3.1.5を追加する。古いrunも読める。検査定義と保存済みの原始証拠は変更しない。`base_assessment`を指定した直接記録でも更新競合を検出できる。過去の呼出しとの互換性のため、この指定は既存recordでは任意とする。

作業状態doneは、人への引き継ぎを含む担当作業の終了を表す。判断保留や人の確認待ちをWCAGの通過へ変えない。タスクは作成済みの検査票を分割するもので、収集器の全URLの巡回を分割・再実行する機能ではない。収集中の停止には従来のrecoverと未収集範囲の確認を使う。

Excelは1出力1万票、1セル32,767文字までとし、上限を超えたら分割を求める。文字を黙って切り捨てない。サイト由来の文字列を数式として保存せず、取り込み時にも数式を拒否する。ネットワークファイルシステム上のロックや、実際のExcel共同編集サービス自体の動作は保証しない。

## 検証方法

別プロセスのタスク取得・判定記録、強制停止後のロック解放、途中の記録を保持した再開、Excelの往復・変更のない古い行・同じ票の競合・取り込み全体の拒否を試験する。証拠のない通過、作業状態だけの完了、式、長いセル、識別情報の変更も拒否する。保存済みの複数ページの2,200票をExcelへ出力し、件数・未完了・人への確認を読み戻して比較する。
