# 0046 隔離したCodexでスキルの発見と入力への展開を確かめる

日付：2026-11-19 / 状態：Accepted

## 背景

現在の環境でCodexの設定ディレクトリーは読み取り専用で、app-serverの起動時に `installation_id` を保存できなかった。4スキルを実際のホストが見つけ、依頼に応じてどの本文をモデル入力へ含めるか確認する方法が必要だった。

## 決定

同じ版のCodex CLIと公開スキルを、新しいDockerコンテナへ読み取り専用で配置する。コンテナ専用の書き込み先を使い、ホストの設定・認証から分離する。実app-serverの `skills/list` を使って配置を確かめ、個々の短い試行で、通常のテキスト又は明示したスキルとテキストを `turn/start` に渡す。モデルのリクエストはコンテナ内のループバックで観測する。

## 代替案と影響

設定ファイルの確認に加え、実ホストが生成した入力を確認できる。実行試験には認証済みのモデルが必要で、オフラインの入力確認結果と区別する。ユーザーの設定と過去の記録を保持する。

## 検証方法

Debian 13の隔離環境でCodex CLI 0.167.0-alpha.4の `app-server --stdio` を起動した。`initialize`、`initialized`、`skills/list` を順に送り、作業ディレクトリーの `.agents/skills/` にある4スキルが有効で、検出エラーが0件であることを確認した。

カスタムResponsesプロバイダーのURLをコンテナ内の受け口に設定し、各試行で `thread/start` に作業先と `ephemeral: true` を渡した。`turn/start` の `input` には通常の `type: text` を含め、明示指定時だけ `type: skill`、スキル名、コンテナ内のパスを加えた。通常の質問には4スキルの本文が入らず、個別指定4件では指定した本文だけがモデル入力に入った。`codex exec --ephemeral --json --skip-git-repo-check -s read-only` への `$wcag-page` の指定でも、同じ本文が渡った。受け口は入力を受け取ってHTTP 400を返す。今回の観察範囲はモデル入力まで。
