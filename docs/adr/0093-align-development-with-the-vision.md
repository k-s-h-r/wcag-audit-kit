# 0093 VISIONに沿って開発計画と次の作業を揃える

- 日付 2026-11-21
- 状態 Proposed

## 背景

[VISION](../VISION.md)では、URLから操作を見つけ、範囲の適合を根拠付きで答えられることを目指す。[従来の計画](0018-machine-first-staged-audits.md)には最初の10行で行った作業と当時の次の手順が残り、[コンボボックスの実証](0080-follow-editable-combobox-keys.md)後も同じ作業が次の候補に見えた。条件を指定した回帰試験と、URLから必要な操作を見つける検査にも、それぞれの成績が必要だった。

現在の帳票は達成基準ごとの判定、問題箇所、確認が残る範囲と `audit_complete` を表示する。範囲の適合の結論を成果物と最終回答でそろえる作業と、アクセシビリティ点検の試行はタスクになっていなかった。

## 決定

[開発計画](../ROADMAP.md)を完成像・実証の範囲・次の作業に沿って整理し、開発時はVISIONも読む。最初の作業は[既存のT020計画](0084-score-machine-findings-from-url-only.md)で、通常の入口にURLを渡し、問題39行と対照48行を測る。保存済みの記録から適合の結論と二つの成果物を照合する[T021](../tasks/T021-scope-conformance-report.md)は独立して着手できる。

[T022](../tasks/T022-url-to-process-audit.md)でURLを起点とする一手続きの検証を試し、得た操作の証拠を[T023](../tasks/T023-accessibility-review-pilot.md)の点検に使う。二つの使い方で受け取る結果と、現在ある四つの検証手段の設定は、READMEと設計方針から確認できるようにする。

## 代替案

タスクの状態欄だけを修正する案もあった。今回の見直しでは、次に着手する条件と、成果物へつなぐ作業まで計画に置く。対象の発見、判定、報告のどこで止まるかが分かるよう、既存の実装と小さな対照から始める。

## 影響

T018は既存のアコーディオン対照をURLから確かめる作業に絞る。T019は全体の再検査との照合と、再検査量・調べられた状態の計測を扱う。合流済みPRの状態を更新し、過去の実測は版と条件ごとの記録として参照できる。

## 検証方法

タスクID・前提・担当範囲・リンクを照合し、問題集の計画対象数を確認する。保存済みrunの再出力はコピーに対して試し、元の証拠を保存したまま未完了を報告できることを確認する。本計画に追加した実測は各タスクで行う。
