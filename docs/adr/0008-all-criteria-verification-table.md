# 0008 全達成基準の検証分担を1つの表で示す

日付：2026-11-16 / 状態：Proposed

## 背景

[ADR 0007](0007-verification-responsibilities.md)では、確認観点と代表的な基準番号を添え、プログラム・AI・人の分担を3つの表で説明した。この形式では、個々の達成基準について、何をプログラムで確認でき、どの判断が残るかを一覧で確認できない。

## 決定

READMEの分担の説明を、WCAG 2.2の全86達成基準を1基準1行で掲載する1つの表へ置き換える。A・AA・AAAを含め、削除された4.1.1は含めない。番号・名称・レベルは現行カタログと一致させ、基準名から個別の検査手順へリンクする。

各行に、プログラムで確認できる部分と実行範囲、AIによる任意の補助、人又は専門環境が必要になる条件を併記する。プログラムの列ではpage-auditの「自動」、別の操作・道具で行う「追加」、信頼できる実装・実証が揃わない「未整備」を区別する。音声・手話・閃光・読解水準・実端末等の制約は該当する行へ記す。ページ間の比較が必要な基準を、1ページの取得だけで確認済みにしない。

ADR 0007の、基準内の確認観点を分担する方針は維持する。AIや人を達成基準全体の専任とする分類にはしない。AIの利用は必須にせず、機械検査から進める。情報・権限・道具・環境と代替方法を調べても確定できない場合を、人への引き継ぎの共通条件として説明する。証拠取得や一部ルールの通過と、基準全体の適合判定を区別する。

## 代替案

- 代表例だけの表では、掲載されていない基準の分担を個別資料から組み立てる必要がある。
- 全86基準をプログラム・AI・人の別々の表へ分けると、同じ基準内で分担できる部分を比較しづらい。
- 各基準を3分類のどれか1つへ固定すると、自動で取得・計測できる部分と内容判断・環境条件を混同する。

## 影響

READMEは長くなるが、基準番号から分担と残る検査を確認できる。検査手順・方法の準備状況・実証記録を詳細の原本とし、変更時はREADMEの該当行も見直す。実装・検査定義・保存済み判定・原始証拠は変更しない。現行キットの範囲を示す表であり、全基準の自動判定や任意のサイトでの精度を保証しない。

## 検証方法

表が1つであり、全86基準がカタログと同じ順序で1回ずつ現れ、番号・名称・レベル・個別手順へのリンクが一致することを確認する。A・AAの55行とAAAの31行、表の列数、相対リンク、差分の空白を確認する。各行を検査手順・方法一覧・準備状況と照合し、未整備の方法を自動実行可能と記述していないことを確認する。文書のみの変更のため、実ブラウザー検査や実行ロジックの試験は再実行しない。
