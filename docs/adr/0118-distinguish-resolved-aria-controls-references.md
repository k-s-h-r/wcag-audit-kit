# 0118 解決できる aria-controls の参照先を探索状態に含める

状態は提案。

## 背景

非表示の要素を別領域に追加して `aria-controls` の参照先にすると、参照元のHTMLと可視要素の記録が同じでもaxeの属性値検査は変わる。簡易探索は以前の状態と同じと判断し、全体再検査で得られる操作後の結果を保存しなかった。[T019の測定](../../validation/development/T019/reference-recheck/README.md)

## 決定

初期表示と操作後の観察で、既存のID解決処理を使って、実在する `aria-controls` の参照元とIDを記録する。探索状態の比較には組の集合を使う。同じ非表示要素を別の領域に移しても、同じ参照元から同じIDを解決できる場合は、その参照について同じ状態として扱う。

値の妥当性は文書全体に対するaxeの判定を使う。従来どおり、ARIA属性名と `tabindex` の局所的な判定には、条件を満たす要素の結果を再利用できる。

## 代替案と影響

対象要素のセレクターやDOMの位置をそのまま状態の比較に使うと、参照先の移動と参照先の有無の違いを区別しにくい。全操作の後に差分を無視して全文書を検査すると、可視表示も参照も同じ状態で検査を繰り返す。今回は到達できるIDの集合を比較し、変わった状態の属性値を調べる。

新しい記録がない保存済みの状態は従来の状態として読める。探索の実装が変わった場合は新しいrunを作る。

## 検証

同じ公開URLとクリックで、非表示の参照先の追加・削除・別領域への移動を通常CLIから試す。2つの表示幅で簡易探索と全文書の結果を照合し、保存された状態、結果の再利用、報告の根拠を確認する。[再実行と原始証拠](../../validation/development/T019/reference-recheck/README.md)
