# 0104 アクセシビリティ点検を既存スキルから依頼する

- 日付 2026-11-21
- 状態 Proposed

## 背景

T023では見学予約の操作を観察し、キーボードで止まる箇所、改善案、同じ入力での比較結果を示した。点検結果からT022の判定と操作記録も確認できた。この流れを日々の開発や運営で依頼できるようにする。 [T023](../tasks/T023-accessibility-review-pilot.md) · [ADR 0099](0099-pilot-process-accessibility-review.md)

## 決定

`wcag-audit-kit`を明示して点検を頼めるようにする。依頼に保存済みの観察が含まれる場合はその記録を読み、URLから点検する場合は既存のページ収集と操作手順を使って新しいrunに観察を保存する。実行環境の応答で、利用目的と観察、利用への影響、改善案、再測定の方法と結果、未確認、元のWCAG判定への参照を返す。 [点検の手順](../../skills/wcag-audit-kit/references/accessibility-review.md)

## 代替案

専用の公開スキルを増やすと、4スキルにある依頼の振り分けや操作手順を重ねて保守する必要がある。また、CLIへ検査目的の選択肢を追加すると、既存の `--mode` が扱う検証手段と点検の目的が同じ場所に入り、選ぶ項目が増える。今回は既存の操作記録と補助CLIで観察を用意できるため、共通の手順を追加する。

## 影響と検証

既存の4スキルの配置と `--mode` の定義を使う。点検結果は実行環境の回答か、依頼された場合は新しいMarkdownへ出力する。改善の適用は別の依頼で扱う。検査票と原始証拠は参照し、修正後の比較を行う場合は結果を別runに保存する。

保存済みの証拠から点検する依頼と、ローカルURLだけを渡して操作する依頼を確認する。結果から、観察の根拠と再測定の手順を追え、未確認と元の判定が分かるかを見る。同期・単体テスト・相対リンクも確認する。 [T027](../tasks/T027-accessibility-review-workflow.md)
