# 0084 URLだけで発見した問題を機械検査の主成績にする

- 日付 2026-11-21
- 状態 Proposed

## 背景

既知の操作を指定した試験は、観察や判定の不備の切り分けに使える。利用者がURLから検査を始める場合は、操作の発見、必要な状態への到達、判定までが必要になる。[ADR 0077](0077-measure-url-only-operation-exploration.md)で既存8ページを測った。次は、問題集で機械検出対象とした全行を同じ入力条件で測る。

## 決定

[T020](../tasks/T020-url-only-machine-score.md)を追加する。収集側にURLと共通設定を渡し、採点側で保存済みの出力を既存の期待結果に照合する。主成績は、対象にした問題のうち、収集時に正しく指摘して証拠を残した行の割合とする。対照の誤検出、未到達、判定保留、収集失敗の件数を併記する。

起点の問題集では、問題39行と対照48行が対象になる。今回の決定は、この範囲の測定と採点の計画を追加するもの。測定後に改善箇所を決め、実装は個別の変更に分ける。

## 代替案

T017の8ページを繰り返す方法は、限られた操作の回帰を測るのに使える。全87行に範囲を広げると、既に機械検出対象としている観点のどこがURLだけで使えるかを把握できる。問題集全体へ一度に広げると、意味の比較や実スクリーンリーダーなども必要になるため、最初に機械検出を期待する行で基準値を取る。

## 影響

主成績は固定した問題集と探索上限に対する値になる。既知の問題を取りこぼした行や条件を満たせなかった行も分母に残し、改善前後の比較に使う。T018の操作経路とT019の差分再検査は、検出器を測る版と保存先を固定すれば並行できる。

## 検証方法

計画の追加時は、既存の問題集から対象行を照合し、タスク索引とロードマップの開始条件、参照リンクを確認する。実行担当はT020の完了条件に従い、新しいrunで全行を計測し、採点データと検証記録をPRに添える。
