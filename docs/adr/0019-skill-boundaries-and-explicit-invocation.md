# 0019 4スキルの責務を明確にし、明示呼び出しと対象固有の手順を採用する

日付：2026-11-18 / 状態：Proposed

## 背景

[ADR 0018](0018-machine-first-staged-audits.md)で機械検査から段階的に進める順序を定めた。実測へ進む前に、公開する4スキルの過不足、明示呼び出し、pstackから取り込む構成を確認する必要がある。

4スキルには単独利用の目的がある。一方、候補URLから試験対象を決める責務と、対象固有の操作手順の確認が十分に接続されていなかった。報告スキルには作業用Excelの判定取り込みも含まれ、出力と判定更新の境界が曖昧だった。

## 決定

[設計方針](../SKILL-DESIGN.md)に4スキルの責務と入力・出力を定める。全体進行が試験範囲と選定、pagesが候補一覧、pageが指定ページの検証、reportが保存結果の集計・出力を担当する。取り込みは明示された記録更新として区別する。機械・AI・実スクリーンリーダーや各達成基準を別の公開スキルに分けない。

4つのSKILL.mdへ`disable-model-invocation: true`、それぞれの`agents/openai.yaml`へ`policy.allow_implicit_invocation: false`を追加する。明示された全体監査では、全体進行が子スキルのファイルを必要な分だけ読み、内部手順として適用する。ホストのSkillツールによる子の自動起動に依存しない。明示された範囲を引き継ぎ、内部手順の参照で新しい作業の権限を増やさない。

pstackの手順作成・保守から、対象固有の起動、準備確認、操作、証拠、後片付けを実行して確かめる循環を取り込む。既存の方法一覧とテンプレートを拡充し、pageと全体進行から参照する。手順の不一致、環境不足、対象の問題を切り分ける。1経路の実行確認をWCAG全体の検証成功にしない。参照版と採用しない点は設計方針へ残す。

各スキル固有の呼び出し設定を共通リソースの同期対象にはしない。ベンチマークでは、その設定も実装のスナップショットと識別値へ含める。[ADR 0015](0015-ready-to-use-skill-directories.md)の単独配置を維持する。

## 代替案

4つを1つにまとめると、1ページ・URL一覧・報告だけの利用範囲が曖昧になる。機械・AI・実スクリーンリーダー別に分けると、同じページの状態と残作業の管理が分散する。pstackのcreate・maintainを公開スキルとしてそのまま追加する方法は、現在の利用目的には機能が重なるため見送る。

呼び出しフラグだけ追加すると、ホストが子スキルの起動を拒む場合の全体進行が不明確になる。既に明示された処理の内部手順として読む方法を合わせて定める。Codexにも同じフラグが効くと仮定せず、公式に記載された設定を併記する。

## 影響

通常の利用は環境のスキル選択・明示呼び出しから始める。新しい設定と指示で実装の識別値が変わるため、旧ベンチマークrunを再開せず、新しいrunで評価する。公開するスキル数、機械検査の既定、既存の判定・証拠は維持する。

今回の変更で、代表サンプルを自動選定する仕組みや、対象固有の手順の新しいJSON形式まで実装したとは扱わない。実ホストの呼び出し動作と指示の遵守は別に評価する。skill-creator付属の現在の簡易検査器はこのfrontmatter拡張を許容しないため、その制約を報告し、YAMLの型・配置・保持と実装スナップショットをリポジトリの試験で確認する。

## 検証方法

4フォルダーの単独コピーに呼び出し設定が残ること、共通同期が固有のagents設定を変更しないことを確認する。設定変更がベンチマークの実装識別値を変え、スナップショットへ含まれることを試験する。関連するPython試験、共通同期、文書リンク、差分を確認し、独立したレビューで責務と内部手順の整合を確認する。各ホストでの明示・暗黙呼び出し、実サイトの監査精度は未実証として残す。
