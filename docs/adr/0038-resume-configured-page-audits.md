# 0038 指定URL一覧をページ単位で検査し、途中から再開する

日付：2026-11-19 / 状態：Accepted

## 背景

固定した機械検査10行と、指定URLを別々に収集する中断試験を確認した。利用者が多数のURLを扱うときは、URLごとにコマンドを組み立て、処理済みの帳票を管理する作業を省きたい。中断後に数を限って再開でき、個々の未確認事項も分かる必要がある。

## 決定

`page-batch` が確定済みのURL一覧を順序通りに読み、各URLに従来の `page-audit` を適用する。バッチ台帳は未着手、中断、帳票出力、ページ収集失敗を保存する。各ページには独立したrunとHTML・JSON・Excelがあり、観点の判定件数と未探索の経路はページの処理状況とは別に記録する。

実行前に中断扱いの行を保存し、同じ評価条件で再開する。同じ設定・URL一覧・認証状態・検査実装を確認し、収集済みの証拠を引き継ぐ。途中に保存した証拠のうちrun定義を持たない実行先は保存し、次の試行先を割り当てる。帳票出力済みのページと収集失敗を自動で繰り返さない。操作経路の続きにはページ個別の再開を使う。

## 代替案と影響

全URLを単一runとして収集する既存の方法では、ページごとの再開と帳票生成をまとめて扱いにくい。今回は `page-audit` の証拠と報告をそのまま利用し、ページ間の共通部品も各ページで検査する。対象は `configured` の機械検査とし、上限がある場合は残りを未着手として保持する。

## 検証方法

`python3 tests/page_batch_browser.py --out <新しい保存先>` を実行する。1件目の完了、2件目の途中停止と再開、HTTP 404の記録、最後の1件の実行を照合する。最終台帳は帳票出力3件、ページ収集失敗1件。処理済みのページへの再訪を検出せず、保存済みの証拠のハッシュを確認した。全ページの検査票には未実施が残った。

`python3 tests/site_selection_browser.py --out <新しい保存先>` では、認証後や操作後の観察を含む一覧9件を `page-batch` に渡した。帳票出力2件、404の失敗1件、未着手6件。認証が必要な画面の表示と操作後に見つけたURLのクエリー・フラグメントを確認し、各ページの証拠をそれぞれ照合した。一つのバッチに渡す認証状態は一組とし、権限による表示差は別に調べる。
