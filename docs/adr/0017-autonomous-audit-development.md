# 0017 自律検証の実測を開発の中心に置き、再開可能な計画を残す

日付：2026-11-18 / 状態：Proposed

## 背景

[ADR 0011](0011-criterion-regression-corpus.md)で採点基盤を設け、[0014](0014-complete-fixture-patterns-and-consolidate.md)までに問題集を拡充した。[0015](0015-ready-to-use-skill-directories.md)と[0016](0016-integrate-benchmarks-with-skill-layout.md)で、配置用スキルと開発用の問題集を併用できる構成になった。

利用者の目的は、人手を介さず有償の専門的な検証に相当する品質でWebサイト・Webアプリを検証することである。実装修正は別スコープである。問題集や台帳の件数だけでは、その能力を示せない。今後の優先順位が会話だけに残ると、新しいセッションで背景の調査や方針の議論を繰り返してしまう。

## 決定

[開発計画](../ROADMAP.md)を、目的、現在地、段階ごとの完了条件、次の作業を確認する文書とする。AGENTS.mdとREADME、CONTRIBUTINGから案内する。進捗と次の作業は開発計画で更新し、過去のADRと保存済みの証拠は保持する。

最初の到達目標をWCAG 2.2 AAとし、既存のAAAの問題集も保持する。次の開発は、現行スキルを使うAIによる1.1.1・2.1.1・2.1.2の実測から始める。正解を見ない検査担当と採点担当を分け、正常例と問題例、原始証拠、未確認、操作履歴を記録する。基準値を記録できたことと、自律検証に成功したことを別の完了条件にする。

現在の作業票は基準・対象・状態を与えるため、URLから検査対象を発見する試験は後の段階で追加する。見逃し・誤検出・誤った適合・未確認・人への引き継ぎ・再現性を評価し、時間とトークンも記録する。取得結果の照合など未接続の処理は、改善すべき課題として明記する。

利用先のAIが計画と判断を担当し、補助コードが測定・記録・採点・出力を担当する構成を維持する。通常の依頼でAIが必要な検証方法を計画する動作は今後の実装課題とする。この文書追加では、[ADR 0010](0010-selectable-verification-modes.md)のモード境界や現在のmachine既定を変更しない。最初の実測ではaiモードを明示する。

## 代替案

会話やPR本文だけに方針を残すと、次の担当が現在の優先順位を探しにくい。ADRに進捗を追記し続けると、当時の判断と現在の状態が混在する。新しいスキル構成や広範囲の検出器を先に作る方法は、実際の失敗原因が分かる前に変更を増やすため採用しない。

## 影響

新しいセッションは同じ文書から再開できる。開発PRでは、変更によって計画の状態が変わった場合に、完了根拠・未確認事項・次の一手を更新する作業が増える。

今回の変更は文書に限る。スキルの実行コード、既定動作、問題集、期待結果、保存済みの判定・証拠は変更しない。自律検証の新しい実績も追加しない。専門家による正解確認や、対応環境と品質の数値基準は、今後具体化する課題として残す。

## 検証方法

変更した文書の相対リンクと、ADR番号・必須項目・索引を確認する。AGENTS.mdから開発計画へ進み、前の会話を読まずに現在地、次の作業、完了条件、未確認事項を確認できるかレビューする。既存のモードと検査担当の手順に矛盾しないこと、差分が文書だけであることを確認する。AIによる実検証は次の作業として残す。
