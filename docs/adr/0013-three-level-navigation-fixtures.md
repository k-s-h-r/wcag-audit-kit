# 0013 3階層のメニューをたどるテスト入力を追加する

日付：2026-11-17 / 状態：Proposed

## 背景

[ADR 0012](0012-all-criteria-negative-fixtures.md)で全基準の代表的な問題例を用意したが、単体部品とモーダルだけでは複数階層の到達・離脱・移動順を試せなかった。利用者から、グローバルメニューの3階層目まで確認できるHTMLを求められた。

## 決定

「製品→業務支援→見積管理／契約管理」という3階層のナビゲーションを用意する。通常のnavと開閉ボタンを使い、階層を2回開き、末端リンクを実行してローカルの目的ページへ移動する。

2.1.1にキーで途中の階層を開けない例、2.1.2に第3階層から抜けられない例、2.4.3に展開後のフォーカスが本文へ飛ぶ例を追加する。それぞれに正常な対照を置き、計6ケースとする。素材は基準ごとのpublic内で完結させる。各suiteの版を2へ進め、既存ケースの期待結果は保持する。

確認手順には正方向の到達だけでなく、Shift+Tab、Escapeによる親への復帰、後続の操作への移動、実際のリンク先への到達を含める。論理部品の対象名と細部の指摘位置は既存のtarget_aliasesで対応させる。

## 代替案

初期表示でTab順だけを見る例では、未展開の子階層を試せない。表示の成功だけを期待結果にすると、フォーカスが別の場所へ飛ぶ問題を捉えられない。検証器側の探索・検出実装を同時に変更する案は、まず間違いのテスト入力を整えるという利用者の指定を超える。

## 影響

計182ケース・190ページ分の入力・191期待結果となる。WCAGが3階層を必須にするという意味ではなく、今回のナビゲーションの再現条件として扱う。矢印キーを前提とするARIA menubarとは区別する。検証器・採点器・過去の実行記録は変更しない。

## 検証方法

実ブラウザーで、初期状態からポインターや試験側からのDOM focusを使わずキーだけで3階層へ進む。正常例ではリンク先到達と逆方向の移動を確認し、問題例ではキーだけで止まる場所・循環・フォーカスの飛び先を記録する。途中のキー・activeElement・展開状態・URLを原始記録として保存する。問題例のポインター経路も確認し、ページ自体の故障と区別する。これらはテスト入力の確認で、検証器による検出件数には加算しない。
