# 0021 リポジトリの開発タスクを整理するスキルを.agents/skillsへ置く

日付：2026-11-18 / 状態：Proposed

## 背景

[ADR 0020](0020-parallel-development-tasks.md)で開発計画を個別タスクへ分解した。今後は依頼や実測から新しい作業が生じるため、既存タスクとの重複、依存関係、担当範囲を確認して追加・分割・統合する手順が必要である。利用者から、開発用スキルを`.agents/skills/`へ作成する依頼があった。

## 決定

[wcag-dev-tasks](../../.agents/skills/wcag-dev-tasks/SKILL.md)を、このリポジトリ専用の開発スキルとして作る。ロードマップ、設計、タスク文書、必要な検証記録を読み、依頼の範囲でタスクと索引を整える。配布用`skills/`の4スキルとは別に置き、機械検査の共通リソースや実装スナップショットへ含めない。

SKILL.mdの`disable-model-invocation: true`と、`agents/openai.yaml`の`policy.allow_implicit_invocation: false`を設定し、明示呼び出し専用にする。`$wcag-dev-tasks`で計画の追加・整理を依頼できる構成にする。タスク計画だけの依頼では、開発の実行や担当セッションの起動を行わない。

追加理由を明記し、重複する未完了作業は既存タスクへまとめる。分割・統合では元のIDと経緯を残し、前提と合流条件を含む依存関係を更新する。採番は既存番号の次から行い、3桁を超えても継続できる。観察可能な完了条件、共有するコード・操作環境、引き継ぎ事項を持つテンプレートを同梱する。

補助プログラムは追加せず、指示とテンプレートで始める。スキルはリポジトリ内の文書へ相対参照するため、単独配布用とは扱わない。今回の作成は[T015](../tasks/T015-development-task-skill.md)に記録する。

## 代替案

任意の`dev-skills/`へ置くと、Codexで利用する前に別途登録が必要になる。配布用`skills/`へ置くと、利用者向けの検証スキルと開発用の計画管理が混在する。AGENTS.mdにすべての手順を入れる方法は、通常の開発でタスク整理が不要なときにも詳細を読み込むため採用しない。

自動実行やチャット作成までまとめると、計画と実施の範囲が広がるため今回は含めない。専用のタスク生成プログラムや汎用スキーマは、繰り返し使って必要性が分かってから検討する。

## 影響

このリポジトリを開いた環境で、開発タスクの追加・整理を明示して依頼できる配置になる。既存の14タスクの状態と、機械検査から進める開発順序は維持する。タスク整理の手順が正しく判断できるかと、ホストが実際にスキルを読み込むかは別に確認する。

既存の簡易スキル検査器は`disable-model-invocation`を未対応項目として拒む。拡張を残したまま結果を記録し、YAML、参照先、タスクと索引、依存関係を確認する。過去のADR、判定、原始証拠は変更しない。

## 検証方法

SKILL.mdとagents設定をYAMLとして確認し、必須情報と明示呼び出し設定、テンプレートと参照文書が揃うことを確認する。タスク一覧のID、参照、開始条件と合流条件を含む依存関係に循環がないこと、既存14タスクが不変であることを確認する。共通リソースの同期と差分を確認する。スキル手順の机上確認と静的検査の結果、実ホストの呼び出しや独立したAIによる判断が未実証であることを[T015の記録](../../validation/development/T015/README.md)へ残す。
