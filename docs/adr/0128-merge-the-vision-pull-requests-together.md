# 0128 検証した組み合わせでVISIONのPRを取り込む

状態はAccepted。

## 背景

PR #86〜#115には、先行PRに重ねた実装、同じ変更を含む統合、個別の試験と証拠がある。T037の統合とT040の探索順の調整は、同じ操作後の処理に変更を加えた。両方の動作を同じ配布版で確認する。[統合PR #111](https://github.com/k-s-h-r/wcag-audit-kit/pull/111) · [T037の判断](0121-verify-follow-up-workflows-together.md) · [T040の判断](0124-prioritize-observed-nested-escape.md)

## 決定

既存の統合PR #111に各PRの元のコミットをマージする。正常に操作できた分岐で、T033が使う離脱前の状態の照合と、T038が使う子ダイアログの閉鎖証拠の保存をそれぞれ行う。T040の探索順の調整と既存の再検査・採点を同じ配布版に置く。

## 代替案と影響

PRごとに競合を解消する方法では、先行変更を含む統合PRとの重複を途中の版ごとに確認する必要がある。既存の統合PRにまとめることで、最終版を一度に検証してから取り込める。元のコミットと各試験の記録は履歴からたどれる。

## 検証

対象のPRすべての元のコミットと証拠ファイルを確認し、配布スキルの同期、Pythonの単体試験、同じ76ページ・87行の通常CLIでの検査と採点を行う。子を閉じた証拠、従来の離脱と間隔の採点、表示や操作の未確認も照合する。[統合時の試験](../../validation/development/vision-follow-up/README.md#mainへの統合)
