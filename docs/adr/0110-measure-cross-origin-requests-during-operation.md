# 0110 操作に伴う別オリジンへの通信を受信側で照合する

状態：Proposed

## 背景

起点URLから画面を操作して検証する場合、操作への反応として通信が発生する。`page-audit` は書き込みメソッド、WebSocket、別文書への移動を制限する。操作中の読取が取得先に届くかは、同じ実行で送出・受信の記録を照合して確かめる必要がある。[Issue #82](https://github.com/k-s-h-r/wcag-audit-kit/issues/82)

## 決定

同一ホスト上の異なるポートで、検査対象と別オリジンの受信先を作る。通常の `page-audit` と、明示的にHTTPプロキシを通す `page-audit` をそれぞれ新しいrunで実行する。後者は対象オリジンへの読取だけを許可する。受信側のログ、プロキシの記録、探索台帳のキー・クリックと表示結果から、通信の有無と検査に必要な情報の欠落を調べる。

## 代替案と影響

ブラウザーの要求イベントだけを保存すると、要求を作った時点と受信先で処理した時点が混ざる。受信側のログを併用する方法は、許可と拒否を別に比較できる。今回の環境ではネットワーク名前空間を作る `unshare -Urn` が `/proc/self/uid_map` の書き込み権限で止まった。OSレベルの制限とブラウザー以外の通信には別の実証が要る。

試験用プロキシはループバックで待ち受け、実行中のローカル対照だけに転送する。別オリジンのデータが必要な機能を制限すると、通常の条件と同じ表示を得られないことがある。

## 検証

初期表示の画像、操作後の読取・画像、HTTP転送後の読取、書き込み要求、WebSocketを同一の対照で試す。別オリジンの受信件数、対象オリジンへの同一オリジンの読取、両幅の表示状態を照合する。[T031の実測](../../validation/development/T031/README.md)
