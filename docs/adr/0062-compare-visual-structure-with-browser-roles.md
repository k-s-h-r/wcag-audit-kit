# 0062 見た目の構造をブラウザーの役割と照合する

日付：2026-11-19 / 状態：Accepted

## 背景

1.3.1の検査では、見出しやリストに加え、見た目で分かる表の関係がブラウザーにも伝わるかを確認したい。従来の候補は `p` と限られた箇条書き記号が中心で、表の行・列の関係は出力できなかった。[Issue #29](https://github.com/k-s-h-r/wcag-audit-kit/issues/29) [W3Cの1.3.1解説](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)

## 決定

既存の `visual_structure_scope` を使う。見出し候補にはテキスト主体の `div`、リスト候補にはハイフン等の箇条書きと番号が続く例を追加する。表候補は、セルの矩形が行と列でそろい、太字の先頭行と通常の後続行を持つ3〜8行・2〜6列のまとまりとする。ブラウザーが認識した表・行・セル・列見出しの役割と、同じ表と行に所属するかを照合する。

役割が一致しない候補は、HTML・Excelの「見た目の構造の確認候補」に出す。セレクター、表示文言、認識された役割、元の証拠を対応付ける。JSONには表の行とセルごとの役割も残す。

## 代替案と影響

利用したタグ名で判定すると、同じ構造を伝えるARIAを見落とす。矩形の整列だけで表と判断すると、カードなど目的の違う配置も含まれやすい。表示上の手掛かりとアクセシビリティツリーを照合し、意味の確認が必要なものを候補にする。結合セル、複数段の見出し、行コンテナーのない配置などは追加確認の範囲とする。

## 検証方法

`python3 tests/visual_structure_probe_browser.py --out <新しい出力先>` を実行する。同じ見た目の装飾だけの表、HTMLの表、ARIAの表を比較する。見出しセルの役割が一つ不足した対照は、そのセレクターと認識された役割を確認する。見出し、連番・記号のリスト、カードとの対照、ページ別HTML・JSON・Excelと後続の検査票も照合する。
