# 0022 「進めて」でタスクの選択・実行・後続整理を進める

日付：2026-11-18 / 状態：Proposed

## 背景

[ADR 0021](0021-development-task-skill.md)でタスク整理用スキルを作成した。利用者はタスクの選択と作成もAIへ任せ、「進めて」という依頼だけで開発を継続したいと考えている。実行手順、前提待ちの扱い、後続タスクの追加条件、終了と再開の単位が必要になった。

## 決定

`.agents/skills/`へ[wcag-dev](../../.agents/skills/wcag-dev/SKILL.md)を追加し、既定で1作業単位を選択・再開し、実装・検証・記録・PR作成まで進める。後続の整理が必要ならwcag-dev-tasksを内部手順として読む。タスクが尽きた場合は目標との差から次の最小作業を追加し、開始条件が揃えば実行する。

前提待ちで開始可能なタスクがない状態を、タスクが存在しない状態と区別する。PR待ち、担当競合、環境不足があれば具体的に記録し、独立した作業を探す。完了と採用の根拠、検証能力の達成を分け、マージだけで未実施を通過にしない。

SKILL.mdとagents設定で明示呼び出し専用を維持する。AGENTS.mdで、このリポジトリの開発を継続する「進めて」「続けて」は同ファイルを読んで適用すると定める。通常の相談からホストの自動選択で開発を開始する構成にはしない。

1作業単位を終えた時点で後続と再開情報を保存する。新しい常駐処理やユーザー所有チャットの自動作成は加えない。「進めて」だけでPRをマージする権限は付けず、現在のマージ規則を維持する。実行上限等が明示された場合は、その範囲に従う。

今回の作成は[T016](../tasks/T016-autonomous-development.md)に記録する。PR状態を確認したT015は、配置・静的確認の作業がmainへ採用された状態に更新し、未実証のホスト動作は残す。

## 代替案

タスク整理用スキルへ実装・検証まで含めると、計画だけの依頼でも実行する境界が曖昧になる。AGENTS.mdへ詳細をすべて入れると、通常作業でも長い手順を読むことになる。タスク追加と実行を無制限に繰り返す方式は、1回の依頼と目標に対する作業範囲が分かりにくいため採用しない。

## 影響

利用者は毎回タスクIDや担当を選ばず、開発を進められる。作業を選ぶ際に現在のPR・採用状況を確認する必要がある。進捗は既存のタスク文書とロードマップに残し、別の管理基盤は追加しない。配布用の検証4スキル、既存の測定条件と証拠は保持する。

実ホストのスキル選択、実環境での長期運用、マージ操作は今回の検証とは区別する。簡易スキル検査器のfrontmatter拡張への未対応は記録し、設定を削除して通過させない。

## 検証方法

YAML、参照先、タスクID、前提・合流条件を含む依存関係、共通同期、差分を確認する。隔離した一時リポジトリで、作業が尽きた場面と前提待ちの場面を、独立したAIに同じ手順で進めてもらう。結果と生成物、環境上の制約は[T016の確認記録](../../validation/development/T016/README.md)へ残す。実GitHubへのPR作成・マージを隔離試験で実施したとは扱わない。
