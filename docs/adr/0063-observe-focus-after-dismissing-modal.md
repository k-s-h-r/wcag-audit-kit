# 0063 Escapeでダイアログを閉じた後のフォーカスを追う

日付：2026-11-19 / 状態：Accepted

## 背景

自動探索はモーダルでEscapeを試していた。閉じた直後が開く前と同じ状態にまとまる場合もあり、操作後のフォーカスの位置を帳票から追いにくかった。[Issue #4](https://github.com/k-s-h-r/wcag-audit-kit/issues/4)

## 決定

既存のEscape経路で、主文書のモーダルを開いた実入力、Escapeの前後、同じ要素に戻ったかを記録する。閉じたことを確かめた場合は、探索の上限内で同じ経路を別のブラウザーコンテキストに再生してTabを送る。証拠には実入力とフォーカス先を残す。Tabで移動しなかった場合、再生前後の状態を確かめられない場合、別モーダルへ移った場合は保留する。更新待ちのタイマーが残る場合も既存のEscapeを試し、その後の判定とTabは保留する。

## 代替案と影響

Escapeに続けて同じ経路内でTabを押すと、閉じた直後に保存する画面の状態が変わる。Tabを別の経路として記録し、両方の画面と操作を追えるようにする。フォーカスが開く前と別の位置へ移る場合はその位置を示し、適切かは手続きの文脈を確認する。複数のモーダル、別文書、閉じるボタンでの復帰は追加確認の範囲とする。[WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

## 検証方法

`python3 tests/dialog_focus_browser.py --out <新しい出力先>`。開いたボタンに戻る、別の位置に移る、Escapeを受けても開いたまま、開いたボタンが同じIDの別要素に置き換わる例を比較する。復帰しても次のTabで動かない例と、タイマーが残っていてもEscapeを試す例も確認する。信頼済み入力、閉じた直後と次のTabの移動先、HTML・JSON・Excelを照合する。
