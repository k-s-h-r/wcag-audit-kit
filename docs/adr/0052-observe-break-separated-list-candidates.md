# 0052 改行で並べた箇条書きを確認候補に含める

日付：2026-11-19 / 状態：Accepted

## 背景

中黒で始まる段落を並べたリストは候補にしていた。1つの段落に `br` で項目を並べると、同じ見た目でも候補が出なかった。[Issue #29](https://github.com/k-s-h-r/wcag-audit-kit/issues/29) [W3Cの手法 H48](https://www.w3.org/WAI/WCAG22/Techniques/html/H48)

## 決定

指定領域の直下にある段落のうち、テキストと `br` で構成されるものを調べる。同じ `・` または `•` で始まり、各項目が1行で表示される連続3行以上に、段落のセレクター、行番号、表示された文言と位置を記録する。既存の段落ごとのリストと同じ配置の条件を使う。

Chromiumのアクセシビリティツリーで段落の役割を1回照合し、候補と証拠をページ別帳票と後続の作業票に渡す。段落全体が一つの `listitem` でも、目で見える複数の行がそれぞれリスト項目として伝わるかは検査票で確認する。

## 代替案と影響

DOM上の中黒の数だけで探すと、本文中の語句や、折り返して表示された文も候補に入り得る。明示した改行、ブラウザーで測った位置、既存の範囲・観察時間の上限を使う。2行以下、装飾で生成した記号、入れ子の要素がある段落、表示範囲外の行は追加確認に残る。

## 検証方法

`python3 tests/visual_structure_probe_browser.py --out <新しい保存先>`。同じ表示のネイティブリストと、ARIAで一項目にまとめた段落を比較する。本文中の中黒、2行、折り返し、画面に出ない行、先頭がそろわない行も比較する。通常の機械モードでJSON・HTML・Excelと後続の作業票へ1.3.1の観察が渡り、達成基準の判定が未実施のまま保持されることを確認する。
