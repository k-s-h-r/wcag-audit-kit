# 0028 追加表示の操作とフォーカス先の覆いを実際の画面状態で確認する

日付：2026-11-19 / 状態：Accepted

## 背景

通常の探索はホバーで開いた状態やフォーカス位置を記録できる。追加表示へポインターを動かした後や、フォーカス先がバナーに覆われた状態の機械結果は出していなかった。現行版に既存の1.4.13と2.4.11の正常例と問題例を4ページずつ渡したところ、8ページすべてで該当する機械結果は0件だった。

## 決定

1.4.13にはトリガーと追加表示を明示するホバー経路を加える。ブラウザーで入力を送り、最大64点の実入力で追加表示へ向かう経路をたどり、その間の表示と、Escapeを押して閉じられるかを個別に記録する。表示を開けない、入力や移動先を確認できない、またはページ移動などで途中停止した場合は観察を保留する。Escape以外の解除手段、例外、持続時間、フォーカスだけで開く表示は追加確認に残す。[W3C 1.4.13の解説](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)

2.4.11には指定したキー経路の最後に、フォーカスがある部品を前面の要素が覆うかを測定する条件を加える。実キーの記録と対象へのフォーカスを確かめ、矩形、表示領域、前後関係、不透明な塗りを照合する。測定は主文書内の、描画を確かめられる状態が対象となる。フォーカスを進めずにユーザーが開いたコンテンツを閉じられるかは別の確認に残す。[W3C 2.4.11の解説](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)

両方とも、指定した状態と手順で見つかった機械結果を、対象と証拠を含めてページ別のJSON・HTML・Excelへ出す。達成基準の検査票は別に判定する。途中停止した経路は探索キューに従って再開できる。

## 代替案と影響

CSSやDOMの属性だけからホバー動作を推測すると、JavaScriptが反応する操作や実際に入れる範囲を見逃す。ポインターの当たり判定だけでフォーカス先の覆いを決めると、透明な要素や当たり判定を持たない描画を誤って扱う。そのため、どちらも状態を作って実測し、根拠の足りない観察は保留する。指定がないページでは通常の探索を行う。検査実装が異なるrunを再開する場合は新しい保存先を使う。

## 検証方法

`python3 tests/dynamic_visual_paths_browser.py --out <新しい出力先>`で、Chromiumによる8ページの操作、曖昧な表示の保留、途中停止と再開、原始入力、3種類の帳票を照合する。既存のキーボード経路も再試験する。

既存8ページの12観察では、正常6件と問題6件を区別した。追加の5試行では、ポインターを一度で移すと飛び越える隙間で表示が消えることを確認した。半透明・ポインター入力を受けない前面要素・領域外まで広がる枠画像・対象を確認できない例は保留した。画像をすべて取得するモードでは、フォーカス部品の測定時の画面が証拠に残ることも確認した。
