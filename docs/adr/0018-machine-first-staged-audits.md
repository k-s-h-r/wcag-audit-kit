# 0018 1ページの機械検査から、対象範囲と検証手段を段階的に広げる

日付：2026-11-18 / 状態：Proposed

## 背景

[ADR 0017](0017-autonomous-audit-development.md)では、最初の作業を3基準のAI検証の実測とした。利用者から、まず指定の1ページで機械が正しく判断できる範囲を固め、AIによる意味判断や実スクリーンリーダーへ順に進めたいという方針が示された。自律的なURL収集・一覧化と、評価事業者が行うような試験の選定・実施・報告も必要である。

現在のmachine既定と[モード仕様](0010-selectable-verification-modes.md)は、機械検査を先行する方針と整合する。指定URL一覧の利用と初期リンクの収集も既にある。これらを評価しながら利用範囲を広げ、追加の手段が必要な観点へAIや実スクリーンリーダーを使う。

## 決定

[開発計画](../ROADMAP.md)を、1ページの機械検査、指定URL一覧の検査、URL収集、AIの意味判断、実スクリーンリーダー、サイト・アプリ全体の試験の順に更新する。0017の最初の実測対象を変更し、同ADRの引き継ぎ方法と証拠を保持する方針は継続する。過去のADR本文は変更しない。

次の作業はmachineでの小さな基準値測定とする。1.1.1-01のimage-altに対応する機械ルールと2.4.2-01のタイトルの存在確認について、対象行を先に固定する。現行CLIには観点単位の実行フィルターがないため、基準単位の収集結果から対象範囲を集計する。意味判断、未探索、取得照合の未接続等は別に記録し、基準全体の適合とは扱わない。

実行時は各ページ・状態の機械検査を先に進め、残る確認に必要な証拠と手段を割り当てる。AIが見つけた新しい状態には機械検査を適用する。スクリーンリーダーの検証は、対応環境での実操作と発話を必要とし、AIモデルの性能だけで代替しない。各段階の追加費用と解決件数を測る。

機械で扱える全観点の実装完了を、以後の開発の前提にはしない。選択範囲で安定した検査を、URL一覧と基本的な巡回へ適用する。高度な探索や判断を必要とする対象は、その後の段階で拡充する。

サイト全体の試験では、[WCAG-EM 2.0](https://www.w3.org/TR/2026/NOTE-wcag-em-2-20260723/)を参考に範囲・対象一覧・選定理由・操作過程・結果を記録する。URL候補と実際の試験対象を区別し、未検査範囲へ適合の主張を広げない。

## 代替案

最初からAIと実スクリーンリーダーを含む全体検証を改善すると、機械検査の誤りと追加手段の誤りを切り分けにくい。全機械検査の実装完了まで他の開発を止めると、既存機能を複数ページへ使う評価も遅れる。検証手段だけを段階化すると、URL選定やサイト単位の試験工程が計画から漏れるため、対象範囲を広げる順序も明記する。

## 影響

最初の実測を小さく始め、安定した検査を複数ページで使える。追加のAI処理や実スクリーンリーダーの費用は、解決した観点とともに評価する。

今回の変更は文書のみで、機械検査の精度やURL探索能力を新たに実証したものではない。モードを変えて追加検証する場合は別runとし、最初からai・fullを選んだrunでは、その範囲で機械検査から順に進める。別runの証拠の再利用は対象・状態・環境・版と出所を確認する今後の実装課題とし、既存の判定・スナップショット・原始証拠は変更しない。

## 検証方法

ロードマップの次の作業がmachineの2観点の実測になり、段階別の成果物と完了条件を読めることを確認する。現行のモード、URL選定、採点、取得観点の仕様と照合する。ADR 0017が不変であること、変更した文書のリンク・ADR索引・番号・必須項目・差分を確認する。機械検査・AI・実スクリーンリーダーの実測は次の開発へ残す。
