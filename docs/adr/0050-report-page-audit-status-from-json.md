# 0050 帳票の出力と検証の完了を報告JSONで確認する

日付：2026-11-19 / 状態：Accepted

## 背景

隔離したCodexで公開モデルを使い、指定した1ページをChromiumで機械検査した。CLIはHTML・JSON・Excelを出力した。モデルは同じ回で`page-report`も呼び、達成基準の判定がまだ0件の状態で検証完了と回答した。保存済み結果だけを出力する別の依頼でも、帳票は生成されたが、回答は検証完了とした。[T004](../tasks/T004-codex-invocation.md)

## 決定

`wcag-page`は、初回と再開の`page-audit`が返した帳票を機械検査の結果として案内する。判定の追記を反映する場合や、保存済み結果から帳票を作り直す依頼では`page-report`を使う。`wcag-page`と`wcag-report`は報告JSONの`audit_complete`を確認し、`false`の場合は利用者への回答で検証が未完了と伝える。機械ルールの指摘は対象箇所とルールを添えて示し、達成基準全体の判定には保存された判定を使う。

## 代替案と影響

機械検査の直後に毎回`page-report`を呼ぶと、同じデータからExcelがもう一つ生成される。実行結果の終了コードだけでは、未実施の検査票や探索が残っているか分からない。既存の帳票と完了フラグを利用するため、CLIや保存形式の変更は不要。利用するホストでは、JSONまたは同じ状態を返すツール出力を確認できる必要がある。

## 検証方法

Codex CLIとChromiumを置いた外部ネットワークなしのコンテナに、ループバックの対象ページと対象外のリンクを用意する。明示した1ページの検査、別セッションからの保存済み報告、親手順からの子手順の読み取りを行う。通信、コマンド実行順、帳票の内容、再出力の前後で保存済み証拠のハッシュ、モデルの最終回答をそれぞれ照合する。ホストの本文展開は`python3 tests/codex_skill_dispatch.py`でも確認する。ローカルモデルの実行結果と適用範囲は[T004](../tasks/T004-codex-invocation.md)に記録する。
