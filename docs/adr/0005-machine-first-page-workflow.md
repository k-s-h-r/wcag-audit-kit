# 0005 1ページの機械検査と状態探索を先行させる

日付：2026-11-15 / 状態：Proposed

## 背景

Issue #4の最優先は1ページの検証と人に分かる出力である。サイト全体への展開は後にする。人の介入とAIの判断への依存を減らすため、実行可能な機械検査を先行させる必要がある。[0003](0003-modular-skills-and-inspection-profiles.md)では状態の調査を主にスキルへ委ねていた。[0004](0004-human-checksheet.md)の帳票にも、機械で取得した事実と基準全体の適否を区別して示す必要がある。

## 決定

page-auditを追加する。指定1 URLで実クリック・hover・キー・入力による経路を試し、開閉・選択・入れ子等の状態をキューから探索する。状態の内容・属性・値・表示スタイルで同一性を比較する。各経路を独立したブラウザーコンテキストから再生し、同じ状態へ達した別の入力経路も記録する。

探索で実際に収集した状態をcapture-manifestと検査計画へ追加する。事前設定のstatesを書き換えず、設定・カタログの版と過去の証拠を保持する。探索キューと証拠ハッシュはexploration.jsonへ保存する。状態・経路・深さ・画像の上限に達したら残作業として示し、再開可能にする。探索セッションと台帳更新はロックで保護する。保存途中に停止した場合はcheckpointに含むmanifestから復元する。

状態ごとにaxeのWCAGタグ付きルールを実行する。実入力の到達・送出の結果も機械検査として表示する。LLMやAIサービスの接続なしで、探索・機械検査・帳票出力が動く。機械ルールの結果は達成基準全体の適否へ自動変換しない。原典の条件・例外・全対象について不足する確認を識別し、別の自動測定・実操作を進め、意味や目的等で必要な部分だけをAIや人の判断へ渡す。

page-nextは未完了票と該当する原典・手順・機械結果を小さな単位で返す。機械検査の未確定を直ちに人待ちへ変えない。必要な道具を実行する。探索で残った範囲の解消は、その版のgraph_digestと追加の観察・証拠に対応付け、別の履歴として保存する。未実行のキューは解消記録で消せない。

page-reportはページだけのHTML・JSON・Excelをrun直下へ生成する。証拠の相対参照を保ち、元のrun全体の出力を変更しない。既存のExcel交換形式と判定保存方式は保持し、新しい機械結果シートは閲覧用にする。人向けチェックシートでは機械検査の内訳と基準全体の判定を区別する。

## 代替案

- AIだけに全操作の探索を任せる方法は、繰り返しの操作・記録・漏れの追跡にAIを使い続ける必要がある。
- DOMやaxeの通過だけで基準全体を自動適合にすると、意味・状態・対象・例外の不足を見落とす。
- 全組合せを無制限に探索すると、動的な内容で終わらなくなる。上限と未実行キューを明示して再開する。
- 新しい状態が見つかるたびに全体を新規runで取り直すと、同じ証拠と判定の再作成が増える。同じ設定の実測状態を追加し、ビルド・設定・定義を変える場合は新しいrunを使う。

## 影響

主な入口を1ページにし、サイト全体の重複排除・並列運用は実装しない。既存page / startと過去のrunを保持する。事前設定statesの収集はpageを使い、自動探索には独自シナリオをprobeで追加する。イベントやカーソル等による候補の抽出には限界がある。画面、iframe・closed shadow DOM・canvasの内部、複雑なドラッグや外部環境などは、実行できた範囲と追加検査を明示する。機械検査の終了とWCAGの検証完了を区別する。

探索では送信・永続変更・別ページ移動を保留し、書き込みメソッド・WebSocket等を制限する。任意の本番サイトの副作用を防ぐ保証にはしない。必要な操作はテスト環境で明示した経路を別に実行する。実SR・実拡大を実行したことにせず、その証拠を別に求める。

## 検証方法

機械ルールの通過が基準全体の通過にならないこと、未実行キュー・残る探索・部分的な判定が完了を妨げること、証拠改変・古い解消記録の拒否、ページ別の出力範囲を試験する。所有する1ページでアコーディオン・入れ子・コンボボックス・モーダル・クリック可能なdivを実操作する。中断・再開、既存証拠の保持、別ページへ巡回しないこと、書き込み通信を受信しないことを確認する。HTMLとExcelを読み戻して機械結果・未確認を照合する。任意のサイトの完全な状態網羅、実SR・実Excelアプリの動作を今回の試験から保証しない。
