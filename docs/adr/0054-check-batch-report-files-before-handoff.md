# 0054 バッチの帳票を台帳と照合してから案内する

日付：2026-11-19 / 状態：Accepted

## 背景

隔離したCodexで子の実ファイルを読み、確定済み2 URLのバッチと帳票生成を確認した。最終回答が時間切れだったため、別の試行で出力形式にHTMLパスの配列を指定した。その試行は終了コード0でJSONを返したが、ツール呼び出しは0件で、返されたパスのファイルは存在しなかった。[T004](../tasks/T004-codex-invocation.md)

## 決定

`page-batch`の案内には、`page-batch.json`で対象URLに対応する処理状況と帳票の記録を使う。完了した行は、バッチ保存先を基準に`reports`のパスを解決し、ファイルの実在を確かめて渡す。未着手・中断・失敗は台帳の処理状況を、検証の完了はページ別報告JSONの`audit_complete`を伝える。

## 代替案と影響

JSON形式を指定すると機械で応答を読み取りやすい。生成したパスの確認には、バッチの実行記録とディスク上の帳票が必要になる。既存の台帳と帳票を使うため、報告の案内に新しい収集や判定更新は発生しない。

## 検証方法

親の試行では、子手順の本文とファイルハッシュ、バッチのコマンド、HTTPリクエスト、URL別のHTML・JSON・Excelを照合する。構造化応答の試行はツール履歴と実パスを照合する。`tests/codex_skill_dispatch.py`で変更後の本文がホストの明示指定で展開されることを確認し、`tests/page_batch_browser.py`でページごとの処理状況と帳票を別の保存先に再現する。
