# 0068 1ページ検査の初期結果を先に返す

日付：2026-11-20 / 状態：Proposed

## 背景

単独ページの検査では、初期画面のaxeが終わっても、操作探索が区切られるまで帳票を返さなかった。確認したページでは、リンクの中の文言などにも操作候補を作り、状態が変わるたびに組み合わせが増えた。[ADR 0005](0005-machine-first-page-workflow.md)の機械検査を、初期画面の報告と必要な操作探索に分ける。

## 決定

- 直接の `wcag-page` では `page-audit --initial-only` を使い、環境ごとに初期画面のaxe・DOM・設定済みの初期画像を保存する。初期段階は操作キューの組み立て、Tab入力、診断スクロールを保留し、初期結果と操作探索が未実施であることを返す。
- 操作探索の依頼を受けたら、同じrunを `--resume --explore` で進める。初期証拠を読み、操作経路を作り、各環境のTab・スクロールと追加の状態を観察する。既存の初期証拠を保持し、追加結果は同じ帳票に反映する。初期収集の途中停止は `--resume --initial-only` で再開できる。
- リンクやボタンの中でポインターのカーソルだけを親と共有する要素は、その部品にまとめる。明示的な役割・Tab停止位置・イベントがある要素、独立したポインター候補、汎用の委譲先の候補は残す。根拠が明確な候補を、カーソルだけの候補より先に試す。
- Chromiumの内蔵エラー画面は探索結果から除外し、実ページを確認できなかった経路として残す。

## 代替案と影響

初期画面用と操作探索用に別runを作ると、同じ初期状態の取得・帳票・判定が重複する。同じrunで段階を管理し、初期証拠を残す。補助CLIの従来の呼び出しとバッチ処理は、従来のように操作探索も実行する。以前のcheckpointsを報告に使うときは保存済みの意味を保つ。実装の異なる中断runには従来の実装照合が適用される。

カーソルの検出を一律に省く案では、DOM上の役割がない実際の操作対象を取りこぼすため、根拠を確認できる重複に限ってまとめる。初期結果だけでは操作後の状態は未確認のままになる。

## 検証方法

ローカルのChromiumで、初期結果がPC幅とスマホ相当の幅を各1回読み込んで生成され、探索キューとキー入力がないことを確認する。同じrunで初期証拠のハッシュを照合し、明示的に探索を始めて初めて出る画像の代替テキストの問題を確認する。リンク内の文言、独立したイベント、ポインターだけの部品、委譲イベントの対象を同じページに置き、候補として扱う範囲を照合する。
