# 0078 同じ画面に到達してもキーボード操作の続きを調べる

- 日付 2026-11-20
- 状態 Proposed

## 背景

[T017](../tasks/T017-url-only-exploration.md)の3階層メニューでは、クリックでもEnterでも同じ状態に到達した。先に到達したクリックからは次の操作を探索した。Enterの続きは、画面状態が既出だったため候補に入らなかった。

## 決定

実キーが対象に届き、`aria-expanded` が `false` から `true`、または `details` が閉から開へ変わったことを確認した場合に、キー経路を続ける。新しく操作できるようになった開閉ボタンのキー入力と、開いた直後のTabを候補へ入れる。画面状態が既出の場合には、この候補だけを追加する。起点の環境、到達した画面状態、開いた要素、実際のフォーカス先が同じなら、続きを一度だけ作る。

簡易探索は、画面幅ごとの進捗を揃えながら、開いた部品のキーボード経路を優先する。既存の深さ・経路数・ステップの上限を使う。開いた後とTab後のフォーカスを操作の記録やページの機械検査欄から追えるようにする。公開Shadow DOMでは内部の実際のフォーカス先を記録する。

## 代替案と影響

クリックとキーの経路ごとに状態を重複収集すると、同じ画面のaxe検査や画像取得が増える。画面の状態は共用し、開いたことを実入力で確認できた場合に必要な操作だけを追加する。フォーカスは観察結果として記録する。ページ内でどの順序が適切かは目的に応じた確認が必要になる。

## 検証方法

`python3 tests/keyboard_opening_browser.py --out <新しい出力先>` で、問題集の3階層メニューを確認する。正常例ではEnterを2回送り、Tabで第3階層のリンクへ移動する。問題例ではメニューが開いても本文へフォーカスが移る。どちらもクリックが先に同じ画面へ到達すること、両幅でキーだけの経路を記録すること、画面を重複保存しないことを照合する。 `benchmarks/url_only.py` で既存8ページも再試験する。

レビュー後は公開Shadow DOM内の開閉ボタンとその中の項目を、開いた直後とTab後に区別できることを両幅で確認した。
