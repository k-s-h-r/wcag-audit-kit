# 0111 日付選択とエラー修正を同じ予約で確かめる

状態：Proposed

## 背景

予約の起点からの操作、空き状況の識別、入力エラーの発話はそれぞれ別の対照で実証した。VISIONで例に挙げた利用場面を実際の順序で検査するには、日付を選んだ後もその日付が失われず、入力の間違いを直して確認画面に進めるかを、証拠で追える形にしたい。[T022](../tasks/T022-url-to-process-audit.md) · [T026](../tasks/T026-process-error-speech.md) · [T029](../tasks/T029-audit-availability-without-color.md)

## 決定

閉じたメニュー、日付の選択、人数入力、確認の4ページをつないだローカル対照を用意する。両例の画面と操作は同じとし、人数のエラー通知を公開するロールだけを変える。別の検査担当による画面と公開アクセシビリティ情報の観察を行い、同じ対照の操作を実Orcaでも記録する。採点資料のハッシュを実行前に保存し、独立した観察結果を受け取ってから資料を公開する。

## 代替案と影響

個別のHTMLだけを使った試験は、表示・役割や発話の違いを小さく再現できる。今回の4ページを続けて操作する試験は、公開画面からの入口の発見、選択した値の引き継ぎ、実スクリーンリーダーでのエラー修正を追える。対照の範囲は試験ページで確認画面まで。対象の達成基準と手続き全体の適合要件は帳票上でそれぞれ確認する。

## 検証

起点だけを指定した通常の `page-audit` の操作結果、別担当による実ブラウザーでのキー操作の記録、実Orcaの発話ログを比較する。入力エラーの観察を標準の検査票と不適合箇所一覧に結び付け、どの環境を測ったかを残す。[検証手順と証拠](../../validation/development/T032/README.md)
