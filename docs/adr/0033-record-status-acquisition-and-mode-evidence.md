# 0033 操作後の状態取得とモードごとの実施記録を帳票へ出す

日付：2026-11-19 / 状態：Accepted

## 背景

4.1.3の問題集には保存操作後に表示が変わる例がある。通常の探索では保存操作を保留するため、初期表示だけでは取得の条件を照合できなかった。また、モードの対応表ではHTMLとExcelの列が異なり、対応できる観点とその回の実施記録を一緒に追いづらかった。

## 決定

4.1.3-01の指定ローカル例では、正解を含まない操作と対象を公開作業票に定める。保存済みのHTMLを独立したChromiumで再生し、指定位置の実クリックと、同じ文書・要素の操作前後の表示と役割を取得する。取得記録をページ・状態・ソースのハッシュ・実行にひも付けて保存する。追加通信を中断した場合、対象が変わる場合、証拠が一致しない場合は保留する。発話は実スクリーンリーダーで確認する。

HTML・Excelではモード対応表の列を共通化し、実行した範囲で保存された機械検査・画像と、実スクリーンリーダーの記録を併記する。対応表は準備や使える手段、実施記録は保存された証拠を示す。AIを使用したかどうかはモードの選択から推測しない。

## 代替案と影響

すべてのサイトで保存ボタンを自動探索に加えると、副作用のある操作が範囲に入る。既知の問題集を明示的に再生する範囲に絞る。DOMの役割を確認できても、発話の検査票への判定には使わない。新しい収集条件は問題集4.1.3の版に反映し、旧runの証拠は保持する。

モード選択を検査実施と同じ状態にすると、例えばSR併用を選んだだけで発話を確認したように見える。出力には実際に取得した記録と未実施を残す。既存の達成基準の判定手順を維持する。

## 検証方法

```sh
python3 benchmarks/run.py collect --mode machine --criterion 4.1.3 --out <新しい保存先>
python3 benchmarks/run.py score --run <同じ保存先> --strict
python3 tests/verification_modes_browser.py --out <別の新しい保存先>
```

Chromiumで2例とも「待機中」から「保存しました」への変化を記録し、アクセシビリティツリーの役割は`paragraph`と`status`だった。機械モードで取得2件が一致、発話4件は省略。SR併用を選んで発話を実行しない再測定では、発話4件は未確認だった。

4モードで各131観点の共通列・集計をJSON・HTML・Excelで照合した。実施記録では画像は順に0・2・0・2枚、発話はモード外または未実施だった。保存済み証拠を残したまま再開でき、モードを切り替えての再開は拒否された。
