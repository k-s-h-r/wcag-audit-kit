# 0014 テスト関連PRを集約し、全確認観点の入力と操作パターンを拡充する

日付：2026-11-17 / 状態：Proposed

## 背景

PR #7・#8・#10には採点基盤、全基準の代表例、3階層メニューの例が分かれていた。利用者から、これらをまとめ、追加パターンを拡充しきるよう指示があった。#9のスキル配置変更は独立させるよう明示された。現在は131確認観点のうち89観点の入力があり、取得する対象と判定する内容が一部混在している。

## 決定

テスト関連の3PRを#7へ集約し、#9は変更・取り込み・クローズの対象にしない。mainへのマージは行わない。既存のADRと証拠を保持する。

今回の拡充の完了条件は、全131確認観点に具体的な入力と期待結果があり、主要な操作パターンにも問題例・対照例・再現手順があることとする。無限にある全サイトの全状態の網羅を完了条件にはしない。入力の完成と検証器の実装・精度確認を区別する。

判定の観点には従来の期待判定を使う。画像候補の列挙、読み順、寸法、フォーカス経路等の取得の観点には、非公開のevidence_expectationsとして対象・状態・取得内容を記録する。取得できたことをWCAGの適合へ変えない。取得期待の照合器は未接続と明示し、未確認を別表へ残し、必要な取得期待を残した実行をクリアにしない。取得期待の対象一覧や期待値は検査担当へ渡さない。

入れ子のダイアログ、コンボボックス、タブ、Shadow DOM、iframe、狭い画面のナビゲーション、操作後の状態・サイズ・コントラストの変化、時間延長と保存、字幕・音声解説・手話等の素材を追加する。意味を確かめるためのメディアは、既知の生成元又はライセンスと意味の出典を確認した素材を使う。端末センサー、実SR、長期保持については、入力を用意したことと実機・実時間で検証したことを分ける。

レビューで指摘された相対パスの採点エラーと、操作後に移動するHTMLの欠落も修正する。静的なHTMLの参照だけでなく、記述が確定しているインラインの移動先も確認する。検出アルゴリズム自体の変更は含めない。

## 代替案

観点を列挙するだけの空のHTMLでは操作や観察を試せない。取得の成功を適合とする形式では、対象を見つけただけで検証済みと誤認する。専門的な素材を外見だけで適合例にしたり、仮想時計・合成イベントを実時間・実端末の確認と扱ったりすると、期待結果が信用できなくなる。#9まで同時に取り込む案は利用者の指定に反する。

## 影響

テスト入力と期待結果を先にそろえ、後から検出器を改善できる。判定の採点と取得の未確認は分けて報告する。素材の出典、条件、未実施の環境確認、独立した専門家による確認の不足を残す。既存ケースの変更が必要な場合は理由と新しい版を記録し、過去のrunは上書きしない。

## 検証方法

相対パスの問題を旧実装で再現し、修正後を確認する。全観点・必須パターンの入力が欠けると試験を失敗させる。公開ページと素材の参照、操作後の移動先、取得期待の形式、未確認を成功にしないことを検査する。実ブラウザーで操作・フォーカス・状態を記録し、仮想時間と合成センサーを使う試験は記録へ明記する。素材の内容・出典・ハッシュを保存し、旧証拠の不変を照合する。

実施結果と未確認事項は[全確認観点の入力と追加パターンの確認](../../validation/complete-fixture-patterns/README.md)へ保存した。
