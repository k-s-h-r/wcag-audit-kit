# 検査結果を記録する

1つのcaseは、ページ・状態・環境・達成基準の組合せ。caseの中で適用する全対象を列挙する。複数の検査手順が必要なら、それぞれを実施して記録する。

記入するキーは[結果例](../assets/judgment.example.json)を参照する。値は実際のcaseと観察から埋める。記入例の文章を実際の結果として流用しない。

## 必須の情報

- `case_id`、設定の`config_digest`、基準本文の`normative_sha256`。`case`コマンドから取得する。
- `execution`と`outcome`。未実行と判断保留を合格にしない。
- `steps_executed`と`tests_applied`。実際の操作と、使用した手順のID。
- `observed`。実際に観察した事実。AIが用意した方針や期待結果とは区別する。
- `targets`。実際の対象を識別する情報、期待結果、観察結果、対象ごとの結果、証拠。
- `evidence`。実行先内の実在する証拠ファイルへの相対パス。外部ツールの証拠は`attach`で取り込む。
- `conditions_reviewed`、`exceptions_reviewed`、`coverage_complete`。原典の条件・例外・全対象を確認した範囲。
- `method_coverage`。必要な観察方法ごとに、実施したか、今回不要と判断したか、その根拠。
- `remaining`。不足する対象・状態・判断、必要な環境・操作。
- `human_handoff`。人に必要な理由・試行・証拠・対象ごとの操作・判定条件。[引き継ぎの取り決め](human-review.md)に従う。

## 結果

| outcome | 意味 |
| --- | --- |
| passed | このcaseの適用対象と必要な条件を検査し、通過した |
| failed | 不適合を確認した。別に残る未確認も記録する |
| inapplicable | この範囲に適用対象がない等、条件を満たさない根拠を確認した |
| cant_tell | 対象・観察・判断等が不足している |

`execution`は`completed`、`blocked`、`not_run`。後二者のoutcomeは`cant_tell`にする。

passedでは全対象がpassedで、remainingが空であることが必要。必要な方法を実施できなかった場合はcant_tellにする。同じ条件を検査できる別の方法を使った場合は、元の方法を不要とした根拠と、実際に使った方法を記す。

基準に列挙された方法をすべて記録し、プロジェクト固有の追加方法も記録できる。例えば非HTML文書では、DOMの代わりに文書メタデータを取得した具体的な方法を追加する。追加方法があることを理由に、必要な観察を無記入にしない。

failedは不適合対象を少なくとも1つ含める。一件失敗しただけで他の対象を未検査にした場合はcoverage_completeをfalseにし、残る対象を列挙する。pendingにはこのcaseも残る。

inapplicableには対象不在等の証拠と、調べた範囲・条件を記す。設定で選ばなかったことや、操作環境がないことは対象外ではない。

## 証拠の注意

recordはファイルの存在、caseとの対応、ハッシュ等を確認する。しかし、画像を実際に見たか、内容の解釈が正しいかをソフトウェアだけで保証することはできない。AIは画面・媒体・原典を実際に確認してから記録する。

証拠は後片付け後も残す。変更・消失すると集計は失敗する。新しい判定は別ファイルに保存し、過去の判定を保持する。共有用には認証情報・個人情報を含めないよう整理する。

レポートの検証完了は、全予定caseに判断保留・未実施・対象の未網羅が残らず、サイトの範囲と適合要件の確認が記録されている場合に限る。不適合が残っていても、全対象を検証できたこととは両立する。検証完了とWCAG適合は同じ意味ではない。

## 媒体の区間別の比較

1.2.1〜1.2.9のpassed、又はfailedでcoverage_complete=trueとする場合は、適用対象ごとに`media_review`を記す。[ひな型](../assets/media-review.example.json)を実際の媒体と比較へ合わせる。

- source：実際の媒体・トラック・言語・代替を識別する。
- timeline：prerecorded又はlive_window。live_windowには実際の期間と範囲をwindow_descriptionに記す。
- duration：対象全長又は観察窓の長さを秒で指定する。
- comparison：この基準で何の情報をどの代替と比較したかを具体化する。
- intervals：start・end・statusの一覧。reviewedにはobserved・expected・evidence、not_reviewedにはreasonを記す。

recordは比較済み区間の抜け、末尾の不足、明示した未確認、不正な時刻を確認する。reviewedの証拠もrun内の実在ファイルとしてハッシュを保持する。時間の範囲が連続していても、その情報を実際に理解・比較した保証にはならない。内容・手話等を判断できる手段を確かめてから記す。

一部で不適合を確認したが全体は未確認の場合、coverage_complete=falseと残る検査を記録できる。区間別の状態はHTMLレポートと判定のJSONにも残す。収録済みの途中だけ、又はライブの観察窓を、媒体・配信全体の確認へ広げない。

## 定義を更新した後の報告

新しい実行では`catalog.snapshot.json`へ当時の定義を保存する。レポートはそのスナップショットと保存した判定・証拠から再集計できる。現在のスキルと定義が異なる場合は、そのことを表示する。再集計は再検査ではなく、新しい手順に通ったことを示さない。

定義を更新した旧実行へ、新しい判定・追加検査・範囲確認を混在させない。新しいrunで検査する。設定や保存した定義、別caseへの判定の差し替え、証拠の変化を検出した場合は集計を停止する。

旧実行にスナップショットがない場合は、インストール済みの定義と当時のハッシュが一致するときに限り、次で保存できる。異なる版の定義で穴埋めしない。

```sh
python3 scripts/audit.py snapshot --run /project/artifacts/wcag/run-001
```
