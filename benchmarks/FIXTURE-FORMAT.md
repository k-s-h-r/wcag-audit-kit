# 判定の期待結果と、取得の期待結果を分ける

全131確認観点のうち、114観点に判定の期待結果、17観点に取得の期待結果を用意しています。ページを見つける、画像を列挙する、フォーカス経路を記録するという作業の成功から、WCAGの適合は結論できません。

## 判定の期待結果

`expectations`には、ページ・状態・対象・確認観点ごとのpassed／failed／inapplicableと根拠を置きます。例えば、画像と代替文の意味が合うか、操作後に部品の展開状態が伝わるかです。

各行の `evidence_kind` に必要な証拠の種類を、`modes` にモードごとの `evaluate` または `defer` を記録します。機械検出対象の集計条件は `evidence_kind: program` と `modes.machine: evaluate` の両方です。実スクリーンリーダーが必要な場合は `screen-reader` を使い、必要な環境があればケースの `requires_environment` に記録します。検査手段の表示と集計は既存のフラグから生成します。

独立した画像やボタンに問題があれば、対象ごとに行を分けます。タブやダイアログのように1つの機能を構成する部品は、target_aliasesで論理部品へ対応させられます。関係のない部品の指摘をまとめて、正しい検出として数えないでください。

## 取得の期待結果

非公開の`evidence_expectations`には次の項目を記録します。

| 項目 | 内容 |
| --- | --- |
| checkpoint／page／state | 取得する観点と、どのページのどの状態か |
| kind | 対象列挙、フォーカス経路、表示幅、操作前後の状態、時系列、指定言語、名前・ラベル、サイズ・位置の種類 |
| targets | 見落とさず取得してほしい対象。対象なしが正しい対照では、empty_is_expectedを明示する |
| rationale | 何を取得する期待結果か、その根拠 |
| その他の項目 | 読み順、サイズ、名前、言語、区間、必要な画面等。その観点の既知の取得内容 |

例えば、間違った言語としてfrが指定された英文でも、取得結果は「指定値fr」です。その取得自体を不適合にせず、実際の言語との一致は別の判定観点で扱います。

取得期待にはpassed／failedを置きません。取得期待の照合器は今回未接続で、HTML・Excelには未確認の別表として出します。必要な取得期待が残ればstrictはクリアにしません。既存の判定の件数・精度へ混ぜず、提出時も取得の観点を適合・不適合として取り込むことを拒否します。

## 試験専用の操作と、検証器へ渡す操作

`fixture_probe`は、作成したページが意図した動作をするか確かめる試験用の操作とアサーションです。正解を含むため、検証器へ渡しません。通常の収集でこのprobeを実行して、検出器が正解したように扱うこともしません。

検証器へはstatesの再現手順、観点、使用するモード、必要な環境と公開ページを渡します。取得期待の対象一覧や値は公開タスクへ含めません。`acquisition_checkpoints`は判定と取得を区別するID一覧だけです。

`requires_environment`には、実SR、端末センサー、音声・手話の内容比較、実時間の保持等が必要な場合の条件を置きます。仮想時計で21時間進めた試験は、24時間という実装条件を通ることの試験であり、現実に21時間保持した実証とは分けます。合成センサーイベントや文字サイズの上書きも同様です。

## 追加後に更新する

```sh
python3 benchmarks/build_fixture_index.py
python3 benchmarks/build_fixture_index.py --check
python3 -m unittest discover -s tests -p test_benchmarks.py
```

索引には全131観点の入力と追加パターンの参照先を記録します。未収録の観点や必須パターンがあれば試験を失敗させます。既存の問題集と比較するときは、同じ版・同じ入力で再実行してください。
