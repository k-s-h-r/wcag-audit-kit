# 開発を次の作業単位まで進める

利用者はタスクIDや担当を選ばず、`$wcag-dev`又はAGENTS.mdで定めた「進めて」で開発を依頼できる。既定では1タスク、又は同じ成果物に必要な小さな作業一組を、実装・検証・記録・PR作成まで進める。タスクの提案だけで終了しない。案だけを求められた場合は案を返す。

## 現在の状態を復元する

リポジトリルートを基準に、[AGENTS.md](../../../AGENTS.md)、[開発計画](../../../docs/ROADMAP.md)、[タスク一覧](../../../docs/tasks/README.md)、関連タスクの引き継ぎと検証記録を読む。Gitの差分、作業ブランチとworktree、最新main、関連PRの状態を確認する。利用者の未コミットの変更を保持する。

今回の明示的な依頼と、進行中の作業への修正指示を優先する。一般的な継続依頼では、同じ目的の未完了作業を再開し、次にロードマップの優先順と後続を開く作業を選ぶ。新しいセッションでも、会話にしかない状態を前提にしない。

タスクの記述と実際のPRが食い違う場合は、PR・採用された変更・検証記録を照合して状態を更新する。PRのマージだけで、未実施の試験やG1・G2を成功にしない。マージ確認ができなければ確認不能として残す。

## 実行する作業を選ぶ

| 状況 | 次の行動 |
| --- | --- |
| 自分の作業に未完了の実装、失敗した試験、対応すべきレビューがある | 既存のブランチ・PRと記録から再開し、重複するPRを作らない |
| 前提が揃い、担当と資源が競合しないタスクがある | 目標に近い小さな作業を選び、具体的な担当範囲を記録して実行する |
| PRレビュー・マージ、別担当、環境や権限を待つ作業がある | その理由を残し、独立して進められるタスクを探す。未マージのコードをmainへ採用済みとして扱わない |
| 開始できるタスクがなく、前提待ちが残る | 待ちを整理し、既存タスクで扱える解消作業を確認する。待っているだけの作業を複製しない |
| 必要なタスクが尽き、目標に未達の範囲がある | 下記のタスク整理手順で、根拠のある次の最小作業を追加し、その開始条件が揃えば実行する |
| 目標を達成している | 根拠と残る制約を報告して終了する。作業を増やすためのタスクを作らない |

前提・合流条件はタスクの完了根拠から確認する。必要なコードが未マージなら、原則として独立した作業を先に進める。依存するPRを重ねる必要がある場合はbaseと依存先を明示し、合流条件の達成を先取りしない。

## 実行し、確認できた結果を残す

選んだタスクへ担当ブランチ・起点・成果物・使用する操作環境を記録する。作業ブランチと必要な別worktree・runを用意し、タスクの完了条件に従って作業する。方法が足りなければ小さく調査・実行確認して進め、同じ失敗を根拠なく繰り返さない。解消できない場合は具体的な不足を残し、既存の独立した作業があれば切り替える。

独立した調査や検証を補助エージェントへ分担する場合は、許可された資源、担当ファイル、操作環境、成果物を限定する。採番、同じCLI入口・採点器の編集、共有台帳や同じデスクトップの操作は調整担当が管理する。新しいユーザー所有のチャットを自動作成することには依存しない。

変更に必要なADR、試験、証拠と再現手順、担当ファイルの更新を揃え、結果を確認してPRを作成する。未実施や判断保留はそのまま記録し、環境不足と製品の問題を区別する。作業の完了、PRの採用、検証能力の達成を分ける。過去の判定・原始証拠・ADRは書き換えない。

PR作成や必要な確認ができない場合は、可能なローカル作業を終え、未作成・未確認を明示して再開情報を残す。作成していないPRのURLや未実行の試験結果を記載しない。マージは現在のAGENTS.mdに従い、通常の「進めて」をマージの許可として解釈しない。

## 後続を整え、次回へ渡す

作業中に見つかった不備と目標の未達範囲を確認する。追加・分割・統合が必要なら、[wcag-dev-tasks](../wcag-dev-tasks/SKILL.md)をファイルとして読み、この依頼の内部手順として適用する。利用者に子スキルを呼び出し直させない。既存タスクを具体化できる場合は新規作成せず、採番と依存関係を調整する。タスク追加を理由に、既定の1作業単位を超えて実装を続けない。

担当ファイルへ、状態、成果物、試験・証拠、PR、未確認、待っている相手や環境、次に行う具体的な作業を残す。段階や次の作業が変わる場合はロードマップも更新する。別の進捗台帳を増やさず、次のセッションが既存文書から再開できるようにする。

1作業単位のPRができたとき、目標を達成したとき、又は独立して進められる作業がなく人の判断・権限・外部状態を待つときに終了する。明示された実行上限がある場合はその範囲に従い、中断するなら途中のrunと再開条件を保存する。

最後に、今回進めたIDと結果、PR、追加・更新したタスク、未確認・待ち、次回の「進めて」で行う作業を簡潔に伝える。タスクIDや担当の選択を毎回利用者へ戻さない。
