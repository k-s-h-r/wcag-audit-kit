# T番号：具体的な成果物が分かる題名

状態：未着手。前提タスク：必要なID又はなし。親・関連タスク：ある場合に記載。

追加理由と根拠：依頼、開発計画の該当箇所、実測した問題、前提不足を記載する。参照した記録と、今回の目的を具体化する。

## 作業と成果物

対象、入力、行う作業、作成する成果物を記す。未確認の実装方針を決定済みとしない。測定では対象と条件を先に定め、修正では原因と小さな再現例を特定する。

保存先：新しい記録は`validation/development/担当ID/`以下の別run等へ保存し、既存の証拠を保持する。文書作業だけなら、その成果物のパスを記す。

## 完了条件と確認

- 第三者が成果物から確認できる条件を記す。
- 必要な試験又は文書確認と、参照する証拠を記す。
- 測定の記録完了と、検証能力の達成を区別する。未確認と残る条件を明示する。

## 担当範囲と引き継ぎ

編集するファイル又はモジュール、共有箇所と調整相手、独立させる操作環境を記す。別worktree・ブランチ・runを使う。担当範囲外の問題は根拠を残し、後続へ渡す。

完了時に記載する情報：成果物、起点と版、検証記録、PR、未確認、次の作業。中断する場合は途中のrunと再開条件も残す。
