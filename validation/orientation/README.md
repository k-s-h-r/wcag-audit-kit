# 向きのエミュレーションの比較

ChromiumのCDPで、CSS表示領域、画面の寸法、Screen Orientation APIのtype・angleを明示的に変更して比較した。実端末の回転ではなく、ブラウザーのエミュレーションとして記録している。

## 制限のない例

[正常例の結果](good-002/orientation.json)は11段階。landscape-primary → portrait-primary → landscape-primary → portrait-secondary → landscape-secondary → landscape-primaryと変えた。各段階で向きに対応する画面寸法・API・メディアクエリーの値を取得した。

カウンターは向きの変更後も値を保持し、各向きで操作して0から5まで増えた。全ての中間assertが成功した。[縦向きで2件になった画面](good-002/step-3.png)も保存した。

## 向きを制限する例

[制限例の結果](bad-001/orientation.json)は5段階。横向きで1件にした後、縦向きにするとカウンター全体が非表示になり、[回転を求める表示](bad-001/step-2.png)だけになった。横向きへ戻すと1件のまま再表示され、2件へ増やす操作を完了した。

実画面、DOMのorientationメディアクエリー、表示条件のassert、保持した件数を照合した。このカウンターは普通の件数追加であり、正常例で両方の向きでも同じ機能を実行できた。特定の向きが本質的に必要な内容の例として扱っていない。

## 証拠の範囲

両方ともcollectedであり、観察が完了した意味。WCAGの基準判定を自動で合格にしていない。各実行先に依頼とSHA-256、全段階の画面・DOM・計測・入力を保存している。全画像の画素寸法が表示領域と一致したことも確認した。

関連する3単体試験では、CSSの縦横だけが合っていても画面APIが違う値なら確認済みにしないこと、secondaryの角度、矛盾した寸法やbooleanを拒否することを確認した。

OSの向きのロック、回転センサー、全画面・PWAの向き制御、実端末の触覚や回転を再現した試験ではない。元の依頼と残る確認は実プロジェクトで具体化する。
