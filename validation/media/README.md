# 媒体の実表示と音声認識の校正

7秒の合成音声・図・確認音の既知の試験素材を作り、字幕を3種類にした。同じ原本を使い、意図した文、異なる文、後から出る字幕を比較した。これは既知の原文を使う方法の校正であり、未知の音声に対する独立した精度評価ではない。

## 取得したもの

実際のCaptionsとPlayボタンをクリックして終端まで再生した。3例とも全210映像フレーム、欠落0、7.008秒までの再生を記録した。コールバックは210又は209であり、これを検査者が全映像を理解した回数とは扱わない。

| 試験ページ | 約1.2秒・2.5秒の実表示 | 約5.7秒の実表示 |
| --- | --- | --- |
| 意図した字幕 | Press the blue button to save the document. | Confirmation tone |
| 異なる文 | Press the red button to delete the document. | Confirmation tone |
| 後から出る字幕 | 文字は表示されない | 最初の文とConfirmation toneが同時に表示される |

[意図した字幕の画面](player-good/caption-1.png)、[異なる文の画面](player-wrong-text/caption-1.png)、[遅い字幕の画面](player-late/caption-1.png)を実際に見て照合した。各実行先には、UI操作、時刻、全cue、トラックのモード、再生範囲、実画面、フレーム・イベントを保持している。

[原本](source/clip.webm)と[生成時の情報](source/source-provenance.json)、[ストリームの調査](inventory/media.json)も保存した。全映像・音声のデコードが完了し、210フレームのRGBA表現で11種類のハッシュ・隣接する差10件を得た。これを閃光数に置き換えたり、一般・赤色閃光の閾値を確認したことにはしていない。

## 音声の内容を確認できなかった理由

このAIへの音声入力は非対応だった。試したFFmpeg/PocketSphinxの出力は「use blue are you to uganda cute」で、生成時の意図した「Press the blue button to save the document.」から大きくずれた。[実出力と方法の状態](method-health/health.json)を保存している。

このASRを音声の正解として使わず、音声と字幕の内容、話者、意味のある音の比較は未確認とした。既知の生成原文や動画内の図だけから、検査者が音を聴いたとは扱っていない。

その後、[Whisper.cppによる校正](asr/README.md)も実行した。base.enは元の短い発話と、重要語を変えた別の発話を再現したが、無音から「You」も出力した。tiny.enはblue buttonを誤認識した。認識区間と生成音声の配置区間は異なり、実発話の境界は測定していない。発話の比較の補助にできる範囲と、誤出力・同期・非言語音の制約を保存し、既存の台帳を自動で通過や不適合へ変えていない。

## 実際の検査台帳

[1.2.2の判断保留を含むレポート](run-001/report.html)は、54件未実施・判断保留1件。音声情報の比較を全5区間で未確認と記し、strictは終了コード2、検証完了はfalseとなった。利用した実ページ・状態・環境の証拠と、case_idを合わせたプレーヤーの再生を接続した。

媒体の1.2.1〜1.2.9の手順を版2へ更新し、全対象を確定する際は、区間別の比較記録を要求するようにした。抜け・末尾未確認・明示した未確認区間・不正な時刻を検査する4単体試験と、recordまで通す1試験を追加した。これらは記録の整合性の試験であり、音声の意味が正しいと判定する試験ではない。

残る作業は、適切な聴取又は校正された別の手段による内容の比較、必要な音・話者・同期・映像情報と代替の評価。閃光、手話、音声解説等の別基準も、この再生記録だけで確認済みにはしていない。

記録上限を1イベントにした[方法の否定例](trace-cap-control/caption-player.json)では、再生自体は終端へ到達したが、212イベントが欠けてpartial・終了コード2となった。再生終了だけで観察記録が揃ったとは扱っていない。
