# 時間制限と再認証の実測

所有する小さな試験サービスをChromium 156.0.8078.79で実行した。サーバーの実セッション・無操作失効・401を使い、仮想時計やDOMへの失効状態の注入は使わない。実アカウントや実データは使っていない。

| 実行 | 確認した事実 |
| --- | --- |
| good-extend | 26秒の無操作制限。警告から簡単なクリックで10回延長。最後の警告から最後の有効な応答まで22.894秒、失効の観察まで22.995秒。 |
| bad-extend | 6秒の無操作制限。延長は1回まで。最後の警告から最後の有効応答まで1.901秒、失効の観察まで2.001秒。無効化・調整の代替もない。 |
| good-off | 制限に遭遇する前に無効化。入力後27.066秒以上経過しても失効せず、既定26秒を超えて4値を保存できた。 |

タイマーを戻す操作を全ソースと照合し、監視のGETは期限を更新しない。ブラウザーの単調増加時刻と実待機時間、画面、サーバー応答を記録した。最後の有効応答は、警告後にまだ操作できた時間の保守的な観測下限であり、失効時刻そのものとは分けている。画面上の警告と残り時間も確認した。[測定の比較](run/evidence/methods/timing/comparison.json)を参照する。

日本語を含むタイトル、複数行の本文、選択、チェックの4値を入力した。両例とも期限後の保存はサーバーに401で拒否された。正常例は再認証後に全4値が一致し、追記も含めて保存を完了し受領結果を比較した。比較例は失効時に全4値が初期化され、再認証後も復元しなかった。ログイン画面へ到達しただけでは完了としていない。

[レポート](run/report.html)の記録は次のとおり。

| 基準 | good | bad |
| --- | --- | --- |
| 2.2.1 | 通過、無効化の経路を確認。延長も実測 | 不適合、警告時間・回数が不足し代替経路もない |
| 2.2.3 | 通過、制限をなくして活動を完了できる | 不適合、通常の入力で時間に依存する経路が必須 |
| 2.2.5 | 通過、再認証後に元データと追記で活動を完了 | 不適合、入力を失い継続できない |
| 2.2.6 | 対象外、この実装の無操作失効はデータを消さない | 不適合、6秒の無操作で消失し期間の告知・復元がない |

通過3・不適合4・対象外1・未実施164、範囲未確認、検査未完了。`--strict`の終了コードは2。AA又はAAA全体に適合したとの報告ではない。20時間超の保存を実測した結果でもない。

コア収集の初期画像は校正の初期画像と画素単位で同一で、各caseの`evidence/attached/`にURL・シナリオ・ソースハッシュとの対応を保存した。[全ソースと実行原文](run/evidence/methods/timing/)と26＋7＋4段階の実画像・DOM・観察を保持している。既知の単純な実装の校正であり、外部認証、複数の手続き、長い保存期間等の独立した精度評価は残る。

Python57試験が成功した。[出力](python-tests.txt)を保存した。[レポートの表示確認](report-ui-002/results.json)では1280px・320pxで172行と未完了の表示を確認し、axe違反0、文書幅1280px・320px、狭い表示の表は1024pxのスクロール領域だった。レポート自体の全基準の適合を判定した結果ではない。最初の表示確認はChromiumの管理ポリシーでfile URLが開けず、[その記録](report-ui/blocked.json)を残してローカルHTTPで再実行した。

[初回の失敗記録](method-controls/first-attempt/results.json)では、Playwrightの`wait_for_function`の引数指定の誤りで延長テストが停止した。無効化の実行だけは完了した。元の実行を保持し、引数を修正した別の出力先で3経路を再実行した。失敗を検証済みへ変更していない。
