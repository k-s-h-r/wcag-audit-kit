# T042 帳票で見つけた不足に戻ってフォーカス時の移動を確かめる

通常探索が移動先の通信を遮断した073を、別のChromiumで同じ初期画面から再操作した。最初のTabで料金一覧の文書が開くことを確かめ、元の初期状態・画面幅の検査票に追試結果を追加した。対照074は同じ画面に留まった。[T042](../../../docs/tasks/T042-confirm-focus-navigation.md) · [ADR 0126](../../../docs/adr/0126-revisit-blocked-focus-navigation.md)

## 開始条件と追試する観察の選び方

起点は公開PR #111の `405134e`。事前に073・074・移動先のファイルを同じ版に固定した。初期取得はAAA、AI併用、quick、初期画面の画像だけとした。両画面幅は1280×900、320×900 CSS pxで倍率1。簡易探索には4ステップを指定し、残りの操作を表示させた。追試も同じ画面幅と起点URLを使った。支援技術の起動は対象外。[事前に固定した計画とファイルのハッシュ](plan.json)

初回のHTMLと `page-next` で、073の「通信を遮断したため移動先の表示は未確認」という2行を確認した。各行の参照先に、1回目のTab、`#subject` のフォーカス、主文書のGET要求と遮断があった。サーバーは通常探索中に始点のGET各4件を受け、移動先の受信は0件だった。074には移動先の不足を示す行がなかった。

`page-next` の既定の5票は別基準だったので、`pending --criterion 3.2.1 --page-exact <起点>` で初期状態の検査票を両画面幅から選び、`case --id <検査票ID>` で保存された状態、達成基準、設定と原典のハッシュを確認した。引き継ぐ対象、正確な残件の文言と探索のハッシュを記録した。[追試へ渡した情報](run-002/handoff.json)

## 別のChromiumで戻って確認する

固定した同じループバックのURLに戻り、ページ・幅ごとに新しいChromiumコンテキストで最初のTabをPlaywrightから1回だけ送った。追加操作後は1秒を観察した。試験の通信制限で許容したのは起点への初期GETと、Tab後に既知の同一オリジンの移動先へ出るメインフレームのGET。フォーカス、ブラウザーの移動通知、主文書のコミット、HTTP受信と応答のハッシュ、前後の画面・DOM・アクセシビリティツリーを保存した。

| 問題集 | 最初の実Tab | サーバーと文書で確認したこと |
| --- | --- | --- |
| 073 | 氏名入力欄 `#subject` にフォーカス。そのイベントの配信中に別文書への移動を通知 | 両幅で `GET /details.html` が各1件届いて200を返した。前後で文書の時刻原点が変わり、見出しは「利用案内」から「利用料金の一覧」に変わった |
| 074 | 氏名入力欄 `#subject` にフォーカス | 両幅で開始URLと同じ文書に留まり、入力欄にフォーカスが残った。移動先の受信は0件 |

073はこの入力欄がフォーカスを受けた時点で別の主文書を開く。保存した前後の文書と実入力を読み、3.2.1の文脈の変化をこの対象で確認した。074は試した入力欄と1秒間の観察に限って文脈の変化がなかった。[追試の集計](run-002/manual-summary.json) · [073の前の画面](run-002/073-desktop-before.png) · [073の後の画面](run-002/073-desktop-after.png) · [本文と公式解説](../../../skills/wcag-audit-kit/references/sources/3.2.1.md)

## 同じ帳票へ追試を登録する

追試の採取時に、検査票ID・開始URL・画面幅・探索版と、前後の画面や操作を含む原本14点のSHA-256を条件ごとに保存した。全条件の原本と画像寸法を照合してから、`attach --case` で同じ検査票IDに実入力と追試結果を添付し、`record` で判断と残る確認を記録した。073の `resolve-exploration` には、`page-next` から得た探索版のハッシュと移動先表示の不足の原文を使った。2幅を一件ずつ登録し、どちらも同じ探索版で累積した。最後に `page-report` と `page-next` を再実行した。

| 問題集 | 両幅の3.2.1検査票 | WCAG 2.2 AAAの対象範囲 | 探索の残件 |
| --- | --- | --- | --- |
| 073 | 未実施 → 不適合。ほかのフォーカス先・状態は未網羅 | 未確認 → 不適合 | 8件 → 6件。探索待ちは6経路 |
| 074 | 未実施 → 判断保留。1対象の観察結果は通過 | 未確認 | 4件。探索待ちは6経路 |

HTMLとJSONで同じ検査票IDと観察証拠を参照できる。Excelでは073の不適合箇所から追加観察へ直接移れる。074は検査票の証拠欄に参照パスがある。機械検査、他の達成基準、原始探索のバイトと残っていた経路を前後比較した。両例とも検査全体は未完了。記録した範囲は最初のTabで届く入力欄までで、別のフォーカス先、状態、支援環境は未確認。[前後の帳票の照合](run-002/checks.json)

## 検証原本

別のレビュアーが4条件の原始入力、前後の文書、サーバー記録、通常CLIの前後の帳票を照合した。追試前の画像は、通常CLIの初期画像と4条件すべてでバイト単位で一致。新たに添付した40点の証拠は原本と一致した。073は両幅ともExcelの不適合箇所から追試の `observation.json` を開ける。[独立照合](run-002/independent-review.json) · [Excelリンクの照合](run-002/independent-excel.json)

独立レビューで、初回の再現手順には別の画面幅の原本を混ぜたコピーを添付できる不備が見つかった。原本と検査票の照合を加え、`run-002` の通常探索後の台帳と帳票を別の `run-003-receipts` に復元して4追試と帳票作成を繰り返した。原本がそろった4条件は登録でき、別の画面幅の画像・入力記録・HTTP記録・採取記録に差し替えた独立対照16件は拒否された。最後の条件だけを差し替えた試行でも、全条件の添付を始める前に止まった。[独立対照の照合](run-002/independent-receipts.json)

初回公開用の `run-001` は、原始証拠ZIPと当時の照合を保管する。初回ZIPのSHA-256は `dcf44ea0bd14ea8a449754acab05a3c697fd25179e3f26fc070142c37a363b67`。[初回の原本](run-001/proof.zip) · [初回の独立照合](run-001/independent-review.json) · [初回のExcelリンク照合](run-001/independent-excel.json)

修正後の公開用 `run-002` のZIPでは、各ページの `before/` に通常探索後の帳票と引き継ぎ、`manual/` に追試と原本の採取記録、各 `after/` に所見と解消の入力、各 `page/` に台帳と最終帳票がある。収録した原本267点は `sha256.json` で照合できる。ZIPのSHA-256は `9c7f0f12c93b8a27eb74e9c91bd9da9b2ae176b2b72187e42976bd877d5ad8e6`。[実行と帳票の原本](run-002/proof.zip)

## 再実行

同じリポジトリを開き、毎回別の新しい出力先を指定する。通常CLIの初期取得から `page-next` まで、別ブラウザーの追試、確認済みの所見の登録の順に実行する。提出する所見の対象と前後文書は追試の原本から確認できる。[固定対照の所見](observed-judgments.json)

```sh
t042_run=/tmp/t042-new
python3 validation/development/T042/collect.py --out "$t042_run"
python3 validation/development/T042/followup.py --run "$t042_run"
python3 validation/development/T042/submit.py --run "$t042_run"
```

取り違えの対照を再現する場合は、追試を採取した後、登録前の出力を別の場所に複製する。そのコピーの `manual/073/desktop/input-events.json` に `manual/073/narrow/input-events.json` を上書きしてから `submit.py` を実行すると、採取時のSHA-256と一致せず、添付の前に終了する。
