# T016：「進めて」で継続する開発スキルの確認

確認日：2026-11-18。起点：`899d3f9`。

対象は`.agents/skills/wcag-dev/`とAGENTS.mdからの接続、タスク状態の更新と利用案内。この記録は開発手順の確認であり、WebサイトのWCAG検証結果ではない。

## 配置と文書の確認

SKILL.mdとagents設定をYAMLとして解析し、名前・説明・版・明示呼び出し専用設定を確認した。相対リンク、16タスクと索引、前提とG1・G2を含む依存関係に循環がないことを確認した。配布用4スキル、検証ランタイム、問題集、既存の実測記録が起点から不変であることを照合した。

`.venv/bin/python scripts/sync_skills.py --check`は成功した。`quick_validate.py`は`disable-model-invocation`を未対応項目として拒否し、終了コード1だった。既存スキルと同じ制約のため設定を保持し、YAMLの型・必須情報と参照先は別に確認する。

## 隔離した環境での継続手順

[入力](evaluation-001/inputs.json)は、二つの小さなGitリポジトリの初期ファイル、起点コミット、使ったスキルのハッシュを含む。保存済み入力は変更せず、別の条件や手順で試す場合は新しい記録へ保存する。

独立したAIへ、各リポジトリのAGENTS.mdとwcag-devを使って「進めて」を実行するよう依頼した。期待する答えや元の開発会話は渡していない。外部ネットワーク、実GitHubへのPR、元のリポジトリへのアクセスは禁止し、ローカルで実行できた作業と残る外部操作を記録する条件とした。

| 場面 | 入力の状態 | 確認する対象 |
| --- | --- | --- |
| タスクがない | 起動・設定の説明が目標だが、タスク文書はまだない | 必要な作業を追加し、文書の計画だけで終えず作業まで進めるか |
| 前提待ち | T001の変更が作業ブランチにあり、T002はmainへの採用を待っている | 未採用を採用済みにせず、待ちを根拠なく別タスクで埋めないか |

結果は[原報告](evaluation-001/agent-report.txt)、[照合結果とハッシュ](evaluation-001/results.json)、[タスクがない場面の差分](evaluation-001/no_tasks.patch)、[前提待ちの差分](evaluation-001/pr_wait.patch)に保存した。

保存したunified diffは、空の文脈行にも形式上の空白を含むため、このフォルダーの`.gitattributes`でpatchファイル自体の空白検査を無効にした。証拠の内容は変更していない。元の変更内容に対する空白検査は、各試験リポジトリで成功している。

- タスクがない場面では、既存のタスク整理スキルを内部手順として読み、T001を1件追加してREADMEの作成まで進めた。起動、ヘルプ、APP_PORTの変更の3コマンドが終了コード0だった。[コマンドの実出力](evaluation-001/evidence/no_tasks/validation/development/T001/20261117T164911Z/cli-results.json)を保存し、新しいブランチへコミットした。タスクとREADMEの実体、アプリとスキルの不変を照合した。
- 前提待ちでは、成果物がfeatureブランチに存在し、mainにはないことをGitで確認した。T002を未着手のまま保ち、新しいタスクを追加せず、待ちと再開条件を記録した。[Gitの実出力](evaluation-001/evidence/pr_wait/validation/development/T001/20261117T164911Z/repository-facts.json)と照合し、READMEとアプリ、mainと元featureブランチを保持していることを確認した。
- 両方で担当ファイル、索引、ロードマップ、ADR、確認記録を作成又は更新した。最終の作業ツリーはクリーンで、各mainは初期コミットのままだった。remoteは設定されておらず、外部操作は試みていないと報告した。PRは未作成と明記し、URLやマージ成功を作っていない。

以上は、スキルの手順を読み込んだ後の小さなローカル継続試験である。実GitHubでのPR作成・マージや、すべてのタスク選択・分割の正しさを実証するものではない。

## 実ホストと運用で残る確認

通常のCodexでのスキル発見・呼び出しと、AGENTS.mdからの自然な継続依頼の遵守、実GitHubでのPR再開やレビュー対応、複数担当での長期運用は、この隔離試験とは別に実証する必要がある。無期限の自律実行、PR自動マージ、WCAG検証能力を今回実証したとは扱わない。
