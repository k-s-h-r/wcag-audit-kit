# T019 非表示の aria-controls 参照先を操作後に再検査する

同じボタンに `aria-controls="reference"` を設定したローカルの3ページを、PC相当1280×900とスマートフォン相当320×900 CSS pxで測る。操作用のボタンをクリックすると、画面外にある非表示の参照先を追加・削除するか、同じIDの要素を別の領域へ移す。参照元のHTMLと可視要素の状態記録は、クリックの前後で一致した。

簡易探索は共通の設定で `page-audit --initial-only` と `--resume --quick-explore` を使う。比較する全文書検査は `--explore` を使う。全文書側には同じクリックと参照先の個数または配置だけを公開の `exploration_labels` で指定する。発見した経路をラベルで確認し、可視状態が同じ場合もその操作後のaxeを保存するための設定。両方のクリックに、入力ログでブラウザー由来のイベントを確認する。

機械モード、WCAG 2.2 AA、画像なし。各ページの上限は24ステップ、16状態、深さ1。実測環境はDebian 13、Python 3.12.14、Playwright 1.62.0、Chromium 156.0.8078.79、同梱のaxe 4.11.0。変更前は `run-002`、実装コミット `0962300` は `run-003` に保存した。

比較する項目は全ルールの違反・判断保留・通過・対象外、各分類の対象と影響度、参照元のHTMLと参照先の有無。再検査数はaxeの結果に記録された対象数で、処理時間とは別に扱う。

## 追加・除去の結果

| 操作 | 初期の `#subject` | 変更前の簡易探索 | 全文書の操作後 | 変更後の簡易探索 |
| --- | --- | --- | --- | --- |
| 非表示の参照先を追加 | 違反 | 初期の違反を参照 | 通過 | 通過を新しく記録 |
| 非表示の参照先を除去 | 通過 | 初期の通過を参照 | 違反 | 違反を新しく記録 |

両操作とも両画面幅で同じ結果だった。変更前は計4条件で、可視要素が同じ状態として操作後のaxeを省き、初期の結果を参照した。変更後は `#subject` が解決できるIDの組を状態に含め、操作後の検査結果を帳票で追えるようにした。追加後のJSON帳票では値の妥当性9対象が通過し、除去後は `#subject` の違反1対象と通過8対象を確認した。

変更後の簡易探索は、各操作・各画面幅で `aria-valid-attr-value` の9対象を全文書で再検査した。ARIA属性名の9対象と `tabindex` の8対象の結果は、従来の差分検査が再利用した。

## 同じIDへ解決できる移動

同じ非表示の参照先を隣の領域へ移しても、初期表示と操作後のどちらも `#subject` は通過した。簡易探索は移動の前後を同じ状態と判定し、各幅で初期の結果を参照した。全文書検査は操作後の9対象を記録した。変更後はこの移動も含む6条件すべてで、全ルールの分類、対象、影響度が全文書検査と一致した。

変更後の簡易探索で保存した状態は追加と除去で各4、移動で2だった。試験用のラベルを使った全文書検査はいずれも4状態を保存した。文書のGETは各ページで簡易16件、全文書22件だった。モード間では探索する経路も異なるため、再検査した対象数とは分けて記録した。

独立レビューは別のループバック待受で3対照を両画面幅で再実行し、6条件すべてを全文書検査と照合した。除去後のHTMLでは対象の違反と根拠へのリンク、Excelでは機械検査の該当行、JSONでは範囲の結論が未確認であることを確認した。
