# T019 操作後の差分再検査を全体再検査と照合した記録

ネイティブのモーダルを開いたときに、背後の要素の判定が残る問題を修正した。CSSで現れる領域、外部ラベル、離れたポップアップ、ネイティブのモーダルを、同じクリック経路で比較した。修正後は全8条件でaxeの違反・判断保留・通過・対象外と、各判定の対象が全体再検査と一致した。 [修正前の比較](run-001/baseline-cli.json) · [修正後の比較](run-001/fixed-cli.json)

## モーダルの背後の判定を表示していた

修正前は `dialog.showModal()` でモーダルを開いても、背後にある9要素のARIA属性名と `tabindex` の結果を再利用した。2ルールとも、全体再検査ではモーダル内の1要素だけが違反だった。差分再検査には背後の違反1件と通過8件がそれぞれ余分に残った。Chromiumの2つの表示幅で同じ差が出た。 [要素単位の比較](run-001/baseline-browser.json)

修正後は `operation-impact.json` に `whole_page` と理由の `native_modal` が残る。通常のダイアログとネイティブのモーダルは、同じHTML・操作候補でも別の状態になる。二つのモーダルを逆順で開くと、前面のボタンと検査の対象も変わった。複数のモーダルが開いた状態は観察ごとに保存する。画面を取得してからaxeの読み取り中にダイアログを閉じて開き直した場合は、開いている一覧が同じでも結果の保存を止める。 [修正後の要素単位の比較](run-001/fixed-browser.json) · [順序ごとのCLI結果](run-001/modal-stack.json)

## 同じ状態で再検査した対象数

再検査数はaxeの結果に記録された対象数。括弧内は全文書で記録された数。いずれもクリック直後の値で、1280px幅と320px幅で等しかった。

| 操作 | ARIA属性名 | `tabindex` | 再利用数（各ルール） |
| --- | ---: | ---: | ---: |
| CSSで領域を表示 | 2（11） | 1（10） | 9 |
| 画面外の外部ラベルを空にする | 2（11） | 0（9） | 9 |
| 別領域のポップアップを表示 | 3（12） | 1（10） | 9 |
| ネイティブのモーダルを開く | 1（1） | 1（1） | 0 |

外部ラベルの変更は `#labelled` の名前の欠落として検出できた。領域の表示と、画面外のポップアップでは、新たに現れた要素も検査した。簡易探索と通常探索は各条件とも両幅を合わせて4状態を取得した。試行した操作・到達した経路、文書のリクエスト数、所要時間は結果JSONに個別に記録した。探索方法による経路の違いがあるため、再利用が通信量や所要時間をどれだけ変えるかは未確認。
