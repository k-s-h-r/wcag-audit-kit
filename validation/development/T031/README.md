# 操作中の別オリジンへの通信を受信側で確かめる

通常の `page-audit` では、検査対象とは別のオリジンが、操作中のGETを受信した。対象オリジンへの読取通信を通す試験用HTTPプロキシを明示した対照では、別オリジンへのGETの到達は0件だった。通信を制限した画面はボタンで候補を表示したあとに「日時を取得できません」と表示した。[計測結果](run-003/summary.json)

## 条件

統合版 `5bb4a80` の `page-audit` を使った。検査対象、別オリジンの受信先、試験用プロキシは `127.0.0.1` の異なるポートに置いた。ブラウザーは Chromium 156.0.8078.79、画面幅は1280pxと320px。二つの条件は別々のrunに記録し、どちらも初期表示と簡易探索を続けて実行した。累計の探索上限は10ステップ。オリジンはHTTPのスキーム、ホスト、ポートで区別する。

ボタンで候補を表示すると、同一オリジンのGETと、別オリジンへの直接GET・画像・POST・WebSocketを試みる。対象オリジンから302を返すGETも発生させ、転送先での受信を記録する。受信ログの件数には、操作経路を別コンテキストで再生する際の再取得を含む。[対照と測定スクリプト](measure.py)

## ローカルの受信件数と表示

| リクエスト | 通常の `page-audit` | プロキシを通した `page-audit` |
| --- | ---: | ---: |
| 別オリジンの初期画像 | 10 | 0 |
| 操作後の別オリジンへの直接GET | 6 | 0 |
| 操作後の別オリジンの画像 | 6 | 0 |
| 操作後に302で転送された別オリジンのGET | 6 | 0 |
| 操作後の別オリジンへのPOST | 0 | 0 |
| 操作後の別オリジンでのWebSocketハンドシェイク | 0 | 0 |
| 操作後の検査対象オリジンへのGET | 6 | 6 |

両条件で、POSTは探索台帳にも遮断として記録された。別オリジンでのWebSocketハンドシェイクは受信されなかった。プロキシ側は対照ページから別オリジンへのGETを4種類、計28件拒否した。両幅でボタンに実際のEnterが届き、日時欄には通常の条件で「日時を取得」、通信を制限した条件で「日時を取得できません」と表示された。両条件の検査票は適合の結論を未確認としている。[通常の条件の受信ログと操作証拠](run-003/standard.json) · [プロキシ条件の受信ログと操作証拠](run-003/proxy.json) · [受信ログと対象経路の原始記録](run-003/evidence.zip)

同じプロキシは、Chromiumのバックグラウンド要求も拒否した。この実行ではGETが2件、POSTが2件、CONNECTが7件だった。通常の条件では対照の外にある受信先で計測しておらず、HTTPSの通信範囲も未確認。[プロキシの原始記録](run-003/proxy.json)

## 再実行と残る確認

Chromium、Playwright、リポジトリのセットアップを済ませ、リポジトリのルートから新しい出力先を指定する。スクリプトから通常のCLIを実行し、`standard/` と `proxy/` に各run、CLI引数、受信記録とプロキシの記録を保存する。待受ポートは実行ごとに変わる。

```sh
python3 validation/development/T031/measure.py --out /tmp/wcag-t031
```

試験用プロキシの許可先は、その場で作るローカルHTTP対照に固定する。スクリプトはプロキシを使う条件で、Chromiumにプロキシのアドレスと、ループバックにも適用する引数を渡す。HTTPS、ブラウザー以外の通信、OSでのネットワーク分離、本番サイトへの適用は未確認。通信制限を実装する場合は、許可先を明示し、制限によって取得できなくなったページや操作結果を未確認として利用者に返す条件も同じ対照で確かめる。[T031](../../../docs/tasks/T031-cross-origin-operation-observation.md) · [ADR 0110](../../../docs/adr/0110-measure-cross-origin-requests-during-operation.md)
