# 通常の `page-audit` でHTTPSの操作通信を測る

通常のCLIから同じループバック対照を調べた。直接接続では別オリジンにGETが28件届いた。許可した接続先だけに `CONNECT` を通す試験用プロキシ経由では、別オリジンの受信は0件だった。両条件とも、許可した同一オリジンの操作後のGETは6件届いた。[事前条件](https-conditions.md) · [測定結果](https-run-001/comparison.json)

| 別オリジンの受信 | 直接接続 | プロキシ経由 |
| --- | ---: | ---: |
| 初期画面の画像 | 10 | 0 |
| 操作後のfetch | 6 | 0 |
| 操作後の画像 | 6 | 0 |
| 同一オリジンの302転送先 | 6 | 0 |

PC幅1280×900とスマートフォン相当幅320×900 CSS pxの両方で、主文書の開閉ボタンへ実Enterが届き、候補が表示された。プロキシ経由では日時の取得だけができず、その旨が画面に出た。POSTは探索台帳に遮断が残り、別オリジンにPOSTやWebSocketのUpgradeは届かなかった。両条件とも範囲の結論は未確認だった。[直接接続の受信と実キー](https-run-001/direct.json) · [プロキシ経由の受信と実キー](https-run-001/guarded.json)

プロキシは許可先への `CONNECT` を32件通し、別オリジンへの28件を拒否した。対照外のブラウザーのバックグラウンド通信として記録したGET 2件、POST 2件、`CONNECT` 9件も拒否した。直接接続の条件では対照外の受信先を測っていない。プロキシが扱うのは接続先ホスト・ポートと暗号化された通信。許可したトンネル内のHTTPを制限する仕組み、OSによる分離、他のブラウザー、本番環境は未確認。[原始証拠・帳票](https-run-001/evidence.zip) · [実行環境・保存証拠のハッシュ](https-run-001/provenance.json)

別エージェントが、両条件の受信ログ、入力、状態を独立に照合した。別のループバック試験でも、直接接続とトンネル経由の両方でTLS 1.3と同じ対向証明書を確認した。別受信先への `CONNECT` と平文のGETは403で拒否され、別受信先には届かなかった。[独立試験の出力](https-run-001/independent.json)

## 再実行

Chromium、Playwright、OpenSSLが使える環境で、新しい保存先を用意する。スクリプトはその場でテスト用の証明書を生成し、公開鍵をその試験のChromiumに指定する。証明書の秘密鍵は一時ディレクトリーにのみ置く。

```sh
python3 validation/development/T031/measure_https.py --out /tmp/t031-https-new
```
