# T008：機械結果と残作業の帳票照合

2026-11-18。T002・T003の既存4runを読み取りだけで確認した。収集器を起動せず、対象ページへの再訪問・判定更新・帳票再作成は行っていない。[確認スクリプト](examine.py)は既存帳票を表示し、元の全ファイルのハッシュを前後で照合する。

[4runの照合結果](readback/observed.json)は、JSON・HTML・Excelの判定行・件数・証拠リンクが一致することを示す。各runで1280pxと320px、表のキーによる横スクロール、指定WCAGタグのaxeを確認した。取得未接続は画像runの別表に3行残り、意味判断の省略や未確認も維持されている。

全28ページ報告も、audit_complete=false、scope_confirmed=false、判定票の全件がnot_runである。55票のページだけでなく、追加状態があるページは110票であり、状態を隠して単純に55票へまとめていない。機械のaxe結果とWCAG基準全体の適否は分かれていた。

元の4,676ファイルは前後でバイトが不変だった。報告を読むだけで検査・判定更新が起きず、全体の未完了が保存されている。不一致がなかったため、報告コードやレイアウトは変更しない。T007の全取得照合は未接続のままなので、変更した後は別の新規出力で再確認する。

最初の確認スクリプトは全ページの票数を55と仮定し、追加状態のある110票で停止した。[原エラー](attempt-001-analysis-error/stderr.txt)と元の確認コードを保持した。仮定を除き、実際のcases数と全票not_runの一致を確認する方法へ修正し、別出力先で再実行した。製品の判定値や元の帳票は変更していない。

元のrunはT002・T003のzipから参照できる。再試験はexamine.pyに展開した2基準のrun親ディレクトリーを--title-root・--image-rootで指定し、新規--outを使う。証拠として確認した範囲の結果であり、Microsoft ExcelのネイティブUIや実サイトの適合の確認ではない。G1にはT009等による操作後の2行の解消が残る。
