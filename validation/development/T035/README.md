# 初期表示で隣り合うボタンの寸法と間隔を測る

通常の `page-audit` で初期表示を取得した。Chromium 156.0.8078.79、Playwright 1.62.0、1280×900および320×900 CSS px、`machine`、AAAを使用した。既存5ページと追加8ページの計13ページを用いた。うち問題集068・069・070の3ページは通常の簡易探索まで進め、固定した5行を採点した。[対照生成と再実行](measure.py) · [採点結果](run-001/score.json)

祖先による切り抜き、測定点間を覆う透明な要素、当たり範囲を広げる疑似要素、明示寸法のないボタン、追加のリンク、閉じた宣言的シャドウDOMを使った対照は、両幅で機械行を出さなかった。帳票の2.5.8の検査票は未実施のまま。別の形状・状態の当たり判定と、ほかの例外の判断は個別に行う。[対象ごとの実測](run-001/observations.json) · [初期状態、帳票と原始証拠](run-001/raw-evidence.zip)

固定5行のうち、068の2行を検出し、069の2行が正常対照に一致した。070の1行は到達・判定なしで、採点外の指摘は0件だった。統合版の保存済み76ページ・87行を新しい採点器で読み直し、以前の採点JSONと完全に一致した。保存済みの初期表示152通りに新しい機械計測の操作候補条件を当てたところ、該当するのは068と069の両幅だった。[統合版の保存済み結果](../vision/run-001/machine-score.json)

別エージェントが、実ブラウザーの当たり判定、通常CLIのJSON・HTML・Excel、旧runの帳票再生成、証拠と帳票の改変を使った採点の照合を確認した。中心間の境界に加え、円から隣接する細長い矩形まで12 CSS pxの境界も比較した。[独立レビュー](run-001/independent-review.md) · [独立測定の原始記録](run-001/independent-evidence.zip)

## 採用した計測の範囲

統合版の帳票では2.5.8の機械行がなく、初期画面のDOM状態には矩形が保存されていた。配布axe 4.11.0の `target-size` は既定で無効だった。同じChromiumで有効にするとp01・p03に違反を出し、p02・p04は通過、p05は適用外だった。一方、中心間23.984375 CSS pxは通過し、上から覆ったボタンにも違反を出した。通常の取得に組み込む測定は、静的なネイティブボタンの寸法と位置、内側9点の当たり判定に絞った。[axeとポインターの原始比較](run-001/raw-evidence.zip) · [ADR 0119](../../../docs/adr/0119-observe-initial-native-button-spacing.md)

24 CSS pxの中心間距離はW3C公式解説の図5にある、20 CSS pxの対象に4 CSS pxの隙間を置く対照と同じ条件。小型の細長い対象が隣にある場合は、その円に加え、対象矩形との重なりも確かめる。[2.5.8本文と公式解説](../../../skills/wcag-audit-kit/references/sources/2.5.8.md)

## 再実行

配布スキルの同期を確認し、ChromiumとPlaywrightを使える環境で新しい出力先を指定する。

```sh
python3 scripts/sync_skills.py --check
python3 validation/development/T035/measure.py --out /tmp/wcag-t035
```

原始証拠ZIPには初期表示の抜粋と帳票、基準版の矩形とaxe実行結果、ファイルごとのSHA-256を収めた。探索run全体を読み込む試験は、再実行で作った出力先を使う。
