## キーボード、配信、映像

- c03・c04とも、同じ名前の選択ボタンにTabで移動した。両方で信頼済みのEnterの押下、クリック、キーアップを観察し、DOMとAXの押下状態は `false` から `true` に変わった。c03は元動画、c04は音声解説版にそれぞれ進んだ。
- `attempt-004-protocol.log` のページ遷移と同じセッションにあるSpaceの押下・解放と、それぞれの成功応答を照合した。未選択対照はID 71/72、c03は334/335、c04は598/599。ブラウザー標準の再生ボタンにフォーカスがあるとき、ページ側にはSpaceのキーイベントが現れなかった。AXのPlayからPauseへの変化、同じ動画の信頼済みplay・playing・ended、開始から6.983秒までの連続した再生を確認した。
- ChromeのMedia応答の受信終了とサーバーの個別レシートを確認した。元動画は38,398バイトで、未選択の対照はレシート2、c03は4、c04選択前は6。c04選択後の音声解説版は74,490バイトでレシート7。いずれも全範囲が206応答に入り、ディスクキャッシュ・Service Workerは使われなかった。
- c03・c04の `playing-03.0.png` を目視し、両方に「Access code 7291」を確認した。両配信素材のデコード済み映像フレームのハッシュ列は一致した。

## ブラウザーの再生音声

独立してFFmpegで、ブラウザーの `captureStream()` と対応する配信素材を16 kHzモノラルPCMにデコードした。ブラウザー側はすべて7.020秒、配信素材側は6.975秒だった。未選択とc03の再生PCMは同一のSHA-256。各条件の非無音250 ms窓は対応する配信素材と +6.5 ms の安定したずれで一致し、相関係数はすべて0.9995以上だった。c04の追加音声がある各窓も一致した。[区間ごとの測定値](independent-pcm.json)

10 msのRMS窓を−40 dBFSで比較すると、共通の台詞に続く追加音声はc04のブラウザー収録で約3.14–6.31秒、配信素材で約3.13–6.30秒にあった。c03と元動画には2.5秒以降にこの水準の音声がなかった。全尺を入力したWhisperはc04の再生音声と配信素材の両方で `7-2-9-1` を認識した。未選択とc03の認識結果には共通の「Press the blue button to save the document.」だけがあった。別に2.85–6.95秒を切り出したWhisperはc04の末尾の1を落としたため、認識自体の精度を一般化できない。

根拠はブラウザーが再生したメディア要素の音声トラックまで。スピーカーの出力、人の聞き取り、他の台詞や非言語音、正確な発話境界、他の再生環境とWCAG達成基準全体は確認範囲外。
