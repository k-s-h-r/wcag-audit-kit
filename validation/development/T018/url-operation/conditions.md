# URLからアコーディオンを開閉する試験条件

起点を統合版 `5bb4a80` に固定する。既存のT018はEnterによる開閉とTabによる移動を調べた。今回は同じボタン・本文・CSSを持つ2ページで、標準のEnterとSpaceの両方を比較する。開閉ボタンと領域は公開Shadow DOM内に置く。両ページでマウスのクリックに応じて本文を開閉する。

ループバックHTTPからChromiumのヘッドレスで、1280×900と320×900 CSS pxを調べる。検査側は配布用の `page-audit` にURLと共通設定だけを渡す。WCAG 2.2 AA、`machine`、初期表示を撮影。最初に既定の簡易探索で収集する。Spaceが探索対象に入らない場合は、別runで深さ4、最大48ステップ、16状態の通常探索を試す。簡易探索と通常探索のそれぞれで初期キャプチャーと操作ログを保存する。

採集後に、クリックとキーを別々に数える。クリックのポインター種別、キーダウンの信頼性と到達先を入力ログで確認する。閉じた表示から開いた状態への変化は、本文の表示、ボタンの `aria-expanded` とChromiumのアクセシビリティツリーの展開状態で照合する。キーを送ったとき、TabとShift+Tabによる本文と見出しの間の移動、開閉ボタンの反復操作で閉じたあとのフォーカスを、それぞれ別の観察として示す。経路が採集されていないときは未確認として記録する。

結果を判断する側は [対照の期待](expected.json) を読む。検査CLIに期待値、操作順、部品のセレクターを渡さない。既存の公開対照p06・p07と構成が違うため、元の問題集の採点には加えない。
