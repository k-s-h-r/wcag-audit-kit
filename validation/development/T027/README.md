# アクセシビリティ点検の実行確認

保存済みの観察を使う依頼と、URLから実際に操作する依頼を、[点検の手順](../../../skills/wcag-audit-kit/references/accessibility-review.md)で確かめる。明示呼び出しの表記は利用する環境に合わせる。

## 保存済みの観察を渡す

T022の `run-001` にある観察、採点結果、操作の証拠を渡す。比較済みの効果も答えられるか確かめる場合は、T023の `run-002` にある比較結果と証拠を加える。 [T022の操作記録](../T022/run-001/observations.json) · [検査票の照合](../T022/run-001/score.json) · [T023の比較結果](../T023/run-002/result.json)

> `$wcag-audit-kit` 添付した記録で、工作室の見学予約をアクセシビリティ点検してください。どの操作で困るか、改善案、効果の確かめ方を確認したいです。元のWCAG判定と、確認が残ることも教えてください。

操作と証拠への参照、利用への影響、変更箇所と確かめ方、元の2.1.1・2.5.3の判定を確認する。比較資料を渡さない場合は効果が未確認と伝わるか、渡した場合は実測値と比較条件を参照できるかを見る。実行履歴で対象URLへのアクセスの有無を、入力ファイルのハッシュで保存済みの証拠や判定への変更の有無を確認する。

## URLを渡して操作を観察する

[T022の再実行手順](../T022/README.md#再実行)でローカルサイトを起動し、問題例の `/rb/` のURLを渡す。調査担当に渡すのはサイトと作業条件。T022・T023の採点や操作履歴は手元で照合する。

> `$wcag-audit-kit` このURLから工作室の見学予約を始め、確認画面までキーボードで進めるか点検してください。止まる箇所と改善案、直したあとに確かめる操作を教えてください。最終確定や実装変更は不要です。

回答から、URL、実際に押したキー、停止点、画面やログ、確かめた別の操作、未確認をたどる。改善案は、同じ出発点から2名を選んで確認画面に進めるか確かめる手順と結び付ける。新しい観察でWCAG判定を記録していない場合は、点検の所見と基準との関係を示し、判定を未確認として扱う。

## ローカルの操作と証拠を確かめた結果

起点ページと人数選択ページに対し、`page-audit --level AA --mode machine --screenshots initial --initial-only` と `--resume --quick-explore` を別々のrunで実行した。両方にHTML・JSON・Excelが出力され、適合は未確認だった。起点のリンクによるページ移動は自動探索の対象外として残った。人数選択では追加の探索が4経路残った。帳票は `/workspace/wcag-audit-work/evidence/t027-cli-cxswlu61/` に保存した。

Chromium 156.0.8078.79、1280×900で `/rb/` を開き、開始リンクから人数選択に進んだ。増員にEnterとSpaceを送っても1名のままで、確認ボタンを押すと2名以上が必要という案内が出た。増員をクリックすると2名になり、TabとEnterで確認画面に着いた。確認ボタンの表示は「予約内容を確認する」、ブラウザーが公開した名前は「詳細を見る」だった。

9時点の画面とアクセシビリティツリーを新しい観察先へ保存した。元のT022の操作記録・採点結果とT023の比較結果は試行の前後でSHA-256が一致した。保存先は `/workspace/wcag-audit-work/evidence/t027-observe-f0sze87i/observations.json`。SHA-256は `9b340e916489e38c1d9b478bedb203847662f39b24227498059383d2461f8c08`。
