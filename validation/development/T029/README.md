# 予約カレンダーで選択前の空き状況を確認した記録

工作室の予約サイト2例を、起点URLから検証した。対象は、2027年5月10日から16日のカレンダーで、日付を選ぶ前に空きありと満席を色以外でも区別できるかというWCAG 2.2の1.4.1の観点。検査はAA、デスクトップ1280×900 CSS pxの初期表示を対象にした。

## 色と操作が同じ二つの対照を固定した

両例とも、同じ7日を同じ色で表示し、すべての日付ボタンを操作できる。一方の各ボタンは日付と曜日が表示され、空き状況は凡例と背景色の対応で分かる。もう一方は、各日付ボタンに「空きあり」又は「満席」と表示する。選択後は、両例とも結果を文字で表示する。

Chromiumで取得した背景色同士の相対輝度コントラストは1.0247:1。文字とそれぞれの背景は11.1887:1と11.4656:1だった。公開ページのハッシュと採点条件は実行前に固定し、検査担当への依頼には正解・対照の区分を含めなかった。 [評価条件と公開ファイルのハッシュ](run-001/oracle.json) · [計測した配色](run-001/contrast.json)

## 機械検査はどちらも判断を残した

通常のCLIで、それぞれの起点URLからカレンダーを発見した。初期表示と簡易探索で操作後の状態を4つずつ収集した。axeの `link-in-text-block` は両例の全状態で該当なし。初期画面の空き状況に関する判定は2件とも未確認だった。 [機械検査の結果](run-001/machine.json)

## 独立した検査担当は二つの表示を区別できた

検査担当は、両方の起点から「予約できる日を探す」にTabで移動し、Enterでカレンダーを開いた。5月10日と11日を別々のブラウザー文脈で選んだ。両例とも5月10日を選ぶと空きがあることを知らせ、確認リンクが現れた。5月11日は満席と表示された。グレースケールは選択前の比較に使い、実キー操作は元の表示で行った。 [検査担当の原文](run-001/observer-response.md) · [操作記録](run-001/date-selections.json)

| 対象 | 選択前の表示 | 機械検査 | 独立した対象判定 | 1.4.1の検査票 |
| --- | --- | --- | --- | --- |
| u47b | 日付と曜日から空き状況を見分けるには背景色を凡例と照合する | 未確認 | 不適合 | 不適合。残る確認あり |
| m85c | 全7日のボタンに「空きあり」又は「満席」と表示 | 未確認 | 通過 | 判断保留。残る確認あり |

空き状況の観点では、機械検査で判断が残った2件を追加観察で判定し、事前の採点条件と2件とも一致した。検査票ではカレンダー内の他の色の用途と、選択後の表示状態に対する1.4.1を未確認として残す。 [観察を帳票に渡す記録](run-001/observations.json) · [帳票と証拠のハッシュ](run-001/reports.json)

観察者・機械run・判定前のAI runで、URL、画面幅、選択前画像のSHA-256が一致した。AI runのコピーへ、画像4点・実キーのイベント記録2点・選択前のアクセシビリティツリー1点を例ごとに添付した。HTML・JSON・Excelの対象判定と検査票を照合し、既知の不適合だけが不適合箇所一覧に出ることを確認した。元の機械runの177ファイルと、AI runの各22ファイルは同じSHA-256だった。 [添付と元ファイルの照合](run-001/reports.json)

## 再実行

Debian、Python 3.12.14、Playwright 1.62.0、Chromium 156.0.8078.79で実行した。共有デスクトップは使わず、起点から別のブラウザー文脈で操作した。採点担当と検査担当の会話・参照先を分けた。共有実行環境での参照範囲は、検査担当への依頼で制限した。Codexの実行モデル識別子・費用は取得できなかった。

観察の原文と全ファイル、判定前の機械・AI run、生成した帳票は `/workspace/wcag-audit-work/evidence/t029-evidence-001.tar.gz` に保存した。SHA-256は `064ed82d49b6070838ab8fb202c2369e6f95e29bc6129aa6469e1161b878f3b3`。

リポジトリのルートから、公開ファイルだけを配信する。

```sh
python3 -m http.server 43929 --bind 127.0.0.1 --directory validation/development/T029/fixture
```

別の端末で、機械用と追加観察用の新しいrunを作る。機械の操作探索は10ステップ・8状態・深さ1。

```sh
t029_results=$(mktemp -d)
python3 validation/development/T029/collect.py \
  --cli skills/wcag-page/scripts/audit.py --out "$t029_results/machine" \
  http://127.0.0.1:43929/u47b/ http://127.0.0.1:43929/m85c/
python3 validation/development/T029/collect.py \
  --cli skills/wcag-page/scripts/audit.py --mode ai --out "$t029_results/ai" \
  http://127.0.0.1:43929/u47b/ http://127.0.0.1:43929/m85c/
```

同じ初期画面で取得した保存済みの観察を使い、元のAI runを新しい出力先にコピーして帳票を生成する。

```sh

  --cli skills/wcag-page/scripts/audit.py --machine "$t029_results/machine" \
  --runs "$t029_results/ai" --out "$t029_results/reported" \
  --observations validation/development/T029/run-001/observations.json
```
