# 日付を選ぶ前の空き状況の見分け方

**WCAG 2.2の達成基準1.4.1「色の使用」の確認結果は、u47bが不適合、m85cが通過。** 対象は、両サイトの2027年5月10〜16日の利用日選択画面で、日付を押す前に空き状況を判断できるかという観点。Chromium 156.0.8078.79を1280×900 CSS pxで使った。

両サイトとも起点の「予約できる日を探す」へTabで移動し、Enterでカレンダーを開いた。表示された凡例と日付を見て、青系の5月10日とピンク系の5月11日を選んだ。各日を別々のブラウザーコンテキストで試し、Tabで日付にフォーカスした時点と、Enterで選んだ時点の画面とアクセシビリティツリーを保存した。イベントログには `isTrusted: true` のTab・Enterと、入力時の対象がある。[起点からの経路](entry-routes.json) · [日付選択の全ログ](date-selections.json)

| サイト | 選択前に使える情報 | 判断 |
| --- | --- | --- |
| [u47b](u47b-02-arrival.png) | 各ボタンの表示とアクセシブルな名前は日付と曜日。別の凡例に「空きあり」「満席」とあるが、日付と凡例の対応を示すのは背景色。5月10日と11日の枠・形は同じで、Tabでフォーカスしても状態の説明は出なかった。 | 不適合。色を見分けられないと、どの日に空きがあるか選ぶ前に判断できない。[グレースケール](u47b-before-selection-grayscale.png) · [5月11日のフォーカス](u47b-11-date-focused.png) · [選択前のアクセシビリティツリー](u47b-02-arrival.ax.json) |
| [m85c](m85c-02-arrival.png) | 7日すべての日付ボタンに「空きあり」か「満席」が文字で表示され、アクセシブルな名前にも含まれる。グレースケールでも、各日の状態を文字で読める。 | この観点を通過。日付と状態を色に頼らず対応付けられる。[グレースケール](m85c-before-selection-grayscale.png) · [5月11日のフォーカス](m85c-11-date-focused.png) · [選択前のアクセシビリティツリー](m85c-02-arrival.ax.json) |

5月10日と11日の背景色は両サイトでそれぞれ `rgb(199, 214, 238)` と `rgb(237, 201, 215)`。WCAGのsRGB相対輝度式で約1.02:1の差だった。グレースケールは選択前の比較画像だけに使い、実キー操作の前に元の表示へ戻した。[取得した表示値](date-selections.json)

| Enterで選んだ日 | 両サイトの結果 | 証拠 |
| --- | --- | --- |
| 5月10日 | 「5月10日には空きがあります。」と表示し、「予約内容を確認する」リンクが現れた。 | [u47b](u47b-10-selected.png) · [m85c](m85c-10-selected.png) |
| 5月11日 | 「5月11日は満席です。別の日を選んでください。」と表示された。 | [u47b](u47b-11-selected.png) · [m85c](m85c-11-selected.png) |

u47bで色に頼らない状態の説明を得られたのは、日付を押したあとだった。結論は、選択前に空き状況を見分ける観点に限る。5月12〜16日は選択前の表示を確認した。選択後の結果は5月10日と11日を確認した。

最初の5月10日の試行ではキーイベントの記録を初期化できなかったため、画面を `preliminary/` に保管して再試行した。本文は4試行分のキーイベントと再取得した画面に基づく。
