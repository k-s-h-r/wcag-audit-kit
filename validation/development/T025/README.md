# 共通ナビゲーションを修正した前後で検査票を比較する

同じナビゲーションのリンクを載せた6ページで、文字コントラストの検査票を比べた。変更したのはページごとの文字色。WCAG 2.2 AAの1.4.3を対象に、Chromium 156の1280×900 CSS pxで初期状態を収集した。

## ページごとの結果

| URLのパス | 変更前 | 変更後 | 照合結果 |
| --- | --- | --- | --- |
| `/resolved` | 不適合 | 通過 | 解消 |
| `/continuing` | 不適合 | 不適合 | 継続 |
| `/new` | 通過 | 不適合 | 新規 |
| `/pending` | 不適合 | 判定未記録 | 未確認 |
| `/excluded` | 不適合 | 検査範囲から除外 | 未確認 |
| `/uncollected` | 不適合 | HTTP 404 | 未確認 |

`/pending` では変更後のaxe測定にリンクの通過が含まれるが、検査票の判定は意図して記録しなかった。比較は未確認と表示した。[実行結果](run-001/summary.json)

## 再実行

リポジトリのルートで、通常のブラウザー検査に必要な依存関係とChromiumを使う。

```sh
python3 validation/development/T025/verify.py --out /tmp/t025-new
```

試験は同じURLで前後のページを配信し、`start`、`record`、`report` で二つのrunを作る。観測対象は共通リンクの `#shared-help`。比較の結果は `comparison.json` と `preview # 1.html` に保存する。HTMLの前後の帳票と証拠へのリンクをたどり、証拠のSHA-256を照合する。

出力ファイルがすでにある場合と、元のrun内を出力先にした場合の拒否も試す。変更後のrunを複製し、複製側の証拠を変えると、その対象は未確認になる。元の前後のrunは比較の前後で全ファイルのSHA-256が一致する。
