# 共通ナビゲーションを修正した前後で検査票を比較する

同じナビゲーションのリンクを載せた6ページで、文字コントラストの検査票を比べた。変更したのはページごとの文字色。WCAG 2.2 AAの1.4.3を対象に、Chromium 156の1280×900 CSS pxで初期状態を収集した。

## ページごとの結果

| URLのパス | 変更前 | 変更後 | 照合結果 |
| --- | --- | --- | --- |
| `/resolved` | 不適合 | 通過 | 解消 |
| `/continuing` | 不適合 | 不適合 | 継続 |
| `/new` | 通過 | 不適合 | 新規 |
| `/pending` | 不適合 | 判定未記録 | 未確認 |
| `/excluded` | 不適合 | 検査範囲から除外 | 未確認 |
| `/uncollected` | 不適合 | HTTP 404 | 未確認 |

`/pending` では変更後のaxe測定にリンクの通過が含まれるが、検査票の判定は意図して記録しなかった。比較は未確認と表示した。[実行結果](run-001/summary.json)

追加試験では、言語を指定しない場合も明示的に `ja-JP` を指定した場合も、同じ条件として扱われた。同じHTMLを `en-US` で開くとコントラストが2.32:1から18.09:1に変わり、比較は環境の差として未確認になった。対象の証拠が別ページの測定だけの場合も未確認になり、同じ検査票への添付に替えると照合できた。[追加試験の結果](run-002/summary.json)

## 再実行

リポジトリのルートで、通常のブラウザー検査に必要な依存関係とChromiumを使う。

```sh
python3 validation/development/T025/verify.py --out /tmp/t025-new
```

試験は同じURLで前後のページを配信し、`start`、`record`、`report` で二つのrunを作る。観測対象は共通リンクの `#shared-help`。比較の結果は `comparison.json` と `preview # 1.html` に保存する。HTMLの前後の帳票と証拠へのリンクをたどり、証拠のSHA-256を照合する。

出力ファイルがすでにある場合と、元のrun内を出力先にした場合の拒否も試す。変更後のrunを複製し、複製側の証拠を変えると、その対象は未確認になる。元の前後のrunは比較の前後で全ファイルのSHA-256が一致する。

複製側で判定を追加した後も、以前の帳票が参照する判定リビジョンを使える。帳票内の判定を書き替えた場合、判定を絶対パスで指定した場合、検査定義の保存ファイルを変えた場合は比較を拒否する。

## 通常の1ページ検査の前後を比べる

```sh
python3 validation/development/T025/verify.py --page-audit --out /tmp/t025-page-audit-new
```

通常の `page-audit --initial-only` と `--resume --quick-explore` で前後を収集し、`record`、`scope-review`、`report` を実行する。HTTP 302で遷移した初期画面と、キーやクリックでURLが変わった画面で、状態・要素一覧・axeのURLが一致することを確かめる。初期画面のChromiumの版とURLは `start` の収集記録とも照合する。コントラストの判定が不適合から通過に変わり、両方の証拠を付けて解消と表示されることを確かめる。[1ページ検査の前後比較](run-003/summary.json)

収集記録から版と遷移先を除いた複製は、未確認と表示される。旧runの版や遷移先が記録されていない場合も同じ扱いになる。試験で判定したのは初期画面の1.4.3。検証全体は前後とも未完了と記録する。
