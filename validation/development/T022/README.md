# URLから工作室の見学予約を調べる

ローカルの予約サイト2例で、起点URLから確認画面に進み、WCAG 2.2 AAのうち2.1.1と2.5.3の選んだ観点を調べた。機械検査で採点できたのは6項目中1件。別のCodexエージェントが実際に操作した後は6件を照合できた。問題例が確認画面に進むには、途中でクリックが必要だった。

| 採点項目 | 正常例 | 問題例 |
| --- | --- | --- |
| キーで1名から2名に変える | 機械・追加検査とも通過 | 機械は未確認。追加検査で不適合 |
| 確認ボタンの表示がアクセシブルな名前に含まれる | 機械は未確認。追加検査で通過 | 機械は未確認。追加検査で不適合 |
| キーだけで確認画面に進む | 機械は未到達。追加検査で到達 | 機械は未到達。追加検査で人数条件の案内まで到達 |

各3ページで、開始から確認画面までを検査した。試験用の手続きは確認で終了する。発話は採点に含めず、2.5.3では画面の文言とChromiumが公開するアクセシブルな名前を比較した。[採点前に固定した対象と期待](run-001/oracle.json) · [採点と成果物の照合](run-001/score.json)

## 問題例ではキーで増員できなかった

増員ボタンにTabで移動し、EnterとSpaceを押したが、人数は1名のままだった。確認すると2名以上を選ぶよう案内された。同じボタンをクリックすると2名になり、次のTabとEnterで確認画面に進めた。[Space後](run-001/rb-06-increase-with-space.png) · [1名で確認した画面](run-001/rb-08-try-review-at-one.png) · [クリック後](run-001/rb-10-increase-with-pointer.png)

確認ボタンの表示は「予約内容を確認する」、アクセシブルな名前は「詳細を見る」だった。正常例は表示と名前が一致し、キーだけで2名を選んで確認画面に進めた。[問題例の画面](run-001/rb-07-focus-review.png) · [アクセシビリティツリー](run-001/rb-07-focus-review.ax.json) · [正常例の確認画面](run-001/na-09-review-with-keyboard.png)

## 機械検査の結果を保存してから追加操作を行った

1. T020で把握した数量変更の観察を、予約の確認までの経路に広げた。採点側で正常例・問題例と6項目の期待結果を固定した。検査側には起点URLと共通の検査条件・観点を渡した。採点の正解は検査役が参照するファイルに置かなかった。
2. 起点から公開リンクを抽出し、発見した4ページを通常の `wcag-page` で初期収集と簡易探索にかけた。確認画面へのリンクはなく、機械検査では未到達だった。
3. 別のCodexエージェントは、先に保存した機械検査のURL一覧を参照し、起点から画面上のリンクを操作した。最初の証跡の採取と画面遷移が重なったため、同じ起点から再試行した。各操作の表示、フォーカス、アクセシビリティツリーを保存した。
4. T021とT024のコードを含む作業ブランチで、追加操作で見つかった両例の確認URLを収集した。HTTP 200とaxeの証拠を保存し、所見を検査票と不適合箇所一覧へ反映した。問題例の報告は2.1.1と2.5.3の不適合、正常例の報告は範囲全体の未確認を示す。問題例の2件は再現手順と証拠を一覧から参照できる。[操作記録](run-001/observations.json)

## 再実行

Debian、Python 3.12.14、Playwright 1.62.0、Chromium 156.0.8078.79を使用した。機械検査は1280×900と320×900、追加操作と手続き報告は1280×900。Codexの別エージェントが最初と最後の画面を保存した間隔は122.5秒。モデル識別子・トークン数・費用は取得できなかった。[環境](run-001/environment.json)

公開ページのサーバーを別の端末で起動する。

```sh
python3 -m http.server 43822 --bind 127.0.0.1 --directory validation/development/T022/fixture
```

```sh
python3 validation/development/T022/collect.py --cli skills/wcag-page/scripts/audit.py --out /tmp/t022-machine-new http://127.0.0.1:43822/na/ http://127.0.0.1:43822/rb/
python3 validation/development/T022/report.py --cli skills/wcag-audit-kit/scripts/audit.py --observations validation/development/T022/run-001/observations.json --out /tmp/t022-report-new
```

全操作の原始証拠と両例のHTML・JSON・Excelを `t022-evidence-001.tar.gz` に保管した。保存先は `/workspace/wcag-audit-work/evidence/`。SHA-256は `b2e22d92a1e9c09911a7ad0f2b68a0a03a42c72721e5952d7617d40732a8355f`。

T023へ問題例の経路を渡す。増員と確認ボタン名を改善し、キーボードだけで確認まで進めるかを測る。[T023](../../../docs/tasks/T023-accessibility-review-pilot.md)
