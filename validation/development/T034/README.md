# T034 Tabのフォーカスに伴う文書移動要求と遮断

通常の `page-audit` に渡すのは公開ページのURLと共通の実行設定だけ。表示幅はPC相当1280×900とスマートフォン相当320×900 CSS px。機械モード、AAA、初期画像のみとし、初期取得の後に `--resume --quick-explore` を実行する。問題集の達成基準、想定操作、対象、期待値は収集後の照合に使う。[T020の測定条件](../T020/README.md)

T020の071・072は3.1.1の回帰対照、073・074は3.2.1-02の問題例と正常例。さらに、3.2.1のc01・c02と、移動要求のきっかけを変えたループバック専用の対照を使う。書き込み先と移動先もローカルの対照ページを使う。

## 結果

変更前の `run-000` と変更後の `run-003` を比較した。073とc01では、変更前も両画面幅で最初のTabの後に移動先への通信を遮断した。変更後は、同じ停止記録から `#subject` のフォーカス、別文書への移動通知、Tabを離した時点の通知の状態、メインフレームの要求の遮断までを両画面幅で追えた。3.2.1の正常例074とc02では発生元を関連付ける記録は0件だった。071の言語指定の指摘と072の通過は両画面幅で確認した。

| 追加の対照 | 両画面幅で確認したこと |
| --- | --- |
| Enterによる起動 | 実際のEnterが届き、その経路で別文書への要求を遮断した。Tabのフォーカスとしての記録は0件 |
| タイマー | 別文書への要求を遮断。Tabのフォーカスとしての記録は0件 |
| ハッシュ | 同一文書内の移動を入力ログに記録 |
| iframe | 子フレームの文書要求を遮断。停止記録に子フレームを記録 |
| バックグラウンド通信 | 文書移動以外のPOSTを遮断 |
| 取消とキーアップ | 同じURLへの通知が2件。最初の取消を記録し、遮断との対応は保留 |
| 取消または文書内での処理と、子フレームからの要求 | メインフレームの文書要求を遮断。子フレームを記録し、発生元の特定は保留 |

独立レビューでは、取り消した移動通知を後から同じURLを要求した操作に誤って結び付ける例を再現した。修正後は、追加の不透明なiframeを使った例も含め、発生元の照合を保留することを別の通常CLIで確かめた。途中で追加したiframeも観察範囲に入った。

最終の帳票文言は `run-004` の073・074で確認した。073のHTMLとJSONには、両画面幅で「Tabの観察中に#subjectへフォーカスが移った」「フォーカスイベントの配信中にメインフレームで別文書への移動が要求された」と停止記録の参照が出た。3.2.1の適否はExcelのチェックシートとJSONで未確認。旧runは現行CLIで報告を再生成でき、現行版で探索を実行する場合は新しいrunを求める既存の確認が働いた。

実測環境はLinux、Python 3.12.14、Playwright 1.62.0、Chromium 156.0.8078.79。変更前は `8520421`、主な変更後の対照と独立レビューは `d1ef2e7` で確認した。`run-004` は補助Tabの帳票文言を調整した版で実行した。実装のユニットテストは325件通過した。

変更前6件、変更後14件、最終文言2件の全22件で初期取得と簡易探索が終了した。サーバーが受信した260件のうち、遮断対象の移動先と書き込み先は0件だった。各runの要約、受信記録、帳票、入力と停止の記録、独立レビューの対照、旧runの再報告結果を収録した。ZIP内の `sha256.json` で収録ファイル855件を照合できる。ZIPのSHA-256は `5a776133e164ea8204dad4d67afa3d9766cfa13d70192e2711e19a14b9807105`。[証拠のZIP](proof.zip)

## 証拠の読み方

`page/work/evidence/<観察>/keyboard-trace-stop.json` の `focus_navigation` は、受け取ったTabのキー押下、フォーカス、ブラウザーの `navigate` 通知、Tabのキーアップへの添字を保存する。四つのイベントは同じディレクトリーの `input-events.json` にある。`isTrusted`、メインフレーム、移動元の文書IDとURL、フォーカス先、`focusDispatchPhase`、移動先URLを照合する。キーアップの `navigationAtKeyup` では、同じ通知が配信を終え、取り消しや中断を受けていないことを確認する。照合する文書要求は停止記録の `blocked_requests` にある。HTMLの操作経路詳細とJSONの `exploration.remaining` に、この観察と保存先が出る。

子フレームが補助観察中に見つかった場合は、停止記録に `child_frame_observed` を残す。トップの文書に通知が出ない移動経路があるため、発生元の照合は保留する。

`status: blocked` は、移動先の文書への通信を制限したことを表す。移動先を受信したかはサーバーの受信記録と照合する。この実証は停止時の観察記録を照合する。3.2.1の適否には、移動先の表示やほかのフォーカス先、操作結果などの追加の確認が残る。
