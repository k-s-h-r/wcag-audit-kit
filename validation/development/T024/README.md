# T024 キーボード操作後の数量を比較した結果

URLだけを渡した機械検査で、クリックでしか数量を変えられない問題例を新たに検出した。T020の既存8行を維持し、問題39行の検出数は8行から9行になった。対照48行のうち、新たに通常のキー操作と別ボタンによる代替操作の2行が一致し、合計は14行から16行になった。採点範囲での誤検出は0行だった。 [全87行の比較](run-001/comparison.json)

## 同じ初期表示からクリック・Enter・Spaceを試した

いずれも初期値は0で、1280×900と320×900 CSS pxで同じ結果になった。クリックは対象に届いたマウス入力を、キー操作はTab到達後に対象へ届いたキー入力を記録した。キーを送出できても値が変わらない場合は、機能の結果を別の観点として報告する。 [入力と状態の記録](run-001/keyboard-evidence.json)

| ページ | クリック後 | Enter後 | Space後 | 2.1.1-02の結果 |
| --- | ---: | ---: | ---: | --- |
| 030 通常のボタン | 1 | 1 | 1 | 対照と一致 |
| 031 クリック専用のボタン | 1 | 0 | 0 | 問題を検出 |
| 032 キーで操作できる別ボタンあり | 1（`#pointer`） | 1（`#control`） | 1（`#control`） | 代替経路の対照と一致 |

032は、採点入力を `#control` の直接操作の報告行だけに絞ると、両幅とも代替経路として採点されなかった。採点には `#pointer` のクリックと、`#control` のキー操作を照合した証拠が必要。独立レビューでは、祖先にキー割り当てがある例と、フォーカスで別ボタンが現れる例を未確認とした。ポインターを押した時点で利用回数が変わる例は機能の問題として指摘しなかった。 [記録と原始ファイル](run-001/keyboard-evidence.json) · [レビューとPR #87](https://github.com/k-s-h-r/wcag-audit-kit/pull/87)

## 旧版で時間切れになった5ページは別runで再試行した

T020と同じ76ページ・87行を、旧版 `67aa42e8a9e01e9b4ec9485c6e4d45c9209625b9` と変更版 `8fe594a79958c572ddf8ddf7f65c751065bcad75` で測った。今回の環境はLinux x86_64、Python 3.12.14、Playwright 1.62.0、Chromium 156.0.8078.79。公開T020の環境はmacOS arm64とChromium 149で、ローカルの変更前後の比較には同じLinux環境を使った。問題集の版は公開T020と同じ。 [T020の測定条件](../T020/README.md)

旧版の初回は6並列で、041・042・043・044・048の簡易探索が240秒で時間切れになった。この5ページだけを同じ旧版・ブラウザー・採点条件で2並列の別runに取り直した。初回の成功分71ページと組み合わせた旧版の結果は、公開T020と87行すべてが一致した。変更版は6並列の初回で76ページを収集できた。今回の結果から実行時間の差は評価していない。 [旧版の初回](run-001/before-score.json) · [旧版の再試行](run-001/before-retry-score.json) · [変更版](run-001/after-score.json)

| 採点 | 問題39行の旧版→変更版 | 対照48行の旧版→変更版 |

## 再実行と証拠の参照

それぞれのコミットの作業ディレクトリで、収集と採点を実行する。下の `RUN` は新しい出力先、`SCORE.json` は新しい採点ファイルに置き換える。CLIへの入力は、ページごとのURLと共通設定だけ。レベルはAAA、モードは機械、撮影は初期表示のみで、簡易探索の上限は24ステップ、16状態、深さ3。

GitHubから作業ディレクトリを作る場合、変更版は公開コミット `61d9e84` を使う。測定時のローカルコミット `8fe594a` と `benchmarks/`・`skills/` の内容が一致する。 [公開コミット](https://github.com/k-s-h-r/wcag-audit-kit/commit/61d9e84dca12b3afe33ed199a0411af43705016b)

```sh
python3 benchmarks/url_only_machine.py --out RUN --workers 6
python3 benchmarks/url_only_machine.py --out RUN --score SCORE.json
```

失敗したページを取り直すときは、PRの作業ディレクトリから `python3 validation/development/T024/retry-incomplete.py RUN RETRY BASE_CHECKOUT` を実行する。`RETRY` は再試行の新しい出力先、`BASE_CHECKOUT` は `RUN` の収集に使ったコミットの作業ディレクトリ。 [再試行に使うスクリプト](retry-incomplete.py)

`comparison.json` は `page_id`・`criterion`・`case`・`page`・`state`・`target`・`checkpoint`・`expected` で各スコアを照合した記録。旧版で再試行を用いた行は `before_source` が `before_retry` になる。スコアの根拠パスはそれぞれのrunを起点とする。数量変更3例の前後で使った原始ファイル158件はZIPに保存した。`keyboard-evidence.json` のパスには、ZIP内で `before/` または `after/` を付けて参照する。 [入力ログ・状態・帳票を収めたZIP](run-001/keyboard-raw.zip)

全ページの原始証拠はローカルの `artifacts/t024/t024-run-001-full.tar.gz` に保存した。SHA-256 は `a3aa9d0bc1b2c1c8df74fbc96fe8d3eeed6fe982420c83764fed5131d5932c26`。展開した `t024-before/`、`t024-before-retry/`、`t024-after/` から、各スコアに記載した根拠をたどれる。

観測範囲は、初期表示に見える数値の `output` が一つあり、同じ起点から結果を比較できる操作。変更後も問題30行、対照32行が未確認で、別の機能、操作の連続、異なる状態での結果は追加検査が必要。数量比較の根拠は一連の手続きを試すT022で参照する。 [ADR 0096](../../../docs/adr/0096-compare-keyboard-function-results.md) · [T022](../../../docs/tasks/T022-url-to-process-audit.md)
