# ポインター取消の方法を比較ページで校正する

同じログ追加機能を持つ2ページで、通常実行と、押下後に対象外へ移動して解放する取消操作を実行した。初期表示からの取消に加え、1件追加済みの状態を再現して同じ操作を実行した。

| 観察 | up-eventの例 | down-eventの例 |
| --- | --- | --- |
| 初期0件から押下 | 0件 | 1件 |
| 対象外で解放・再読み込み | 0件 | 1件のまま |
| 通常のクリック | 1件を作成 | 1件を作成 |
| 1件追加後から押下 | 1件のまま | 2件 |
| その後の対象外で解放・再読み込み | 1件のまま | 2件のまま |

各段階の実画像、表示件数、trustedイベントと対象を照合した。普通のログ追加で、打鍵の模倣や正確な押下時刻を必要とする機能ではない。原典の4条件を照合し、この比較例の2.5.2を通過3件・不適合3件として記録した。残る324件は未実施であり、サイト全体の検証は未完了。

## 検証方法の失敗を取り違えない

別の試験では、取消領域にポインターを置いたまま、ボタンを押したという検査を行おうとした。実イベントの対象がボタンと異なるため、収集器がblockedで停止した。ページのWCAG不適合とは判定していない。

## 確認した範囲

これはChromiumのブラウザー自動操作によるデスクトップのマウス入力の校正。実物のタッチ端末、他のブラウザー、すべてのWCAG基準を試験した結果ではない。試験の設定にあるassertは状態への到達確認であり、基準の期待結果とは分けて判定した。

[検証方法](../../references/pointer.md)に沿って、新しい対象でも実際の機能と適用条件を調べる。これらの結果を別のサイトへ流用しない。
