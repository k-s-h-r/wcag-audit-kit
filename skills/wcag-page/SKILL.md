# 1ページを実際に検証する

入力はURL、必要なら既存run・タスク・認証・状態の到達手順。出力はページの各基準の判定、画像から調べた操作・状態、証拠、必要な人への確認。利用者に基準番号を選ばせない。

## 実行ルートと開始

このSKILL.mdの場所から上位へ探し、`scripts/audit.py`と`references/catalog.json`があるディレクトリーを使う。単体配布ではこのスキルのディレクトリーが実行ルート。

独立した1ページなら、実行ルートから次を実行する。

```sh
python3 scripts/audit.py page-audit --url <URL> --out <新しいrun> --profile standard
```

認証や表示環境には`--config <設定>`を渡す。事前設定のstatesを収集する検査は既存のpageコマンドを使い、自動探索に追加の独自シナリオが必要ならprobeで検査する。単独入口は指定URLだけを収集し、リンクを巡回しない。設定未指定時の初期環境はdesktopとnarrow。実拡大等の追加環境は、基準に応じて調べ、設定又は追加検証で用意する。

既存runの担当なら収集を繰り返さず、`page-next --run <run> --page-exact <URL>`又は`pending --run <run> --page-exact <URL> --task <ID>`から読む。機械検査の収集成功は検証完了ではない。

## 機械検査から自律的に進める

[1ページの実行手順](../../references/page-audit.md)を使う。page-auditはAIサービスへ接続せず、操作候補・状態のキューを探索し、実状態ごとのaxeと実入力の結果を記録する。page-nextで残作業を読み、キューが残れば適切な上限で--resumeする。自動検出した対象以外は画像から追加確認する。

まず機械ルール・実操作・測定・既存アダプターで確認し、意味・目的等で必要な部分だけ内容判断する。実行できる検査を手順だけ書いて人へ渡さない。方法が足りなければ代替を調べ、小さい経路で実行を確かめて続ける。人の権限や専門判断が必要になった場合だけ具体的な引き継ぎを作る。

各担当票をrecordし、page-nextから次の票へ進む。探索の解消にはその版に対応する追加証拠を保存する。既存の画像・判定を変更しない。未確認を適合へ変えてループを終了しない。機械ルールの通過やTabによる到達だけで基準全体を確定しない。

## 画面から操作と状態を調べる

[画面の調査手順](../../references/visual-discovery.md)を読む。保存した画像を画像表示ツールで実際に見る。見た目、ラベル、位置から、リンク、ボタンに見える領域、メニュー、入力、開閉、ドラッグ等を列挙する。divかbuttonかは、その後にDOM・ツリーと対応付けて調べる。コード上のイベント検索だけで候補を確定しない。

各候補について、到達・開始・内部操作・終了・閉じた後のフォーカスを実際の入力で確認する。初期表示だけでなく、開いた後、入れ子、エラー、条件付き表示も調べる。モーダル内のTab循環を、それだけでキーボードトラップとしない。

操作する経路とテスト環境を確認する。送信・削除等を無差別に実行しない。未探索の対象と、追加で必要な画像・環境・操作を残す。新しい状態が設定に必要なら元のrunを保持して新しい設定・runで収集する。

ページごとの[操作調査票](../../assets/interaction-review.example.json)を実際の画像・操作へ具体化し、`review-interactions --run <run> --file <票>`で保存する。調査票の版はplanのinteraction_reviewsから読む。初回のbase_reviewはnull。

## 基準ごとに検査する

1. `case --run <run> --id <case_id>`から対象・本文・手順・版を取得する。該当基準の原文、例外、公開テストを必要な分だけ読む。
2. 全対象へ操作・期待結果・観察方法を具体化する。画面・意味・操作を実際に比較する。axeやDOMの属性だけを基準全体の通過にしない。
3. [方法一覧](../../references/methods.md)から必要な道具を使う。実SRがrequiredなら実際の支援技術で確認する。ツリーやVirtual Screen Readerを実SRと呼ばない。使用できなければ具体的な引き継ぎを記す。
4. [記録規約](../../references/recording.md)に従いrecordする。共同作業はbase_assessmentで版を照合する。未実施の票を残したまま全基準確認済みとしない。
5. ページ間比較・手続き全体が必要なら、必要なURL・状態・操作を残して全体進行へ返す。単独ページだからという理由で対象外にしない。

## 観察の予算と終了

[観察設定](../../references/inspection-profiles.md)を使う。画像なしでは画面の操作対象を調査済みにせず、見ていない画像を読んだと記録しない。SRの省略と適用対象の不在も区別する。

今回の担当票に判定又は具体的な引き継ぎを記録し、未探索の操作・状態・省略した観察を説明して渡す。`page-report --run <run> --page-exact <URL>`でページだけのHTML・JSON・Excelを出す。機械検査の結果・基準全体の適否・具体的な箇所・証拠・未確認が区別されているか確認する。サイト全体の適合を宣言しない。
