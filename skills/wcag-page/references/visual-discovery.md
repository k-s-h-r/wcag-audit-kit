# 画面から操作対象と状態を調べる

画面を見て操作できそうな対象を探し、その対象をDOM・アクセシビリティツリー・実際の入力と対応付ける。buttonタグやイベントリスナーだけを起点にすると、divのクリック領域、画像、canvas、見た目と公開された役割が異なる対象を見落とす。

## 実際に見る

1. 初期表示の画像を画像表示ツールで開く。画面全体を確認できない場合はスクロール・表示領域の画像を追加し、未表示の範囲を残す。
2. ボタンらしい領域、リンク、メニュー、入力、開閉、タブ、ドラッグ等を、見えるラベルと位置で列挙する。roleやtabIndexは、候補を見つけた後の対応付けと検査に使う。
3. 操作対象を実際のキー又はポインターで使う。見える機能がキーボードから使えるか、開始・内部操作・終了を確認する。
4. 開いた状態、入れ子、エラー、条件付き表示を新しい調査対象として扱う。閉じる・離脱と、その後のフォーカス位置も確認する。
5. 各対象に、見た目の位置、実操作、観察、証拠、未探索の操作を残す。画像だけではクリック可能性を確定できないため、実動作と照合する。

モーダル内でTabが循環すること自体は不適合ではない。実際にキーボードで閉じて離脱できるか、通常以外の離脱方法があればその案内も確認する。矢印キー等を使う部品を、Tabだけで検査済みにしない。

## 調査票を保存する

[例](../assets/interaction-review.example.json)を、実際のpage_id・capture key・画像・操作へ具体化する。plan.jsonのinteraction_reviewsにあるそのページの現在の版をbase_reviewへ写す。初回はnull。

```sh
python3 scripts/audit.py review-interactions --run /project/run-page --file /project/interaction-review.json
```

capturesは同じページの状態・環境の調査。各visualのstatusはreviewed / partial / skipped、操作対象のstatusはtested / unverified / human。画像・操作の証拠はrun内に保存し、外部ツールの証拠はattachで取り込む。states_completeは、その収集範囲で未観察・未探索が残らないときだけtrueにする。

画像offや上限で調べられなかった範囲は、partial又はskippedと具体的な残作業を記す。操作していない対象をtestedにしない。すべての状態・分岐を発見したことを、1枚の画像や1回のTab移動から推測しない。

screen_readerには実施方法・発話等の観察・証拠、又は省略した理由を記す。AXツリーとVirtual Screen Readerだけでは、実SRのreviewedとして記録できない。

調査票は版ごとに保存し、画像・操作証拠のハッシュを保持する。ページ担当が異なる場合も、他ページの票を上書きしない。保存した証拠が変われば集計を止める。ただしソフトウェアは、AIが画像を実際に読んだことや、判断が正しいことまでは保証できない。
