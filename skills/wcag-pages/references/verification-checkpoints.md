# 確認観点ごとの処理・準備・残る判断

[モードの仕様](verification-modes.md)と[READMEの対応表](https://github.com/k-s-h-r/wcag-audit-kit/blob/adf459777fa43ea0898a95e43edf5dbdde0684b7/README.md)から、必要な観点を開いて使います。対応表の原本は[確認観点の定義](verification-checkpoints.json)です。記号は実施結果ではありません。

<a id="111-01"></a>

## 1.1.1-01 非テキストコンテンツ

確認すること：画像や操作部品に設定された代替文・読み上げ用の名前を確認する。

プログラムの処理と限界：画像・部品の属性と支援技術向けの名前を取得し、axeの該当ルールを実行する。

実行方法・必要な準備：`page-audit`を実行する。探索できた状態の範囲で記録する。

AIの補助：この行の取得・機械検査には使わない。

人の確認・準備が必要になる場合：対象のページ・状態へアクセスする権限や、取得に必要な実行環境を用意できないとき。

制約：対象・操作・期待値を指定した機械検査又は証拠取得。内容の意味の判断は含まない。

[基準の手順](criteria/1.1.1.md)

<a id="111-02"></a>

## 1.1.1-02 非テキストコンテンツ

確認すること：背景画像・SVG・図表なども検査対象に含まれているか。

プログラムの処理と限界：標準の要素一覧に出ない対象を指定し、画像とその説明を取得する。

実行方法・必要な準備：実画面と要素一覧を照合し、不足する対象を指定して調べる。

AIの補助：実画面から、要素一覧に出ない画像・図表等を探す。

人の確認・準備が必要になる場合：実画面や要素一覧を取得できず、背景画像等の対象を特定できないとき。

制約：機械のみ・SRのみでは証拠取得や一部検査まで。画像・文章・操作結果の意味はAI又は人が比較する。

[基準の手順](criteria/1.1.1.md)

## 1.1.1-03 非テキストコンテンツ

確認すること：必要な代替説明を、実際のスクリーンリーダーで利用できるか。

プログラムの処理と限界：対象を操作し、実際に読み上げた名前・説明を記録する。

実行方法・必要な準備：[スクリーンリーダーの手順](screen-reader.md)で環境と対象ごとの操作を準備する。

AIの補助：画像の目的と、実際に読み上げた名前・説明を比較する。

人の確認・準備が必要になる場合：必要なスクリーンリーダーの環境や操作経路を用意できないとき。

制約：実際のスクリーンリーダーの環境と対象ごとの操作が必要。ツリーの取得では代用しない。

[基準の手順](criteria/1.1.1.md)

人の確認・準備が必要になる場合：音声のみの内容比較で信頼できる聴取手段がないとき。現在の実証環境では人の聴取が必要。

制約：一部だけ実証、又は条件を網羅する方法が不足。全対象・全条件を確認済みにしない。 全区間の映像・音声・代替を比較できるよう保存する。意味の一致の自動判定はない。
