# 実ブラウザーの拡大を検証する

1.4.4では文字を200%にして全内容・機能の保持を確認する。1.4.10では原典に沿った表示幅・高さでリフローを検査する。1280 CSS pxから400%に拡大して320 CSS px相当にする方法も使えるが、二次元配置の例外や、横方向の読み取りでは256 CSS px相当という条件も別に確認する。拡大率の操作が成功しただけでは両基準の合格にはならない。

1.4.4は、利用可能な少なくとも一つの方法で文字を200%まで拡大できるという条件。選んだ方法に中間段階があれば、その段階でも内容・機能を保つ必要がある。一つの方法で損失を見つけても、原典の条件を満たす別の拡大方法の有無を確認せずに基準全体の不適合へ変換しない。

ブラウザーの倍率と、実際の文字の拡大も区別する。100%時と各段階のinventoryから同じ文字のfontSizeとDPRを比較し、画面で実際の表示を確かめる。メディアクエリーでfontSizeが小さくなる場合は、ブラウザー200%が文字200%になっているとは限らない。変形、切り取り、別の文字画像等も個別に観察する。

## Linuxでの実行環境

収集器は専用のXvfbとChromiumを起動し、XTestでブラウザーへ実際のCtrl+0、Ctrl+=を送る。既存の利用者のデスクトップへキーは送らない。必要なものはLinux、Chromium、Xvfb、libX11、libXtst。デスクトップ全体の補助画像にはffmpegも使う。

```sh
python3 scripts/audit.py doctor
```

XvfbがPATH上にない場合は、利用可能な実体を環境変数`WCAG_XVFB`に指定する。依存物を揃える方法は実行環境に従う。起動できなければ、その収集を`blocked`にして原因を残す。macOS・Windowsでは、使用できるネイティブブラウザー操作を調査し、同じ観察条件を満たす証拠を追加する。

## 設定と実行

既存の設定の`environments`へ必要な環境を追加する。表示幅・高さは100%時のコンテンツ領域を指定する。

```yaml
environments:
  - id: desktop
    viewport: {width: 1280, height: 900}
    zoom: 1
  - id: zoom-200
    viewport: {width: 1280, height: 900}
    zoom: 2
  - id: zoom-400
    viewport: {width: 1280, height: 900}
    zoom: 4
```

`start`と`probe`の両方で設定を使用する。拡大した後、指定した状態へ実操作で到達し、assertを確認する。初期表示だけでなく、開閉・エラー・完了等も対象にする。

110%・125%・150%・175%の環境も必要に応じて設定できる。ネイティブ拡大の環境では、状態のactionsに`{"type":"zoom","factor":1.25}`等を追加し、エラーや開閉後の状態のまま中間倍率を試すこともできる。`factor: 1`で100%に戻し、内容・状態を比較する。

## 残す証拠

`native-zoom.json`に100%時と拡大後のinner/outer寸法、DPR、visualViewportの倍率、CSS zoom、キー操作を残す。DPRの比、同じ外側の幅、逆比例するCSS表示幅、ピンチ倍率が1という条件を照合する。値が合わなければ拡大済みとせず停止する。

到達までの100%・110%・125%等には、`native-zoom-<倍率>.png`とinventoryも保存する。これらの初回の資料は**設定した状態の操作を実行する前**の表示。エラー等の状態を確認した証拠には流用しない。zoomアクション内の資料には、その操作段階を別に記録する。静止画を保存しただけで、その倍率で全機能を操作したとは扱わない。

拡大時の`page.png`等は、ネイティブ画素で取得した**現在の表示領域**。付随するJSONに寸法と領域を記す。ブラウザー内部のCSS座標をそのままクリップへ使うと画像が切れるため、この場合はクリップを指定しない。ページ全体の画像とは呼ばない。未表示部分は、キー操作や`scroll`操作で移動して追加確認する。固定要素やスクロール領域の中、ダイアログ等も対象にする。

```json
{"type":"scroll","delta_x":0,"delta_y":500}
```

ffmpegが利用できる場合は`native-desktop.png`へブラウザーのUIを含む画面も保存する。実際の200%・400%表示を補助証拠として確認できる。

## 検証方法を試す

同梱の`tests/fixtures/contact.html`では、200%・400%でメール入力から送信完了まで操作する。初期表示、エラー、完了の内容を基準に沿って比較する。

`tests/fixtures/zoom-clipped.html`は、この拡大方法で機能を失う比較例。100%では存在するダウンロード操作が、表示幅800 CSS px以下で消える。1280pxから200%へ実際に拡大し、操作部品を失ったことを画面・DOM・到達可能な操作から確かめる。別の文字拡大方法の有無は別に確認する。

`tests/fixtures/zoom-intermediate.html`は、100%と200%では操作部品が存在し、125%では消える比較例。200%の最終表示だけで損失なしと判断しないことを試す。比較用ページの存在だけを、検証方法が動いた証拠にはしない。
