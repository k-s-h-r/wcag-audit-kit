# 観察方法と検証環境

検査方法の名前と、実際に利用できる道具を区別する。`doctor`がChromiumを見つけても、スクリーンリーダーや実ブラウザー拡大を確認できたことにはならない。

| 方法 | 実行すること | この収集器で用意できるもの |
| --- | --- | --- |
| dom | 実際の要素・属性・関連付け・計算済み情報を取得する | DOM、要素一覧、CDPのアクセシビリティツリー |
| visual | 実画面を見て位置、表示、隠れ、意味のある図等を調べる | 初期・操作後・キー移動後の画像。AIが画像を実際に見る |
| semantic | 内容・目的・文脈と、ラベルや説明等の意味を比較する | 画面、本文、DOM。AIが内容を読んで根拠を記録する |
| keyboard | 実際のキーで機能を開始から完了まで利用する | Tabの証拠と、probeで指定するキー操作。自動Tabだけで全機能完了とはしない |
| pointer | 押下、解放、取消、単一ポインターの代替等を操作する | [ポインターの手順](pointer.md)に沿ってmove/down/up、click、dragを実行し、対象への到達・状態・入力ログを比較する |
| flow / cross-page | 利用フロー全体、複数ページの共通内容を比較する | paths、states、各ページの証拠。比較対象を結果へ明記する |
| measurement | 実際の色、寸法、時間等を取得して測る | computed styleと矩形。measure.pyで色と間隔、[フォーカス表示の手順](focus-appearance.md)で同一画素の前後の比と面積の計算を補助する |
| viewport | 必要なCSS pxの表示幅・高さで利用する | 設定したviewportを記録。全内容・操作はAIが別途確認する |
| zoom | 実ブラウザーの200%等で利用する | [Linux用アダプター](zoom.md)でChromiumを200%・400%へ実際に拡大し、測定値・表示領域の画像・操作結果を保存する。依存物がない環境では別の実ブラウザーで実施する |
| screen-reader | 実際の支援技術の操作モードで読み上げ・通知・移動を確認する | [Guidepup又はLinuxのネイティブOrca](screen-reader.md)で実際の操作と発話を取得する。ツリーやVirtual Screen Readerは別の証拠として区別する |
| media / audio | 全区間の映像・音声・字幕・説明を再生して比較する | [媒体の手順](media.md)で、ストリーム・全復号・実プレーヤーの字幕操作と表示を取得する。内容の比較に必要な聴取等の手段を別に確認し、区間ごとに記録する |
| sign-language | 手話の内容と元内容の対応を判断する | 意味を判断できる手段がなければ未確認にする |
| flash-analysis | 全発生区間を閃光の回数・面積・色の閾値で分析する | 適切な分析道具と手法を調べる。肉眼や一定間隔の画像抽出だけで安全としない |
| timing | 時間制限、延長、失効、更新等を再現して測る | [時間制限の手順](timing.md)で起点・警告時間・10回の延長・再認証後の完了・データ保持を確認する。待った時間と資料上の値を区別する |
| orientation | 縦横で表示・操作の制限、状態の保持、代替等を確認する | [向きの手順](orientation.md)で、画面とAPIを計測するChromiumのエミュレーションを実行できる。実端末が必要な制御は追加して調べる |
| motion-input / touch | 動き、タッチ、複数入力方式を変えて利用する | 必要な端末・センサー又は検証可能な環境を調べる。エミュレーションと物理端末を区別する |
| reduced-motion | 利用者が動きを抑える仕組みで同じ操作をする | [動きを抑える手順](reduced-motion.md)で通常設定と無効化を実操作し、実時間の表示・位置と情報・機能の保持を比較する |
| password-manager | マネージャー、自動入力、貼り付け、代替認証で最後まで進む | 実際に利用可能な認証支援を調べて操作する。属性だけで利用可能としない |
| reading-level | 使用言語と対象内容に適した方法で読解水準と補足版を評価する | AIの内容判断と適切な資料。英語専用の数式だけで日本語を判定しない |

## 方法を調査して仕様にする

対象基準の本文と関連する公開テストを読み、必要な観察を特定する。既存テスト・ブラウザー・OS・支援技術・分析道具から使用可能な方法を探す。具体的なコマンド・操作・期待する観察・証拠の保存方法を書き、小さな経路を実行して手順自体を確かめる。

使用できなければ、代替方法が原典の同じ条件を検査できるか調べる。できない場合は、必要な環境と残る操作を指定する。ツールがないという理由を、コンテンツの対象外へ変更しない。

## 収集器の限界を補う

要素一覧は最大15,000要素で打ち切りを記録する。大きなページではDOM全体や追加の操作ツールで全対象を列挙する。背景画像、shadow DOM、iframe、canvas等は通常の要素一覧だけでは確認が不足する。必要な内部・別コンテキストを調べる。

CSSによる文字間隔の補助は一般的な要素とpの段落を対象にする。他の段落構造、言語、別コンテキストも確認し、本文の適用条件に沿って追加する。幾何学的な重なりやクリック位置だけで、見え方・実際の当たり判定を確定しない。

ネイティブ部品では、hover・押下時に`getComputedStyle()`の背景色が同じでも、UAが実際に塗る色は変わる場合がある。実画面と照合し、必要なら文字や境界・影のない背景部分の画素を調べる。文字のアンチエイリアスの画素を前景色として測ることとは区別する。キーやホイールによるスクロールも非同期で進むため、移動量が落ち着き目的の領域が見えたことを確認してから画像を証拠とする。
