# 操作によるアニメーションを抑える方法を検証する

[2.3.3の本文・公式解説](sources/2.3.3.md)と[関連Tests](tests/2.3.3.md)を読む。操作で始まる動きと、その全対象、動きが機能又は情報に本質的かを特定する。

1. 通常の設定で実際のキー・ポインター等から操作し、位置・大きさ・描画・経過時刻と画面を記録する。
2. サイト又はUAにある動きを無効化する経路を操作する。`prefers-reduced-motion`を使う場合は、設定を変え、`matchMedia`の結果も確認して同じ操作を繰り返す。
3. 実際の動きが無効になったかと、情報・機能を保持して活動を完了できるか比較する。
4. 無効化できない場合は、他の手段の有無と本質性の例外を調べる。media queryを使わないことだけを不適合にしない。

収集器の`reduced_motion`操作はChromiumの設定をエミュレーションできる。物理端末のOS設定を操作した試験とは分ける。検査器が著者CSSへ一律に`animation:none`を注入して止めても、利用者に提供された無効化手段の証拠にはしない。

固定されたcanvasや動画の内部では、外枠の矩形が同じでも中の絵が動く。`getAnimations()`が空、又は矩形が同じことだけを無効化の証明にしない。全描画とソースを比較し、信頼できる方法がなければ[人へ引き継ぐ](human-review.md)。

[実時間での比較](https://github.com/k-s-h-r/wcag-audit-kit/blob/adf459777fa43ea0898a95e43edf5dbdde0684b7/validation/reduced-motion/README.md)では、通常時は動く装飾がreduceで止まり主機能を保持する例と、reduceを無視する例を実キーで確認した。
