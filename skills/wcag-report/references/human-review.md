# AIで確定できない検証を人へ引き継ぐ

環境制約、信頼できる検証方法の不足、専門知識が必要な判断、現実的に実施が難しい検証は、人へ引き継げる。通常のソース確認、実画面の観察、キー・ポインター操作等は先に進め、引き継ぐ項目でも実施できる観察を残す。

## 引き継ぐ前に行うこと

1. 対象URL、状態、環境、基準と実際の対象を列挙し、本文の条件・例外を確認する。
2. [方法の準備状況](VERIFICATION-COVERAGE.md)とプロジェクトで使える道具を調べ、小さい経路で試す。実行不能と内容の不適合を区別する。
3. 取得できる画面、DOM、発話、元媒体・字幕・全長、操作ログ、仕様等を保存する。
4. 対象ごとに残る操作、判定条件、必要な知識・環境、証拠、結果の戻し方を具体化する。
5. `human_handoff`を含む判定を`record`へ渡す。依頼内容は`human-review.md`へ出力する。外部への送信や担当者への連絡は別の明示的な依頼があるときに行う。

[指定例](../assets/human-handoff.example.json)を実caseの観察で埋め、判定の`human_handoff`に設定する。理由区分は`environment_constraint`、`no_reliable_method`、`specialist_judgement`、`impractical_verification`から選び、具体的な事情を`reason`へ記す。

## 判定と引き継ぎの関係

- 確定できなければ`cant_tell`、すでに不適合を確認した部分があれば`failed`とし、未確認の対象を併記する。
- `coverage_complete`はfalse、`remaining`は残る具体的な確認にする。引き継ぎを通過・対象外・網羅完了にはしない。
- `attempts`と`checks`の証拠も実行先内へ保存する。case自身の収集又はcaseに結び付けた証拠が必要。
- 人から結果と証拠を受け取ったら照合して新しい判定を記録する。古い判定・証拠は保持する。未実行の人の判定を補わない。

```sh
python3 scripts/audit.py pending --run <実行先> --status human
python3 scripts/audit.py report --run <実行先> --strict
```

人の確認が残る報告では`--strict`は2となり、検証未完了を表示する。全票を「判定済み又は具体的な引き継ぎあり」にし、サイトの範囲と残る適合要件を記録できたら、AIが今回行える作業を終えて結果を渡す。同じ環境調査を繰り返して人の確認待ちを解消しようとしない。

## 媒体の例

「字幕を確認する」という依頼を、実際のプレーヤー、元音声・字幕の言語、対象0〜7秒等へ具体化する。全発話、必要な音、話者、情報の抜け、同期を全区間で比較する手順にする。元媒体と未確認の区間を示し、cueやASRの文字列を正解として渡さない。

手話は対象言語を理解する担当、閃光は一般閃光・赤色閃光・面積・時間の条件を分析できる担当と道具を指定する。物理端末が必要な制御は機種・OS・入力方法・再現する操作を明記する。

適用対象がない場合と、検証方法が不足した場合を区別する。人への引き継ぎを許可する方針でも、適用条件と全対象の調査は行う。
