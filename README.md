# WCAG検証スキル

サイトを調べ、ページ・状態・環境・達成基準ごとに実際の検査を行い、証拠付きの結果を出すAI向けスキルです。利用者がWCAGの番号や検査手順を指定する必要はありません。

開発中の1ページだけでも、サイト全体でも使えます。入口を分け、必要な段階だけを読み込む構成です。

| スキル | 利用する場面 |
| --- | --- |
| [wcag-page](skills/wcag-page/SKILL.md) | この1ページの画面・操作・達成基準を確認する |
| [wcag-pages](skills/wcag-pages/SKILL.md) | 対象URLを一覧から指定する、又は候補を抽出する |
| [wcag-report](skills/wcag-report/SKILL.md) | 保存済みの結果をHTML・JSON・Excelへまとめる |
| [wcag-audit-kit](SKILL.md) | 依頼を振り分け、サイト全体をページ別タスクで進める |

AIが実行できる検査を進め、環境制約、信頼できる方法の不足、専門判断が必要な部分は、証拠と具体的な確認手順を添えて人へ引き継ぐ初版です。[86基準の実証状況](references/VERIFICATION-COVERAGE.md)で、確認した範囲と未実証の対象を公開しています。

依頼例：

> このサイト全体をWCAG 2.2のAAで検証してください。何ができていて、何ができていないか、証拠と再現手順付きで報告してください。実装修正は行わないでください。

## スキルとして使う

開発者が1ページ検証だけを使う場合は、次で単体のスキルを生成できます。登録先は利用するAI環境に従い、新しい出力先を指定してください。

```sh
python3 scripts/install_skills.py --destination /project/ai-skills --skills wcag-page
```

全4スキルを生成するときは`--skills`を省略します。各ディレクトリーにSKILL.md、実行コード、共通資料が揃い、単独で配置できます。共通資料はこのリポジトリの原本から生成します。大きな検証記録は複製せず、リポジトリへの参照を残します。Gitチェックアウトではコミットを固定します。Git情報がないソースでは、`--source-ref <commit SHA>`で参照版を指定できます（省略時はmain）。依存物は各ディレクトリーのrequirements.txt等から導入します。

ソースのまま使う場合は、ルートのSKILL.mdとskills配下の各SKILL.mdを利用環境へ登録します。ソースのサブディレクトリーだけをコピーせず、単体配置には上の生成コマンドを使ってください。

スキルは、対象範囲の調査、操作・観察方法の準備、証拠の収集、各基準の検査、判定と人への引き継ぎの記録を担当します。修正担当へは不適合の対象・再現手順・期待結果を渡します。

## 1ページから始める

```sh
python3 scripts/audit.py page-audit --url https://example.com/contact --out /project/run-contact --profile standard
```

この入口は指定URLだけで開閉・選択・入れ子などの状態を探索し、実クリック・キー操作と各状態のaxeを実行します。探索・機械検査・ページ別HTML・JSON・Excelの出力にAIサービスやAPIキーは必要ありません。途中で止めたキューは再開できます。[1ページの実行手順](references/page-audit.md)を参照してください。

機械結果と、達成基準全体の適否は区別します。自動ルールで決まらない意味や目的、未探索の内容、必要な実SR等は追加検査に残します。`page-next`で次の票と機械結果・手順を取得し、利用できる道具から確認を進めます。`page-report`でそのページだけの結果を更新できます。既存の`page`は事前設定の状態を収集する入口として保持します。

画像と実SRは[観察設定](references/inspection-profiles.md)で選べます。quickは画像・実SRを省いた予備確認、standardは状態の画像を中心とする確認、thoroughは途中の画像と実SRも求める確認です。省略・上限・未探索は結果へ残し、トークン数や料金を保証する設定とは区別します。

サイト全体では1つのrunを正本とし、同じwcag-pageでページ別タスクを検査します。集計はその正本をwcag-reportへ渡します。

以前の`wcag-skills-draft`とZIPは変更していません。これは別のスキルです。旧下書きの設定とは書式が異なり、設定の自動移行はしません。

## プログラム・AI・人による検証の分担

WCAG 2.2の全86達成基準について、現行キットでプログラムが確認できる部分、AIが補助できる内容判断、人や専門環境が必要になる条件を1つの表にまとめています。A・AA・AAAをすべて掲載し、削除された4.1.1は含めません。基準名のリンクから、そのページで実行する具体的な検査手順へ進めます。

プログラムによる検査・計測を先に進め、残る内容判断に必要ならAIを使います。**AIの利用は必須ではありません。** 同じ証拠を人が確認しても構いません。表の各列は基準内の確認観点の分担であり、その列だけで基準全体の合否が決まる意味ではありません。

- **自動**：`page-audit`が探索した範囲で実行する操作・axeの検査・証拠取得。探索上限、画像の省略、未到達の状態は別に残ります。
- **追加**：対象と経路を具体化し、`probe`・専用アダプター・別の道具で実行する検査。`page-audit`だけでは実行しません。一部だけ実証した方法もあるため、[方法ごとの準備状況](references/method-capabilities.json)を確認し、対象環境で試します。
- **未整備**：現行キットに信頼できる実装・実証が揃っていない部分。プログラムやAI一般に不可能という意味ではありません。
- 人への引き継ぎの**共通条件**：利用できる情報・権限・道具・環境を調べ、代替方法も試してなお確定できない場合。表中の「共通」は、これ以外に基準固有の条件を挙げていない行です。全行で人の確認を必須にするものではありません。

DOM・画像・ログの取得やaxeの通過だけで、基準全体を適合にしません。実際のページの対象・状態ごとに、操作・観察・期待結果との比較を記録します。以下は実装・実証環境に基づく目安であり、当該ページの検証結果ではありません。実SRは実際のスクリーンリーダーを指し、AX（アクセシビリティツリー）の取得とは区別します。現行の実証はLinuxのOrcaを使った限定した操作で、`page-audit`単体では起動しません。

- 実際の読み上げ、拡大、ポインター、向き、媒体の観察用の補助。媒体では未確認の区間を残し、全区間の比較に抜けがある確定記録を拒否する。

AAを目標にするとAとAAの55基準を検査します。AAAなら86基準です。目標レベル外の基準も、未検証であることを報告に残します。削除された4.1.1は対象にしません。

[原典とライセンス](references/SOURCES.md)、[検査定義の索引](references/INDEX.md)、[試験記録](VALIDATION.md)を確認できます。

## 分担・中断・再開とExcel出力

検査票をページ又は基準ごとに小さいタスクへ分割し、担当・作業状態・メモを保存できます。次回は同じタスクの未完了票から続けます。Excelは閲覧用と作業用を用意し、担当・メモ・判定の編集を証拠付きで取り込めます。同じ票への更新が競合したら取り込み全体を止めます。

```sh
python3 scripts/audit.py tasks create --run /project/artifacts/wcag/run-001 --group-by page --size 20
python3 scripts/audit.py tasks list --run /project/artifacts/wcag/run-001
python3 scripts/audit.py excel export --run /project/artifacts/wcag/run-001 --mode report --out /project/wcag-report.xlsx
```

[共同作業の手順](references/collaboration.md)には、担当の取得、タスク別の作業用Excel、取り込みの事前確認、競合の解消、中断後の再開を記しています。対象・証拠等を省いて判定だけを合格にする操作は拒否します。タスク分割は収集済みの検査票が対象です。

HTMLとExcelには、人向けの[達成基準チェックシート](references/checksheet.md)を出力します。1.1.1などの基準ごとに行を用意し、確認観点が複数あれば内訳の行を追加します。適用・適合・未確認と、不適合のURL・状態・対象要素・再現手順・証拠を確認できます。Excelの先頭2シートは閲覧用です。作業結果を取り込む場合は、従来の検査票・対象・観察方法シートを使います。

今後の変更はPRと[ADR](docs/adr/README.md)で記録します。[変更の進め方](CONTRIBUTING.md)を参照してください。

開発時に実行した[検証の証拠とレポート](validation/README.md)も保存しています。未確認が残る報告例も含み、スキル全体の検証完了を示すものではありません。

[単独ページの通し検査](validation/full-fixture/README.md)では、AAの55基準を3状態で検査し、通過75・対象外90として、その固定した範囲の検査を完了しました。状態更新を欠く比較ページの4.1.2は不適合として報告しました。これは既知の小さい試験ページでの確認であり、未知のサイトに対する独立した精度評価は残っています。

[原典との照合による手順の改訂](validation/procedure-review/README.md)では、AAA全31基準と関連する定義等を確認し、媒体の代替を含む10手順を更新しました。過去の検査結果は、当時の定義と共に保持しています。

[フォーカス表示の校正](validation/focus-appearance/README.md)では、同じ画素の前後の比と面積を実測し、面積不足と、隣接色との比だけでは分からない前後の変化不足を区別しました。[測定補助の使い方](references/focus-appearance.md)には適用範囲と追加依存物を記しています。

[時間制限と再認証の校正](validation/timing/README.md)では、実時間で10回の延長と警告時間、制限の無効化、再認証後のデータ保持・保存完了を比較しました。[時間制限の手順](references/timing.md)で、期限や保存期間の記述だけから通過にしない方法を確認できます。

[複数ページの通し検証](validation/site-acceptance/README.md)では、5ページ・20状態・2表示幅の2,200票すべてに、判定又は具体的な人への引き継ぎを記録しました。通過1,342・対象外762・不適合16・人による確認待ち80、未実施0です。人の確認が残るため、このサイトのWCAG適合・検証完了は宣言していません。

[正解を伏せた公開例との比較](validation/act-held-out/README.md)では、ACTの2ルール・12例を実DOM/AXから判定し、公開期待値と12例すべてが一致しました。これはその2ルールの限定した比較で、全WCAG又は専門家によるサイト監査と同等の精度を示す数値ではありません。

## 実行環境

CLIにはPython 3.10以降、PyYAML、Playwright、Chromiumが必要です。既存環境があればそれを使います。

```sh
python3 -m pip install -r requirements.txt
python3 scripts/audit.py doctor
```

Chromiumがなければ、利用環境に従いPlaywrightのChromium等を準備します。実際のスクリーンリーダー、実ブラウザーの拡大、動画・音声・閃光の分析等は、[観察方法の一覧](references/methods.md)に従って必要な環境を調べます。

CLIはAIの判断に必要な証拠と検査票を用意します。CLIを1回実行しただけでは監査は完了しません。スキルを使うAIが各検査票の対象を確認し、実際に操作・観察して結果を記録します。

実スクリーンリーダー用には[GuidepupとネイティブOrcaのアダプター](references/screen-reader.md)を用意しています。Guidepupは`npm ci --ignore-scripts`でライブラリーを用意し、`npm run screen-reader:doctor`で対応条件を確認します。現在のLinuxでは、Orcaを直接起動する別の実バックエンドでも、通知・名前・チェック状態・見出し移動を確認しました。利用した手段と実際に確認した範囲を記録し、取得できない発話を仮想読み上げへ置き換えて確認済みにはしません。

[Guidepupを使う設計と実験の要点](GUIDEPUP-NOTES.md)では、達成基準と実ページからシナリオを具体化する流れと、見た目が同じで読み上げに伝わる状態が異なる例を説明しています。

[実ブラウザーの拡大](references/zoom.md)は、Linuxの専用X11環境で実行できます。200%・400%に加えて中間倍率も操作し、実測値、各段階の画面・DOM、操作結果を残します。用意した画像だけで全機能の検証を済ませず、各状態で操作して確認します。

## 出力するもの

| ファイル | 内容 |
| --- | --- |
| `report.html` | 達成基準・確認観点ごとのチェックシート、不適合箇所、ページ・状態・環境別の検査票 |
| Excel（出力先を指定） | 先頭に人向けチェックシート・不適合箇所、後ろに検査票・対象等の詳細シート |
| `report.json` | 全検査の結果、証拠、未実施・判断保留を含むデータ |
| `issues.md` | 修正担当向けの対象要素、再現手順、期待結果、観察結果 |
| `human-review.md` | 人に必要な知識・環境、試した方法、対象ごとの残る操作・判定条件・証拠 |
| `evidence/` | 画面、DOM、ツリー、操作ログ、測定結果等 |
| `assessments/` | 判定の履歴。新しい判定で過去の記録を削除しない |
| `catalog.snapshot.json` | 当時の検査定義。スキル更新後も、旧判定を当時の定義で再集計するために保持する |

検査の通過、不適合、対象外、判断保留、未実施を分けます。未確認の残るレポートには検証未完了を表示します。収集器の結果からサイト全体の適合を自動で宣言する機能はありません。

人への引き継ぎは[取り決め](references/human-review.md)に従い、未確認として残します。全票に判定又は具体的な引き継ぎを記録し、範囲と残る適合要件を報告できた時点で、AIが今回行える作業を終えて結果を渡します。

## 最初の試行

[実行コマンド](references/commands.md)の手順で、試験用サイトを監査できます。試験用サイトは意図的な不適合を含みます。実サイトで使う場合は、実際のページと状態の調査から始めてください。

スキルの記述と、現在の環境で実行できた検査の範囲は分けています。[試験記録](VALIDATION.md)に、確認済みの動作と、まだ評価していない範囲を記載しています。
